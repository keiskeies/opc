## 决策记录（`decisions/`）

下面这些数字的口径：只数 `decisions/` 下六篇正文里【实测】【变异】两个词的总出现次数，按篇重测过。0001 是 7 与 1，0003 是 9 与 19，0004 是 12 与 12，0005 是 21 与 17，0007 是 22 与 31；**0006 那一栏我不给精确数**：它两项都远高于其余五篇，但只要有人编辑 0006 —— 我记录任何事都得编辑它 —— 那两个数当场就变。我确实观测到它从 81 / 60 变成 90 / 64，那只是我写下上一句话那一刻的值，不是当前值，所以不拿它当数报给你。**【实测】六篇都有；【变异测试记录】并不齐平**：0001 那 1 处是引用式的一句（『常量由测试守住（变异 M5 一改值就红）』），没有独立记录节，密度与其余五篇差一个数量级 —— 所以我曾写『每条都带实测证据与变异测试记录』对 0001 是夸大。它是「为什么这样实现」的**集中**出处 —— 但【唯一】是我口径太宽，按规矩标【撤回】后收窄：规格 §25 的表（列名实测为『取舍 / 备选项 / 建议默认 / 出处』，共 9 行）与计划 §10.2 决策门表（列名『门 / 位置 / 决策内容 / 未决的后果』）也在记决策依据，计划 §1 另有一张『事实 / 对实现的约束』表。分工是：上游那两张表记【要不要这么选】，decisions/ 记【最后为什么这么实现、依据是哪次实测】。改实现前先读对应条目。

  **B** 远程只许「问我要票」，票由桌面推出去（安全性质不变，代价是多一条出站集成才能用）/
  **C** 给远程一个受限签票面（体验最好，代价是引入**第三个凭据层级**，而这条通道上今天只有两种）。
