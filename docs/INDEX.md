## 决策记录（`decisions/`）

下面这些数字的口径：只数 `decisions/` 下六篇正文里【实测】【变异】两个词的总出现次数，按篇重测过。0001 是 7 与 1，0003 是 9 与 19，0004 是 12 与 12，0005 是 21 与 17，0007 是 22 与 31；**0006 那一栏我不给精确数**：它两项都远高于其余五篇，但只要有人编辑 0006 —— 我记录任何事都得编辑它 —— 那两个数当场就变。我确实观测到它从 81 / 60 变成 90 / 64，那只是我写下上一句话那一刻的值，不是当前值，所以不拿它当数报给你。**【实测】六篇都有；【变异测试记录】并不齐平**：0001 那 1 处是引用式的一句（『常量由测试守住（变异 M5 一改值就红）』），没有独立记录节，密度与其余五篇差一个数量级 —— 所以我曾写『每条都带实测证据与变异测试记录』对 0001 是夸大。它是「为什么这样实现」的**集中**出处 —— 但【唯一】是我口径太宽，按规矩标【撤回】后收窄：规格 §25 的表（列名实测为『取舍 / 备选项 / 建议默认 / 出处』，共 9 行）与计划 §10.2 决策门表（列名『门 / 位置 / 决策内容 / 未决的后果』）也在记决策依据，计划 §1 另有一张『事实 / 对实现的约束』表。分工是：上游那两张表记【要不要这么选】，decisions/ 记【最后为什么这么实现、依据是哪次实测】。改实现前先读对应条目。
这五个数只是某一次测量的值，不是你任何时候都能复现的常数：计数口径是自指的 —— 只要有人编辑某篇，它那两项
当场就变。0006 我因此不给精确数（早前记的 81 / 60 到我写下那句时已变成 90 / 64）。这机制在第二
篇上复现了：我为实测补写了 0005 九十八行，它的【实测】就从 16 漂到 21，逼我紧接着改掉上面那个数。

## 等待 CEO 决策（改实现前先看这里）

下面每一条都是【我已经把材料备齐、只等一个答复】的东西。我能拿去 grep 的字样 —— `判据 3`、`A／B／M`、
`读法一`、`读法二` —— 在测试语料和计划里各测一遍，四个都是 0 命中（实测），所以只读代码或只读计划的人
看不到它们该选哪个。【撤回】我曾在这里写的是『它们不在任何测试里，也不在计划里』—— 那是我又一次
没实测就下的全称，两处都假：判据 2 那句话本身就是计划 Task 0.11 的出口标准原文；`--thread` 在测试里有
17 处命中。准确的边界是：测试锁住的是**实现行为**（`--thread` 被拒绝并指路），计划写的是**判据目标**
（要能从 Checkpoint 恢复）；两边都不含【这是我的偏离】【该按哪种读法】【选哪个字母】这些只有你能定的
东西。每一行指向决策文档里的具体小节，那里有实测证据、代价与我的倾向；
**但拍板不是实现层能做的事**（0006 §7 第 42 条记的就是：这些条目此前只存在于对话记录里，等于没送达）。
上面那句我原写【第 43 条】，【撤回】这个条目号：『只存在于对话记录』与『决策材料没送达』实测都在第 42 条的标题与正文里，

读到的是另一个缺口。守卫抓不到它 —— 它能防【指向不存在的条目】，防不了【指向存在但内容不同的条目】。

## 一条命令，你自己复核

上面每一条可复算的主张，现在都能由你自己当场复算，不必读我的转述：
`node docs/review/check-gate.mjs`（在仓库根目录跑）。它只读、不写、可反复跑；退出码非 0
就是有一项不符或判不了 —— 它拒绝在没判成的情况下报绿。为什么要有它：入口里的结论是我写的、
也是我量的；你若只能读我的话，等于用我的口径验收我的工作。
`docs/review/README.md` 写明每条检查替你确认什么，以及它不做什么（边界请当事实读）。

还有一条**关于这份入口自身**的披露，它不属于任何决策，但你判断「回不回退我对入口的改动」时用得上：
「轮次相对指称」这个缺陷类，我此前只在**这份入口**里清理过，**没有清完这一类** —— 其余决策文档里仍有存量，
规模由上面那条命令报出（分布一起打出来）。入口里的条目只说【不在任何测试里】这类**准确的**否定主张时，
范围也可能宽到误导你：准确 ≠ 完备。凡是只说【我已经改好 X】而没说【X 这一类还剩多少】的，按未完备读。
