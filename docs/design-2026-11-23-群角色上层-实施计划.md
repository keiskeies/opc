## 0. 总原则（从规格里继承，实施时不可让步）

1. **写路径唯一**：所有 SQLite 写走 `WriteQueue.node()`（`packages/hub/src/db/write-queue.ts`），读走 `queue.readConnection()`。Hub 单写者模型（规格 §6.2）不因新表而放宽。
2. **留痕＝广播**：凡写一行 `events`，必须同轮 `publishPersisted(evt, seq)`。写了不发＝制造 seq 空洞，活着的 SSE 订阅每次撞洞就整表重拉（0010 §4 量过的失效形状）。新面的推送一律走 SSE，不用轮询（上游 §2.7）。
3. **不开第 11 个 audit action**：`AUDIT_ACTIONS` 十值 append-only。新事件 kind 一律映射进既有十值（映射表见 §5）。
4. **契约先行**：新端点先进 `API_ENDPOINTS`，实现后再进 `IMPLEMENTED_ENDPOINTS`；未实现的自动 501，不写半截返回 200。
5. **落地四件套**（项目口径）：测试 + 自回滚变异探针 + `.workbuddy/AUDIT-LEDGER.txt` 台账条目 + 主张链（claims/coords）同步。

## 1. 实现层新决策（A1–A10）

| # | 决策 | 理由 |
|---|------|------|
| A1 | 新增 `packages/hub/src/http/router.ts`：表驱动路由（`method` + 分段模式 + `:param`），**只承载新面**，`app.ts` 的 21 条手写 `matchRoute` 原样保留，新表未命中时回退旧链。 | 上游要 80+ 新端点；`matchRoute` 是硬编码瀑布（且 `POST /approvals/batch` 先于 `/approvals/:id` 的顺序是承重的），再加 80 条必然写错。回退旧链让既有 21 条的路径语义与测试一行不动。 |
| A2 | 新事件 kind 携带**粗粒度 id**（`messageId/meetingId/docId/memberId/groupId`），细粒度增量走「按 id 拉详情」REST。 | SSE 帧载荷保持有界；消息正文已 normalize 进 `messages` 表，前端只需插指针（上游 §2.7 前端 normalize）。 |
| A3 | `events` 表不加列：新 kind 复用既有列（`actor_id`=member_id、`task_id` 可空、`payload`=JSON 载荷）。 | 触发器 `events_no_update/events_no_delete`、FTS、回放查询、role-memory SQL 都按现有列写；加列会波及一整圈守卫。 |
| A4 | `MODEL_TIERS` 保持 `["management","execution"]`。 | 老板是真人（D1），成员档位映射：`management`＝主持/决策/评审类角色，`execution`＝产出类角色。第三档无人消费（`ModelRegistry.get(tier)` 只有两档实现），立了就是死枚举。 |
| A5 | `web` 包拆双前端：既有七页看板整体移入 `/admin`（保留为底层治理视图，上游 §3「底层治理不显示」指主界面），三栏 IM 主界面挂 `/`。 | 不重写既有看板；治理层「不显示」但「可进入」，验收时两界面都在。 |（2026-11-25 修订）独立 `/admin` 页已彻底删除，七页治理视图只经工作台 `#/admin/<页名>` 一个入口，旧 `/admin` URL 落到 404 不再重定向。 |
| A6 | 文档正文以 `markdown` 为唯一权威格式，前端按 doc kind 提供编辑器（doc/sheet/markdown/mindmap 四种序列化都落 markdown/JSON 文本列）。 | 一套版本/权限/水印/搜索机制覆盖四种 kind，避免四种格式各写一份 diff。 |
| A7 | 文件型资产（头像、附件、导入原件）落库为 BLOB（`assets` 表），不走文件系统。 | 规格 §6.1「单个可备份的 SQLite 文件」是硬前提；落盘会把备份模型撕成两半。 |
| A8 | `model_tier` 留在 `role_runs` 上（不动）：执行器决策放 `member_executors` 表，`model_tier` 继续描述「这一轮用的模型档位」。 | 避免触碰 role-runs 的 21 处既有断言；执行器语义本来就在成员维度，不在 run 维度。 |
| A9 | 会议是**异步回合制**，不追求同毫秒并发发言。 | 执行器是 CLI 子进程（秒级起步），「真实会议」＝发言序列 + 主持指定 + 结论三件套（上游 §2.4），时序正确即达标；写成线程池只会被超时拖死。 |
| A10 | 前端零框架：沿用 `packages/web/public/` 的浏览器 ESM 手写模块 + 既有 normalize/projection 模式。 | 项目铁律「零框架运行时」；引入框架 = production-deps 守卫直接红，且重写成本大于收益。 |

## 2. DB 迁移（0011–0020）

命名沿用 `migrate.ts` 的 `^\d{4}_[a-z0-9_]+\.sql$`；**每文件一事务、无 `IF NOT EXISTS`、禁 `PRAGMA journal_mode`**；触发器体在事务内合法（0001 已验证 5 个触发器）。

### 0011_roles.sql —— 可配置角色表（D9/D11）
```
roles(role_id TEXT PK, name TEXT, kind TEXT CHECK IN ('builtin','custom'),
      category TEXT, reports_to TEXT NULL REFERENCES roles(role_id),
      model_tier TEXT CHECK IN ('management','execution'),
      charter_json TEXT, avatar_seed TEXT, created_at INTEGER, updated_at INTEGER)
```
- 触发器禁删/禁改 `kind='builtin'`（内置角色不可删，D9）；`custom` 删除前由应用层查「已卸任」。
- 同文件 seed 全公司树（D9 激活职能）：`boss`(老板，人类锚点)、`cos`(特助)、`product_director`、`tech_director`、`dev`、`qa`、`designer`、`ops`、`finance`、`hr`、`legal`、`marketing`、`sales`。`reports_to` 还原上游那棵公司树；`designer` 挂 `product_director` 下且 builtin。
- seed 用 INSERT（无幂等需求：迁移本身由版本表保证只跑一次）。

### 0012_groups.sql —— 群＝任务（D2/D6）
```
groups(group_id TEXT PK, title, goal, task_id TEXT NULL REFERENCES tasks(id),
       cos_member_id TEXT NULL, status, created_at, updated_at)
group_members(group_id, member_id, role_id, seat TEXT, joined_at,
              PK(group_id, member_id))
```
- `task_id` 可空：建群→立项分离，立项前群先存在（上游 §2.2 流程）。

### 0013_members.sql —— 成员 = persona+skill+executor+tier（D3/D4/D13）
```
members(member_id TEXT PK, name, role_id, persona_json, model_tier, avatar_asset_id,
        voice_json, tone TEXT, status, hired_at, updated_at)
member_skills(member_id, skill_id, name, note, PK(member_id, skill_id))
member_executors(member_id, seq, kind CHECK IN
  ('claude-cli','codex-cli','qoder-cli','platform-webhook','builtin-plugin','pure-model','human'),
  config_json, enabled, PK(member_id, seq))
hire_events(id INTEGER PK AUTOINCREMENT, member_id, action, from_json, to_json, at)
```
- 执行器多挂 + `seq` 定优先级（D4）；`human` 执行器即真人席位（D7）。

### 0014_conversations.sql —— 会话与消息（D2/D5）
```
conversations(conversation_id TEXT PK, kind CHECK IN ('group','private'),
              group_id NULL, member_a NULL, member_b NULL, title, created_at,
              CHECK((kind='group' AND group_id IS NOT NULL)
                OR (kind='private' AND member_a IS NOT NULL AND member_b IS NOT NULL)))
messages(message_id TEXT PK, conversation_id, sender_member_id NULL, author_kind
         CHECK IN ('member','boss','system'), body, mentions_json, reply_to NULL,
         kind, seq_in_conv INTEGER, created_at)
message_reads(conversation_id, reader TEXT, last_seq_in_conv, read_at, PK(conversation_id, reader))
```
- 私有会话唯一性用部分唯一索引 `member_a||'|'||member_b`（创建时排序归一）保证跨群可读、不重复开线（D5）。

### 0015_meetings.sql —— 真实会议（D8）
```
meetings(meeting_id TEXT PK, group_id, task_id NULL, topic, moderator_member_id,
          speaking_order_json, status CHECK IN ('open','concluded','cancelled'),
          decision TEXT NULL, owner_member_id NULL, deadline_at INTEGER NULL,
          summary_doc_id TEXT NULL, opened_at, concluded_at NULL,
          next_speaker_member_id NULL)
meeting_turns(turn_id INTEGER PK AUTOINCREMENT, meeting_id, speaker_member_id,
              content, turn_seq, created_at)
```
- `decision/owner/deadline` 三列非空约束由「conclude 端点」强制（结论三件套，上游 §2.4）。
- 落地坐标：`0017_meetings_real.sql` 扩真实会议列，`0022_meetings_topic.sql` 补主题，
  `0024_meetings_driver.sql` 补 `opened_at` 与 `next_speaker_member_id`。迁移 append-only，
  不回头改已登记版本；`next_speaker_member_id` 是「当前轮到谁」的持久判据，每轮发言同事务推进。

### 0016_backlog.sql —— 任务面板（D10）
```
backlog_items(id TEXT PK, group_id NULL, task_id NULL, title, detail,
              state CHECK IN ('backlog','scheduled','doing','done','cancelled'),
              priority INTEGER, due_at NULL, parent_id NULL, merged_into NULL,
              created_at, updated_at)
```
- 面板操作（取消/移动/延期/优先级/拆分/合并）全为对本表的 UPDATE/INSERT + 事件留痕；拆分写 `parent_id`，合并写 `merged_into`（保留原件，可追溯）。
- 操作权落地判据：老板恒可写；成员须 active、在对应群有席，且岗位 category=product 或席位=cos。
  跨群移动/合并同时检查来源群与目标群；全局面板（group_id NULL）只许老板写。读侧可见性由 T10 按群席位过滤。

### 0017_documents.sql —— 文档中心（D12）
```
documents(doc_id TEXT PK, kind CHECK IN ('doc','sheet','markdown','mindmap'),
          title, group_id NULL, task_id NULL, owner_member_id NULL,
          body_text, mime, watermark_profile TEXT NULL, origin CHECK IN
          ('created','imported','auto'), template_id NULL,
          created_at, updated_at, deleted_at NULL)
document_versions(version_id INTEGER PK AUTOINCREMENT, doc_id, seq, body_text,
                  author TEXT, created_at)
document_permissions(doc_id, grantee TEXT, tier CHECK IN
                  ('owner','editor','reader'), PK(doc_id, grantee))
document_templates(template_id TEXT PK, name, kind, body_text, builtin INTEGER)
```
- 版本保留 30 天：`documents` 每次写前落 `document_versions`；清理由 rhythm 维护任务删除 `created_at < now-30d` 的版本行（文档本体永不删）。
- `0026_documents_soft_delete.sql` 补 `deleted_at`：DELETE 端点兑现为软删，正文、版本、权限与审计保留，列表/详情不再出现；不做硬删。
- 导入原件的上传端点补登记为 `POST /api/v1/assets`（JSON base64）：契约注释要求先上传字节，但 §3 原清单只有 GET；不补这条，DOCX/XLSX/PDF 导入在真实 HTTP 与桌面 IPC 上都缺入口。
- 模板 seed：周报/复盘/PRD/会议纪要四张 builtin。

### 0018_plugins.sql —— 插件与 MCP（D14）
```
plugins(plugin_id TEXT PK, name, kind CHECK IN ('mcp','builtin'), endpoint,
        config_json, enabled, installed_at, last_probe_json)
plugin_tools(plugin_id, tool_name, description, input_schema_json,
             PK(plugin_id, tool_name))
```

### 0019_assets_talent.sql
```
assets(asset_id TEXT PK, purpose CHECK IN ('avatar','attachment','import-source'),
       mime, size_bytes, sha256, data BLOB, created_at)
talent_market(item_id TEXT PK, source CHECK IN ('builtin','imported','published'),
       name, payload_json, published_at)
```
- 人才市场三入口（上游 §2.3）：内置模板（seed）、导出（生成 payload_json）、导入上架（写入本表并派生 members）。

### 0020_rhythm.sql —— 节奏事件与每日调研（D15）
```
rhythm_events(event_id TEXT PK, kind CHECK IN ('sprint_planning','standup','review','retro'),
              group_id NULL, at, digest_doc_id NULL, payload_json)
research_cards(card_id TEXT PK, day TEXT, source, title, summary, url, created_at)
```

## 5. 事件模型（新 kind → 既有十 action）

| 新 DomainEvent kind | action | 说明 |
|---|---|---|
| `GroupUpdated` | `state_change` | 建群/解散/换特助 |
| `MemberHired` / `MemberUpdated` | `state_change` | 招聘/改配置（细节在 payload） |
| `MessageReceived` | `meeting` | 会话消息（含 @老板；升级链由 payload.kind 区分，role-memory 侧按 kind 过滤） |
| `MeetingOpened` / `MeetingTurnPosted` / `MeetingConcluded` / `MeetingCancelled` | `meeting` | 开场/回合/结论/取消；取消原因进 payload，不能静默消失 |
| `BacklogChanged` | `state_change` | 面板六操作共用，payload 带 op |
| `DocumentChanged` | `state_change` | 保存/还原/权限变更，payload 带 op |
| `ExecutorRunFinished` | `harness_call` | 七执行器统一回执 |
| `RhythmEventRecorded` / `ResearchCardCreated` | `state_change` | 团队节奏实例 / 每日调研卡；payload.kind 区分 |
| `DispatchAssigned` | `state_change` | CoS 规则/LLM 派发落地为执行任务；target=task id |

约束（同 A3）：payload 只带粗粒度 id；每个 kind 的每行 `events` 必配 `publishPersisted`；role-memory 的 `MEMORY_ROWS_SQL` 过滤（action IN approval/review_decision）天然不受影响。
