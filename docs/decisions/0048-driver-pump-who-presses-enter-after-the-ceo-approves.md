# 0048 CEO 批完一张卡之后，谁去敲那一次回车 —— 以及我在写下「巡检永远不会报这一格」之前没跑一遍

> 本篇的实现是 `packages/hub/src/serve/driver-pump.ts` + `assemble.ts` 里那一段派发
> + `config.ts` 的 `--driver-pump`。测试是
> `packages/hub/test/serve/driver-pump.test.ts`（41 发）、
> `packages/hub/test/serve/assemble-driver.test.ts`（19 发，其中一发是变异实验逼出来的，见 §9 的 M8）
> 与 `config.test.ts` 里新增的那一组（8 发）。

## 0. 一句话

0044 补上「章程卡从哪来」，0046 补上「走到人席时她看得见、点得动」，0047 补上「顶层是谁不该问名字」。
合起来仍然有一格是空的，而且是最中间那一格（**下面那段是本篇动手前的状态**，现在那一格由
`--driver-pump` 接着）：

```
CEO 批掉一张卡 ⇒ 任务进到 CHARTER_APPROVED ⇒ 那一格是【agent 席位】
⇒ 本篇动手前，全仓没有任何东西会让它跑下一轮
```

`advance()`（`engine/driver.ts`）早就会推这个循环，而它当时**只有一个生产调用方**：
`hub work`，而那条命令要 tsx 而本机装不上（0039）。也就是说「一人公司」在真机上仍然需要
**有人每过一格去终端敲一次回车** —— 而这正是用户纠正过我的那个东西：

> 「我要做的是一人公司，我将一个想法下发，然后各个 agent 吭哧吭哧干活，我是公司的 ceo」

本篇接的就是那一次敲回车：`--driver-pump` 打开后，心跳每轮问一次「有没有停在 agent 那一格而没人推的任务」，
有就推一格，走到人席（等章程 / 等裁决 / 等终审）自然停下。

## 1. 判据只有四条，每条都对应一种「不这样会怎样」

| 判据 | 住在哪儿 | 不这样的后果 |
| --- | --- | --- |
| 候选状态 = `seatOf(s) === "agent"`，**派生**自边表 | `DRIVER_ELIGIBLE_STATES` | 抄一份状态名单 ⇒ 将来给某格加一条 agent 出边，dispatch 会跑它而驱动器**不会想到它**；症状是「那条边只在有人手跑 work 时才动」，与「这条边坏了」在屏幕上一样 |
| 尝试次数按【这一格 + 这个人】计，且只数**这一次来到这一格之后**的 | `driverAttemptsSql` | 照抄章程泵那个数法（数 `RoleTurnReported`）⇒ 手跑几次 `hub work` 就把自动那条路**永久关掉**；不按格计 ⇒ 打回换了人，上限还延续，而换了人正是「这次可能不一样」的那个理由 |
| **先写认领行、再花钱** | `driveTasks` 循环体 | 「跑完再记」**恰好漏掉全部崩溃**，于是上限看起来在而永远数不到需要它的那些次 |
| 一条抛了**不整轮抛** | `driveTasks` 的 catch + `assemble` 第二层 | 抛到 ticker 那层 = 心跳失败计数，连番之后停掉的是**整条心跳**（含停滞巡检与每日备份）。一条任务推不动不该让停滞检测从此不再运行 |

`MEETING_REQUIRED` / `BLOCKED` 两格**结构性地进不了候选**：两张边表都没有出边，
所以它们连「可驱动」这个谓词都不满足 —— 不是被排除，是**没有可走的路**（这两格的死端另记在别处）。

## 2. ⭐ 我写下「上限到顶之后，巡检永远不会报这一格」，而那是没跑一遍就下的结论

第一版文件头里写着：驱动器自己写的认领行会把停滞计时器每心跳拨一次零，
**所以**「试到上限之后巡检也永远不会报这一格，`io.warn` 必须响，否则没人知道」。

前半是真的，后半是我**读了一遍 `PATROL_SQL` 就下的结论**。跑一遍（`maxAttempts=3`，
阈值 `DEFAULT_STALL_THRESHOLD_MS` = 30 分钟）：

```
三趟驱动跑完 ⇒ 认领行 3 行 + 放弃行 1 行，last_real_event_at 被推到最后一趟那一刻
同刻巡检            ⇒ verdict=recent，silentForMs=0        ← 上面那个窗口，真的
放弃之后再巡        ⇒ verdict=recent（那一行之后没有新行，计时器开始变老）
推到「最后一行 + 阈值 + 1 分钟」再巡 ⇒ stalled=1，silentForMs = 31 分钟   ← 【会报】
```

所以正确的说法是**两个时段**而不是一个断言：

- **还在试的那几轮**：巡检被认领行弄哑。这是真的盲区，也正是**上限必须存在**的理由
  （那几轮在花钱而没推进，且没有任何外部告警）。
- **放弃之后**：驱动器不再认领 ⇒ 没有新行 ⇒ 巡检会在约一个阈值之后**自己报出来**。是一层**延后的兜底**。

`io.warn` 那条结论**不变**，但理由要换准 —— 不是「否则永远没人报」，而是三条更窄的：
① 那句是**当场**的信号，巡检那句要再等约 30 分钟；② 巡检那一层**只在 Hub 继续开着且心跳继续跑**时才存在
（放弃之后就退进程 ⇒ 那层兜底不存在）；③ 巡检那句是「停滞 N 个任务」一句**计数**，
说不出「这是驱动器试到上限那一格、而它的认领行自己把计时器拨着」这段**成因**，
而这段成因正是知道该去改什么所需要的。

**这一条值得记的不是结论错了，是它的形状**：前半句和后半句用同一个「所以」连着，
读起来像一整段推理，而其中只有前半句我验过。措辞错了还会让人以为巡检坏了。

测试这一侧就照着两个时段写（`driver-pump.test.ts` H 组）：先断 `stalled` 做分母，
再断认领后 `recent`，再断放弃后 `recent` → 阈值 + 1 分钟后 `stalled` 且 `silentForMs === 阈值 + 60_000`。
⚠ 这一组**必须用只读的 `patrolTasks`**：`runPatrol` 会写一行 `HeartbeatStalled`，
而巡检的去重判据（`lastStallAtMs >= silentFrom`）会让第二次判定返回 `already_flagged` ——
我第一版在同一份库上连跑两次巡检，拿到的是 `already_flagged`，
差一点把「巡检会报」这条**被我自己的测试写法弄没了**。

## 3. 注入点选在【一整步】而不是最里层，代价当场记

章程泵（0044）注入的是最里面那一格（「起草时别 spawn」），因为其余装配必须保持真的。
驱动器反过来：注入的是 `driveTask` **整一步**，因为**循环本身才是本篇的逻辑本体**，
注到最里面那一格反而**测不到循环**（候选、上限、认领、放弃、逐条不牵连，全在循环里）。

代价就是 0044 §9.2 记过的那个形状：**注入之后默认那一支【零覆盖】** ——
也就是「`bin` / `cwd` / `recordTurn` 到底有没有接到真 runtime 上」这件事
**不能靠那组注入用例宣称接上了**。所以 F/J 组那一发是**真起子进程**的（走 `fake-claude.mjs` 夹具），
断的是审计里的 `harness_calls` 行与 `--agent-cwd` 的**往返**。

## 4. 三件量出来才发现不是我想的那样

### 4.1 `harness_calls.agent_role` 是【这一轮结束后任务归属于谁】，不是【谁被叫去干活】

`dispatch` 成功那一支返回的是 `role: plan.role`，而 `plan.role` 是**落点角色**（`nextRole`），
`driver.ts` 的 `oneTurn` 把它原样交给 `rt.recordTurn({ role: res.role, … })`。

**实测那一发**（J 组，图 `ceo ← manager ← {dev, tech}`）：第一轮真被叫起来的是 `manager`，
它交棒之后任务落到 `tech`，而**两行 `harness_calls` 的 `agent_role` 全都是 `tech`** ——
manager 那一轮的账记在 tech 名下。我第一版断的是「第一行 manager、第二行 tech」，红的。

⚠ 但**不能笼统写成「记的都是落点」**：`planEdge` 里那两支**升到 CEO** 的分支写的是
`role: o.role`（**产出方自己**），因为落点是 `ESCALATED_TO_CEO`（人席），
把任务归属改成 ceo 会让 `approveCard` 的原值回填把一次「升给 CEO 看」变成一次**组织分配**
（0047 §1 那条）。所以准确的口径是：**那一列等于「这一轮跑完之后 `tasks.assigned_role` 的值」**——
换人时是接手人，**不换人时就是产出方**。

这是**量出来的，不是我选的**。我**没有**改实现：那是 `harness_calls` 现成的口径，
改它要连带改这一列的既有语义与其它引用面，不该混进本篇。
但它**不能只留在注释里** —— 所以那发断言旁边留了一段，让「这一列是谁跑的」这个直觉错误
**在这里被读到**，而不是在一个查账的人身上发生。

### 4.2 `exit_code` 判的是【这一轮有没有真的跑起来】，与【跑得好不好】无关

`ok: res.seat === "agent"` 而 `exit_code = ok ? 0 : 1`。而 `dispatch` **成功那一支的 `seat`
是写死的 `"agent"`**（`dispatch.ts:1293`），`seatOf(...)` 只出现在 `stop()` 那一支
（人席、组织图坏掉、顶层判不出…那些**没跑起来**的形状）。所以：

| 那一轮实际发生了什么 | `exit_code` |
| --- | --- |
| CLI 正常跑完、走了边 | 0 |
| **CLI 输出一句人话而没带 `<<<OPC_DECISION>>>`**（没推进、没花钱） | **0** |
| CLI 跑完而状态没动（wait / 越权被拦） | 0 |
| 任务停在人席 ⇒ 连 token 都没烧 | 1 |
| 组织图成环 ⇒ 连 token 都没烧 | 1 |

也就是说那一列分的是**「有没有放 agent 进场」**，不是**「这一轮成不成」**。
我第一版断的是「输出不是 JSON ⇒ `exit_code === 1`」，红的。现在那发断量到的形状：
`exit_code === 0`、`cost_cents === 0`、`state_change` 行数 0、
note 里带着「CLI 输出不是预期的 JSON」—— **没推进、没花钱、而记的是成功**。
（与 4.1 同一族：**审计里那两列说的都不是它们名字暗示的事**。）

### 4.3 反向断言 `toContain` 的**前缀**陷阱

`--agent-cwd` 那发我先写的是「子进程 echo 出来的 cwd **不包含**父进程 cwd」作为反向对照。
它**永远不可能红**：夹具目录就在仓库里面（`packages/hub/.tmp/…`），
子进程的 cwd **恒以**父进程 cwd 为前缀，`not.toContain` 恒真 ——
而且更糟：这个写法在它**本该抓到**的那个失效里也是**通过**的。
改成正则把 echo 的两个值抠出来，再与 `realpathSync` 逐字比相等 / 不等。

## 5. 写下来的话与真的行为：三处要当心的地方

### 5.1 两处「把人支去查一样不存在的东西」

1. **`config.ts` 的用法文本**第一版写「按格尝试的次数看 serve 启动横幅」。
   而那条横幅**故意不含那个数**（见 §6 第 1 条），所以那是一句把人支去查一个不存在的数字的话。
   现在指向 `DriverTurnClaimed` / `DriverTurnAbandoned` 的 payload（`attempt` / `max_attempts`），
   并且 `config.test.ts` 钉两件事：文案里那句**自我承诺**（「不抄那个次数」）必须真的没抄 ——
   `not.toMatch(/试\s*[0-9]+\s*次/)`；以及它指的那两个 token **必须出现在文案里**。
2. **等待时长**：0044 那一版抄的是「最坏 180 秒」，那是章程泵（一次 SIGKILL 上限）的数字。
   驱动器是 `taskLimit × maxTurns × 180s` = `3 × 12 × 180_000` = **6,480,000 ms = 1 小时 48 分**。
   我在**两处注释里抄成了「3 小时 12 分」**（`grep` 得到：那两处注释现在写着真值，
   而错的那一版在 `git diff` 里），而那个错数的来源是**我抄了上一段的话而没算**
   —— `worstDriveWaitMs` 那发断言红了才改掉。一个**偏小**的等待承诺会让人在第四分钟判定进程卡死并
   `kill -9`，而那正是那句话存在的唯一理由（等只是慢，`kill -9` 会留下没关的连接与没提交的事务）。
   所以它做成**从两个配置算出来**的函数，关机横幅那句也不重算一份，只说「上面驱动器横幅里写着」。

顺带一条同族的措辞：Ctrl-C 那句「最坏 180 秒」我第一版在测试里断的是 `not.toContain("最坏 180 秒")`，
而真串是「最坏**等** 180 秒」—— 差一个字，**恰好躲过**。换成断那句新的自我承诺
（「这里不重算一份」）之后才真的有牙。

### 5.2 两处「看起来像判据，而今天不承重」

- **`boundsLine(bounds)`**：三个花钱的数字（美元硬顶 / 任务上限 / `--agent-cwd`）现在由**一个函数**
  拼给**两条**横幅。加驱动器之前只有一条横幅、那三个数是就地拼的；就地再拼一份就是
  「两行屏幕写着不同上限而底下生效的是 `bounds` 里那一份」，而**它漂的时候没有任何东西会红**。
  这一条是本文件反复拒绝的「注释里抄一份数字」的**同一件事换了个位置**——抄在**人读的那一屏**上。
- **`driverBudgetWarned`** 这个 `Set`：它与 `pumpBudgetWarned` **没有共用**，看起来像"少做了一次合并"。
  它是**今天不承重的保险**（这个词与 charter-pump.ts 里「候选为空那道早退是等价变异」同一类），
  而这一句**是量出来的**：把两个 Set 合成一个（删掉声明、驱动那一侧直接传 `pumpBudgetWarned`）
  ⇒ `driver-pump` + `assemble-driver` + `config` + `assemble-pump` 四个文件合跑 **125 / 125 / 0 全绿**。
  原因是今天一条任务不可能同时被两个泵各自判一次"钱到顶"，所以两个 Set 与一个 Set **行为完全相同**。
  它存在的理由是 0044 §9.1 等的那件事（「退回的章程该去哪条边」）一旦被补上，
  同一 `taskId` 就会在两侧各自该说一句，而共用的那个 Set 会**咽掉第二句**。
  合并省下一个声明，代价是少一句真话 —— 不对称。
  **登记它为"不承重"而不是假装它是判据**，否则下一个读代码的人会以为它在挡什么。
  ⚠ 注意它**不等于** M14：M14 删的是「同一条只说一次」那对 `has`/`add`（红 2 条），
  那一发**承重**；这里合并的是**两个 Set 的身份**，那一发**不承重**。同一格代码上的两件事。

## 6. 本篇没做的（不写成「换种方式做到了」）

1. **三个上限没有 CLI 入口**，而且三格的**可达性还不一样**（这是查了装配层才写准的，不是猜的）：
   `taskLimit` 与 `maxAttempts` 有 `BootOverrides` 的注入口（`driverTaskLimit` / `driverMaxAttempts`，
   **只有测试在用**），而 `maxTurns` **连注入口都没有** —— 装配那一句是
   `maxTurns: driverSettings.maxTurns ?? DEFAULT_DRIVER_MAX_TURNS`，而没人往 `driverSettings`
   里填过 `maxTurns`。所以启动横幅那句「每条至多 12 格」**在任何配置下都是缺省值**。
   我**没有**加那三个 CLI 参数：三个新旋钮 = 三种把昂贵循环配得更贵的方式，
   而 `--task-limit-cents` 那条「花钱的闸门」已经吃掉了实际风险。
   这不是「做到了」，是**我判断不该做**，写在这里而不是抹平。
2. **「追加预算」仍然没有入口**（0041 §7 / 0045 §7）：花钱的门挡住一条任务时，
   这一轮只能**说出来**而不能放开它。`reportDriveRound` 里那句「要接着走：追加预算」
   指的是**人工改库/将来那个端点**，今天不是一个按钮。
3. **打回之后不自动重跑上游角色**。驱动器只是下一轮把新那一格推一次；
   「谁该被叫起来改」是 dispatch 的 handoff 语义决定的，本篇不加边。
4. **并行分支各推各的**，不引入任何跨任务的顺序或依赖。
5. **`advance()` 手跑那条路照旧**（`hub work` 要 tsx，本机装不上），
   本篇加的是**常驻进程内**的那条，不是那条命令行。
6. **关机那句只被【纯函数】覆盖了**。`shutdownOrderLine` 是从 `runServeCli` 里
   抽出来的（先例：`serveBannerOf`），因为那句 `io.log` 在真入口里、
   而 `runServeCli` 打印完就阻塞在 SIGINT 监听上（监听起来从不注销，测试里会挂）。
   两个分支现在各自有断言（**抽之前两个分支都是【零】进程内覆盖**，
   第一版测试就是这么红的：`实到 ""`）。**但这不等于覆盖了「真入口会打印它」** ——
   那一句覆盖仍然是零。

## 7. 等 CEO 拍的一项：驱动器「不再推了」这件事，你要在哪里看见

今天它只在**终端**响一声（`io.warn`，`⭐ 驱动器【不再推】…`）。
而 0046 整篇的立场是「你在**桌面端**看公司」—— 终端不在你每天开的那个窗口里。
于是有一格形状是：任务停在 `IN_PROGRESS/dev`，界面显示「开发中」，
而**已经没有人推它了**（试到上限），这个状态**在界面上与"正在被推"无法区分**。

三个候选与代价：

- **(A) 什么都不加**（今天的形状）。代价就是上面那句：状态栏说的是**席位**，不是**有没有人在推**。
- **(B) 给它一张收件箱卡**。这一步的**前置正是 0046 §7 那条**（「收件箱该不该显示不欠决定的东西」归你拍）：
  驱动器放弃**不是一个待决决定**（没有按钮可点 —— `APPROVAL_BUTTONS` 明写没有第四个按钮的位置，
  而 0044 §9.1 记着「否决没地方去」），所以 (B) 会往收件箱里放一张**不欠决定**的卡，
  正好撞在你那条待决上。我不替你定。
- **(C) 运营看板加一列「最近一次被推 / 是否已到上限」**。纯读侧，`DriverTurnClaimed` /
  `DriverTurnAbandoned` 的行就在库里，读现成的。代价是那列只在**出事时**才有意义，
  而看板今天那一版（0042）没有"沉默"这一维。

**我的倾向是 (C)**：它不改「收件箱欠不欠决定」这条契约，也不新造按钮，
而它把「有没有人在推」这件事放到你**真的会看**的那个界面上。(B) 我刻意不选，
因为它的钱要付在**你已经挂起的那条待决**上。(A) 最坏 —— 它把「没人管了」伪装成「进行中」，
而这是本篇在别处反复消灭的那一族（配置写了而没生效、状态说了而没人做）。

### M7 全绿：我为一处【恒假的分支】写了一句"有变异会抓它"

`driveTasks` 循环开头有一发 `if (seatOf(c.status) !== "agent")` 的复核。
把它整块删掉 ⇒ **107 发全绿**。原因不是测试写得松：

- 候选 SQL 筛的是 `t.status IN (DRIVER_ELIGIBLE_STATES)`，
  而 `DRIVER_ELIGIBLE_STATES` 就是 `Object.keys(AGENT_EDGES).filter(seatOf === "agent")` ——
  **同一个谓词**。所以从那条 SQL 出来的每一行**必然**通过复核，那一支在当前 API 下**恒假**。

而我写在那一段旁边的注释是：「那种改动下复核会响（`driver-pump.test.ts` E 组那发变异）」——
**那句是假的**，而且是我**在跑变异之前**写下的。

两件事分开记：

1. **代码里一句"这里有测试挡着"是一个断言，而断言要跑。** 它比没写更坏：
   下一个删那发复核的人会去看注释，注释说安全。
2. **那一格的身份现在是【今天不承重的保险】**，与 `assemble.ts` 里 `driverBudgetWarned`
   同一类（§5.2）。留着（便宜，且它挡的那天真的会让"这格根本不该放 agent 进场"变成一次真花钱的
   子进程），但注释里写明**它不承重、删了不会红**，并注明"真要让它承重得先把那一支做成可达，
   而那意味着把候选 SQL 做成可注入的 —— 那会把『派生』这个卖点换成一个注入点，本篇不做"。

**我没有为它补一条"直接构造一个坏候选"的用例**：`driveTasks` 的候选来自它自己那条 SQL，
要打穿那一支得注入 SQL 或状态集合。为一个恒假分支造一条**必须靠注入才能到**的用例，
测的是我的注入手法而不是判据 —— 那种绿的证明力低于它的维护成本。
**登记为"这一支不承重"就是把这件事说完**，而不是用一条假绿把它伪装成承重。
