# 0055 门禁里那一发「既有良性」：一个从不 exit 0 的 `pnpm test`，和三处「标题写着而断言没写」

> 0053 §7 我写过一句「`packages/hub/test/engine/claude.test.ts` 报 No test suite found 属**既有良性**」。
> 本篇的第一件事是：**那句是错的**，而且错的方向正好是本仓最恨的那一侧 ——
> 它不良性，它让 `pnpm test` 恒 exit 1，从而让 `pnpm verify`（= `lint && typecheck && test`）
> **恒不可能通过**。一个恒不可能通过的验收命令，和一条恒红的断言，是同一个东西。

---

## 1. 一句话

那个文件是 `node:test` 写的，而 vitest 的 `include` 收得到它 ⇒ vitest **导入**它、
node:test 在导入期注册并跑完、vitest 报告「0 test / No test suite found」⇒ 整个套件 exit 1。
搬进 vitest 之后：`pnpm test` **第一次 exit 0**，门禁里多出 14 发真测试。

| | 修前 | 修后 |
| --- | --- | --- |
| `npx vitest run` 退出码 | **1** | **0** |
| 全套 | 2348 / 2342 pass / 6 skip + 1 文件红 | **2362 / 2356 pass / 6 skip，108 文件全绿** |
| 那 13 发在门禁下的状态 | 0 发在跑 | **14 发在跑** |
| biome 全仓 | 294 error | **291 error**（少 3，全是这两个文件自己的既有问题） |

## 2. 「良性」那句是怎么来的，以及它为什么错

我那句「既有良性」是**照抄 round187**（那份记着「`node --test` 下 13/13 绿」）。三条实测把它打回：

1. 【实测】`npx vitest run` 退出码 = **1**。⇒ `pnpm verify` 的最后一段恒红。
   这不是风格问题：一条恒红的验收命令会让人**学会跳过它**，0007 §4.1 记的正是这个代价。
2. 【实测】那 13 发在门禁下**一发都没跑**：把 `parseDecision` 的 `lastIndexOf` 改成 `indexOf`
   （正是「取最后一个决策段」那发明令禁止的改法），门禁输出与基线**逐字节同**、退出码同、
   测试数同（`no tests`）。⇒ 它对目标缺陷的分辨能力是零（0013 §8 那七个字第二次落在同一个仓里）。
3. 【实测】文件头写的兜底跑法依赖 `/tmp/opc-harness/register.mjs` —— **那个文件在本机不存在**。
   所以「`node --test` 下 13/13 绿」这句话我当时没有复算过，而它现在也复算不了。
   （0051 §5 那条「读了、写进了注释、又犯一遍」在这里的变体是：**抄了、写进了结论、又没跑一遍**。）

### 为什么选「搬进 vitest」而不是「把它 exclude 掉 + 加一条 node --test 步骤」

exclude 那条路要新增一个 npm script、要带 TS transform（那个 `/tmp` 注册器就是为它存在的），
而且**结果仍然是这 14 发不在 `pnpm test` 里** —— 覆盖率不计、门禁不看、下一个改 `claude.ts` 的人
看不见它红。搬过来是更小的改动，且把这一族从「两套 runner」减成一套。
唯一代价：`assert.equal` 是**宽松**比较（`==`），`expect().toBe` 是严格（`===`）⇒
搬迁让判据**变严**。我按「若红则是真发现、不许改断言迁就」执行，结果 14 发全绿，
说明那些字段今天本来就是严格相等的（这条是**观测**，不是我推断它们一定相等）。

## 3. 搬完之后必须重新证明它有判别力，结果 14 发变异里 3 发逃掉

「搬进来就绿」不是证据（0053 §2 同一句）。验收只有一条：把**生产源码**
`packages/hub/src/engine/claude.ts` 逐处改坏，每一处都必须红。
探针入库 `.workbuddy/round259-vitest-port-mutate.mjs`，14 发照文件头自己写的那句承诺挑：
「这一层最容易出的错全在进程边界上（参数没传过去、输出不是 JSON、进程挂住不退、非零退出被当成功）」。

第一轮 **11 / 14**，三发存活。三发的成因**各不相同**，而且**没有一个是「断言写松了」**：

| 变异 | 为什么改坏仍绿 | 补法 |
| --- | --- | --- |
| P3 `rolePrompt` 不上 argv | 测试**标题一直写着**「rolePrompt 真的出现在 argv 上」，而**体内从没断过它**；桩也从不回显这个位置 | 桩新增 `systemPrompt` 回显 + 补一条断言 |
| P4 空 `resumeSessionId` 也推 `--resume` | 桩把「不带 `--resume`」与「带空串的 `--resume`」回显成**一模一样**（都是 `"resumed":""`）⇒ 两种实现无法区分 | 桩新增 `resumeFlag` 布尔，与 `resumed` 分开报 |
| N1 只看 `is_error`，非零退出当成功 | 桩的 `nonzero` 档**同时**给 `is_error:true` 与 `exit(1)` ⇒ 两个失败信号绑死，测试对「只信一个」没有分辨力 | 桩新增 `silentfail` 档（`is_error:false` + `exit(3)`）+ 新增一发 |

补完 ⇒ 【实测】**14 / 14**，且收尾自检 `src` 与探针启动时**逐字节一致**。

⭐ **这一族里最该记的是 P3 的形状**：一条测试的**标题**写着某个性质，**断言**里没有那一格，
于是这一格**谁都没守**，而且它红了这么久（13 发全绿）没有任何东西会提示。
标题不是断言。可迁移的动作：**读一条测试时看标题承诺了什么、体内断了什么，两者做差**。
P4 与 N1 是另一种同一形状：**桩把两个应当可区分的状态回显成同一个值**，
于是判据在两个状态上恒同 —— 这与 0053 §2「排除定义处的 filter 永不生效」是同一族
（判据对它声称要盯的那件事分辨能力为零），只是这一侧的成因在**夹具**而不是判据。

**我没验的那半**：真 CLI 会不会给出 `is_error:false` 却非零退出 —— 本机离线、CLI 装不上。
所以 `silentfail` 那一发钉的是【适配器不许只信一个信号】，**不是**【真 CLI 长这样】；
这句话写在测试自己的注释里，不只在本文档里。

## 4. 顺带纠正我自己留在 0053 §7 的那句

0053 §7 原句照留，就地追加更正（0050 §6.2 / 0051 同一口径：**我自己的假结论就地改，历史条目不改写**）。
「既有良性」这个词是我写的，错的是**我没有跑**：那条 `No test suite found` 我读了、以为是噪音、
还给它找了个「node:test 文件 vitest 收不到」的解释——**那个解释是对的，结论是错的**：

形状：**给一个红灯找到正确的机理，不等于给它找到无害的结论**。

## 6. 我本轮犯的错

1. **搬迁第一版把路径导入写坏**：`const HERE = __dirname` —— ESM 里没有 `__dirname`。
   正确写法（`fileURLToPath(import.meta.url)`）就在**我正要覆盖的那份文件里**，我抄的时候丢了。
2. **一次 Edit 手滑删掉了函数体第一行**（`process.env[...] = "garbage"`），
   而且是我自己看 diff 时发现的 —— 那一发若没被发现会红在「环境变量没设」上，红因与判据无关。
3. **注释里第三次写坏中文括号**（`【不回收"东西`）。0054 §7 第 4 条刚写过
   「光把坑写进文档不阻止我再踩」，本轮换了一种坏法又踩一次。修法是**用 node 做字符串替换**
   （memory 里那条），不再重打那串中文。
4. **`213` 那个数我读错过一次**：引擎目录连跑两次都是 213，我以为「加了一发而数没变」。
   实际是两次都已在新增之后，全套的 2361 → 2362 才是对的那个数。
   ⇒ 读了两个相同读数就下结论，和 0051 §5「同一份输出出现两次可以是稳定也可以是同一份坏代码」是同一课。

5. **自己写的计数正则会返回 0 条诊断而实际有 3 条**：临时探针里我用
   `/^packages/[^s]+:d+:d+s/` 去抓 biome 的诊断头行，两次运行都抓到 **0** 条，
   而 `Found 3 errors` 明明在同样的输出里。biome 的诊断头不是那个形状（它是
   `file.ts:LINE:COL rule ━━━` 之外还有前导空格/Windows 反斜杠路径）。
   ⇒ 这正是 0053 §2 那一族换了个地方：**过滤条件写错 ⇒ 恒不命中 ⇒「没抓到」被读成「没有」**。
   发现它是因为 0 条与 `Found 3 errors` 互相矛盾；如果我只看自己那个数就会报「这两个文件修前也没问题」。
   换成 `--reporter=summary`（biome 自己聚合，不是我正则聚合）才拿到能用的分解。

6. **把一个总数拆成分解时没做加法**：§5 里「organizeImports 1 + format 3」写成了一句
   解释「为什么这 3 条属于本篇」的话，而 1+3=4。是回头复算时才撞上的。
   ⇒ 分解比总数更容易错，因为它没有「和必须等于总数」这道自动检查；
   而我引它不是为了凑数，是为了论证归属 —— 论证用的数错了，比清单里的数错了更贵。

7. **把一次性探针的临时文件落在了仓里**：为了在真实路径量 HEAD 的 biome 计数，我建了
   `tmpprobe/` 并往里 `git show` 了两份副本，用完没删 ⇒ `test-inventory` 那一发红了
   （`uncollected: [tmpprobe/claude.test.ts]`）。核对两份副本与 HEAD blob 逐字节相同后才删。
   ⇒ 反面也是本篇的结论之一：**这一发真的会红**（它不是 0053 那种从来没生效的设计红）。

## 7. 别当成做到了

* **搬迁不等于那 14 发以前是假的**。它们的**内容**一直是对的（13 发在 `node --test` 下确实通过）；
  坏的是它们在**门禁里不被执行**。本轮改变的是**谁执行它们**，不是它们的判据。
* **`silentfail` 那一发的现实性没实测**（§3 末）。真的 CLI 有没有那种形状我不知道。
* **桩的回显面变宽了**（新增 `systemPrompt` / `resumeFlag`）。这是**测试夹具**，不进产物；
  但 `fake-claude.mjs` 是**多个测试共用**的（charter / dispatch 那条路也读它的 `cwd` / `budget`），
  所以改动跑过整个 `packages/hub/test/engine/`（213 例）而不只这一份文件。
* **`pnpm verify` 整条链我仍然没有跑**（项目规矩：待人亲跑）。我**分别**跑过它的三段：
  `biome`（291，比 HEAD 少 3）、`tsc -b`（exit 0）、`vitest run`（exit 0）。
  ⚠ 这不等于 `pnpm verify` 绿 —— `pnpm` 还会带上 workspace 里别的包与 pnpm 自身的检查。
* **`tsc -b` 不覆盖 `test/**`**（0007 §5，仍是那条待 CEO 的决定）。本轮这份测试文件的类型
  只靠**一次性** `tsc --noEmit` 手工核过，不是闸门。
* **变异探针不进 CI**（同 0053 §8 / 0054 §8）：14 发的判别力证据在 `.workbuddy/` 里等人跑。
* **门禁现在 exit 0，说的是「今天没有红的东西」，不是「没有缺口」**。
  接线缺口一条没消（0053 §8 那四条仍然为零调用方）。这一轮只让「红」重新变成一个**有意义**的信号。
