# 0057 一句「诚实标注」写完了而机器看不见，和一行删掉测试照样绿的断言

> 起点是优化设计文档 O6 的动作 1：「先在 `engine/claude.ts` 头部把『今天唯一生效的安全
> 边界是 `--permission-mode plan`』写清楚 —— 不做的话后面每一条都会被误读成已兑现。」
> 我做了，写完还给它加了四个模块名，理由是本仓的死模块哨兵按【模块名 + 否定词】找主张句。
> **那一版对哨兵是完全隐形的。** 本篇记两件事：①「诚实标注」这件事可以整体兑现而
> 兑现的那一格是零；② 一条测试里可以有一行断言，把它整行删掉，全套仍然绿。

---

## 1. 一句话

| | 我以为的 | 实测 |
| --- | --- | --- |
| 横幅 | 措辞照着 `claimSites` 写 ⇒ 哨兵看得见，接线那天会点名 | 口径是【模块名与否定词**同一行**】。我把四个模块名写在一行、`对外零 import` 落在下一行 ⇒ 四个模块的命中数**全是 0** |
| 那条四状态 canary | 五条断言把「接上→删基线→再断」整条链钉住了 | 其中【状态③那一行整行删掉，测试仍然绿】—— 它是绿色测试里的装饰物 |
| 「不许再断」这条验收 | 方向 A（新增死模块 ⇒ 红）已经覆盖 | 只在**基线那条已被删掉之后**才成立；条目还在时「死 + 在基线」正是守卫眼中的预期状态 ⇒ 绿 |
| 恒红的验收命令 | 文档写了「今天它红」，照写 | 按 0056 的结论**不能写**。恒不可能通过 = 恒红断言，会被当环境噪音关掉 |

两个通用结论在 §6 与 §7，比本篇任何一个具体缺陷都长。

## 2. 起点：动作 1 要求的是「不会被误读」，我交付的是「不会被看见」

`harness/` 四个模块（`gateway` / `safety` / `routing` / `verifier`）对外零 import，
约 3300 行安全层不在生产路线上。它们的**注释读起来像是在跑** —— 这才是 O6 说的那处
「当前最高危的误读」。动作 1 的产物是横幅 + 一句诚实标注，而我加的四个模块名是为了让
`test/arch/dead-modules.ts` 的 `claimSites` 在接线那天点名它们（横幅应当**自删**，
不等谁记得改文档）。

复算方式不是「读一遍觉得写了」，是**注入探针逐模块打印命中数**：

```
### harness/gateway.ts -> 2 处   （INDEX.md + gateway.ts 自己）
### harness/safety.ts  -> 1 处   （只有它自己）
### harness/routing.ts -> 2 处
### harness/verifier.ts -> 5 处
```

`engine/claude.ts` **一次都没出现**。我那段专门为了「让哨兵看得见」而写的话，
让哨兵看不见的原因是排版：

```
 * harness/gateway.ts、harness/safety.ts、harness/routing.ts、harness/verifier.ts
 * 四个文件今天对外零 import，本模块一个都不经过）。
```

名字在第一行，否定词在第二行。`claimSites` 逐行扫，要求**同一行**里既有模块名又有否定词。

这件事的形状值得单独停一下：**它不是「注释写错了」**。措辞、事实、模块名、意图全对，
唯一的缺陷是它在机器那里不存在。而它比「没写」更坏，因为下一个来查「O6-1 做了没有」的人
会读到那段话，判「做了」——那正是动作 1 要防的那次误读，只是换了一层。

**复算口径**：探针注入 `claimSites` + `trackedRows`，按模块打印命中清单；
`trackedRows` 的取材范围是 `packages/hub/src/**` 与 `docs/**` 里的 `*.ts` / `*.md`，
排除 `*.test.ts`（测试 import 一个模块不构成生产调用方）。

## 3. 口径为什么故意宽、又故意窄

`claimSites` 的判定是「模块名或 basename **同行**出现一个否定词」，注释里也算
（主张就写在注释与文档里）。这条口径两头都被咬过：

- **宽**是故意的。代码里「这段今天不走」的句子经常改天会变成事实，必须被追到，
  所以宁可多报几条让人扫一眼。
- **窄**在换行这一格上不是故意的，但**当场不放宽**。放宽成「跨行找最近的否定词」
  会把正常的散文判成主张 —— 一段话先介绍 `gateway` 的注入函数、三段之后说
  「没人调用它」，那是散文不是主张句。代价改由**射程**承担：新增一发守卫，
  逐文件判真横幅必须命中，谁重排了横幅谁红。

这个取舍写进了测试，没有藏成「口径就是这样」。

## 4. 补的守卫，和它自己的变异

新增 `test/arch/dead-modules.test.ts` 两发（该文件 21 → 23 发，`test/arch` 198 → 200）：

**① 横幅的机器可见性。** 逐文件（不是「全仓至少一处」）拿四个真横幅判 `claimSites`
命中，且首个命中必须落在文件头 15 行内 —— 命中在正文某处说明横幅被人挪走或删了，
而巧合的那句替它说了话。只判「全仓有命中」不够：别的文件替它响，真正的漂移就藏在
别人那一行里。

**② 「不许再断」是四状态链**（§5）。

变异实测（每一个都先断言源串在文件里、否则不算打上 —— 0013 §9 记过一次「变异脚本
自己写空，报『存活』而跑的完全是未变异的旧代码」，那是第二次，同 0012 §5）：

| 变异 | 结果 |
| --- | --- |
| `claimSites` 改成忽略换行（整文件当一行） | **2 发红**（新守卫 + 老的「同行才算」那发） |
| `claimSites` 恒返回空 | **4 发红** |
| 把 `routing.ts` 那半句否定词换到下一行（**数据级**，就是我自己犯的错） | **1 发红，且红话点名**：`expected '横幅隐形：harness/routing.ts' to be '横幅隐形：'` |
| 状态④那格改成期望绿 | 1 发红 |

红话点名这一格是有意为之：拼**串**而不是拼**数组**，数组只报 `Array(0)`，
认不出是哪个模块的横幅坏了。0007 §4.1 那条法则在这里的用法是 —— 读不懂的红会被关掉。

写这一发时先撞到一个自己的错：`expect(value, "说明")` 当成 vitest 的重载用了，
它没有这个重载，于是红是 `TypeError: actual value must be number or bigint`，
读起来像夹具坏了而不是断言失败。**一条自己坏掉的断言，它给出的红在替它撒谎。**

## 5. 第二发：那条链不是一环，是四环半

文档原文要的「`harness/` 若再次变成对外零 import，红」，判它的确实是方向 A
（死而不在基线 ⇒ 红）。但**只在基线里那条已被删掉之后**成立：

| 状态 | 可达性 | 基线 | 判据 |
| --- | --- | --- | --- |
| ① 今天 | 死 | 在 | **绿** —— 「有实现、有测试、零调用方而全仓不红」的形状本身 |
| ② 接上了 | 活 | 还在 | 方向 B 红，点名该改的主张行 |
| ③ 照红行说的删掉基线 | 活 | 无 | 绿 |
| ④ 之后有人把 import 摘了 | 死 | 无 | **方向 A 红 ← 这才是「不许再断」** |
| ⑤ 再断而基线还在 | 死 | 在 | **不判** —— 这套机制的**边界** |

保证不来自方向 A 本身，而来自「方向 B 会一直红，直到你把那条删掉」：
它把【删基线】从"记得做的好事"变成"不红就得做"。状态⑤必须写在表里，
否则读这张表的人会以为链子比它实际更长 —— 它保证「接过之后再断会红」，
**不**保证「从来没接上会红」（后者是 O6 的动作本体，不是守卫的账）。

## 6. 一般化其一：断言的**可删性**也是一条判据

变异实验在 canary 上抓到三个存活：

| 变异 | 为什么活 |
| --- | --- |
| **M4** 删掉状态③那一行 `expect(run(true, EMPTY).length).toBe(0)` | 那一行**不改变任何后续结果** —— 它读的输入与②相同，判的是个纯事实 |
| **M5** 把进度读数里的 `dead && inBaseline` 放宽成只看 `dead` | 今天四个模块都还死着，两个条件给出同一个答案 |
| **M6** 把逐文件循环改成只看第一个文件 | 四个横幅恰好同样措辞 |

**M4 是真缺陷**，不是实验的粗糙。一行断言删掉而全套仍绿，说的是这一行
【没有在判任何东西】——它是绿色测试里的装饰物。它比不写更坏：它让后面那条
看起来「有前提」，而那个前提是虚构的。

修法不是"再补一行"，是换结构：**把所有状态拼成一条断言**。

```ts
const states = [
  "①断了+在基线(今天) = " + verdict(false, base),
  "②接上+在基线 = " + verdict(true, base),
  "③接上+删了基线 = " + verdict(true, EMPTY),
  "④再断+删了基线 = " + verdict(false, EMPTY),
  "⑤再断+基线还在(边界,不判) = " + verdict(false, base),
];
expect(states.join(" | ")).toBe("…五个期望值…");
```

删掉任何一行都让拼出来的串变短 ⇒ 立刻红。**断言的强度可以靠形状买到**：
一个消费方读全部产物的形状，让"少算一项"从静默变成不匹配。

**M5** 的修法不同。`dead` 与 `inBaseline` 两个条件今天同答，光看现状永远分辨不出
哪个在干活 —— 补一个**控制组**：临时把 gateway 那一格从基线里拿掉，读数必须翻。
「一个条件若在两个输入下给出同一个答案，它就没在判任何东西」这条判据本身可以复用到别处。

**M6 与「控制组自己那一条被删」（M8）都活着，而这是对的**：控制组防的是**判据坏掉**，
不防"有人把这行删了" —— 任何控制都自证不了自己还在。这一格写进了注释，
免得下一个人把它当冗余简化掉。区分这两类存活很重要：把「结构上测不到」当成
「测完了没问题」，就是 0056 §3 那条「不对称决定什么才有资格叫腐烂」的反面用法。

## 7. 一般化其二：坐标要在**动完那个文件之后**再数

同一个坐标（`engine/claude.ts` 里 `i.timeoutMs ?? 180_000` 那一行，被 0044 §4 引用）
在这一轮里错了**两次**：

| 我写的 | 那行实际是什么 | 谁抓的 |
| --- | --- | --- |
| `:106` | 裸一句 `}` | `doc-refs` |
| `:109` | `timedOut = true;` | `doc-refs` |
| `:111` | `}, i.timeoutMs ?? 180_000);` | —— |

第二次尤其没道理：已经被红教过一遍，还是按「上次是 109，我又加了 2 行」推的。
推的过程没错，错在**我还在往那个文件的头部加行**。

⇒ **同一轮里凡是改过某个文件，引用它的坐标要等这个文件停手之后再数。**
快照这个形状在这里也值回它的全部成本：`key` 存行号、`value` 存那一行的内容，
所以「看着像」的行号一个都混不过去。如果快照只存行号，`:106` 会一路绿到有人
真去读那一行。

0044 §4 里原地留了这段话（含「我一度写成 106」），没有悄悄改掉。

## 8. O6 的验收：一条不写，一条换了判据

| 文档原话 | 落地 |
| --- | --- |
| 「`engine/` 必须 import `harness/gateway`，缺则红。**今天它红**」 | **不写。** 恒不可能通过的验收命令 = 恒红断言（0056 §1 的同一族：恒红与恒绿一样会把信号读没，0007 §4.1 记的是误红那一面更贵）。它要的是**接线那天**才成立的断言，那一天由方向 B 负责喊 |
| 「`harness/` 若再次变成对外零 import，红」 | **落地**，判据是 §5 那张五状态表，不是链尾 |
| 动作 1「诚实标注」 | **落地**，但必须连 §3 那条排版口径一起落地，否则等于没做 |
| 动作 2 / 3 / 4 | **没动**。四个模块今天仍在基线里（canary 里那条进度读数判的就是这一格） |

O6-2 的接线点仍是 `engine/runtime.ts` 的 `onCost` 旁边；O6-3 那条硬顺序约束
（必须在真员工拿到写权限**之前**）没变。

## 9. 没修 / 别当成做到了

* **`harness/` 今天仍然一行都不执行。** 本篇动的是「这件事会不会被误读」与
  「再断一次会不会红」，**不是**「接上了」。四个模块仍在死模块基线里。
* **`claimSites` 的换行盲区还在。** 我只补了「真横幅不许换行」这一格射程，
  没有放宽口径。别的文档里如果有一句主张恰好跨行写，它今天仍然隐形。
  放宽与不放宽的账在 §3。
* **状态⑤那一格（再断而基线还在 ⇒ 不判）是设计边界，不是待办**。
  想让它红，等价于回到 §8 第一条那条恒红断言。
* **canary 用的是合成小世界**，不是真仓库。真实进度只在最后那条读数里，
  而它是**进度读数**不是主判据（主判据是「不可达集合 ≡ 基线」那条）。
* 复算：`npx vitest run test/arch`（**200** 通过，其中 `dead-modules` **23** 发）；
  `npx tsc -b`（exit 0）；`npx biome check .`（**286** error / **109** warning，
  与 ADR 0055 记的基线同数）。⚠ 这三个数**不写「终版」**：本仓的计数是自指的，
  再编辑本篇或那两个测试都可能让它动（0056 结尾那条同一口径）。
