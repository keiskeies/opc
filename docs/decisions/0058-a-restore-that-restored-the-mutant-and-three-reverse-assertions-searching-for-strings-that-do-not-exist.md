## 2. 第一条：恢复工具的基线污染，以及「byte-identical」这句话为什么不算证据

上一版的驱动器形状是：

```js
const s = fs.readFileSync(p, "utf8");
fs.writeFileSync(BAK, s);          // ← 先备份
const n = s.split(anchor).length - 1;
if (n !== 1) { ... }               // ← 再校验
```

单次运行是对的。它坏在**第二次运行**：第一次跑完文件是变异体，若没 `restore` 就再跑一次，
`BAK` 会被变异体覆盖，`sha` 记录也跟着更新成变异体的哈希。此后 `restore` 拿三个数一比，
全对，打印 `RESTORED byte-identical` —— **它恢复的是变异体，而这句话说的是"和基线一致"**。

本轮的真实经过不是假想：`prompt.ts` 里那句

```
sections.push("额外：档位 " + c.modelTier + " 预算 " + c.budget.dailyUsd + ...)
```

在我开始写这一篇时**还在生产代码里**。我是靠"备份目录里有 `b.bak` 和 `c.bak` 两份、
而 `c.bak` 里 grep 得到那句注入"发现的，不是靠驱动器报的。

三条结论，都写进代码而不是记在脑子里：

1. **备份已存在 ⇒ 拒绝运行**，不覆盖。基线只能被建立一次。
2. **锚点校验在落备份之前**。顺序本身就是判据（与 0007 §5.2 那条「先读口径判别式
   再看计时数，计时数任何时候不得单独发布」同一形状：先确认量的是对的东西，再取值）。
3. **恢复后额外断言"变异标记已消失"**。前两条 + sha 三项全是**自比**（现在的我和
   记录的我一致），只有"标记不在"这一条是**对着基线的性质**判的，而不是对着我的记录。

⚠ 第三条补的正是前两条补不到的那一格：**一个自证的校验器，在基线自己被污染时
会说真话关于一件假事**。这和 0057 §6 那条控制组的限界是同一件事（控制组防判据坏掉，
不防基线错），只是这次的载体是变异工具而不是测试。

## 3. 第二条：反向断言的 needle 必须是**夹具真的带着的值**

`charter/prompt.ts` 的立场是「已有执行点的字段**不**抄进提示词」。这条立场写在文件头，
而**文件头不会被任何断言执行**，所以它唯一的机械证据是 `prompt.test.ts` 里那张
`EXCLUDED` 表，一行一个字段。第一版长这样（节选）：

```ts
{ label: "budget 第二格", why: "同上（per_task）", forbidden: "per_task_usd" },
{ label: "search_policy", why: "门控判它", forbidden: "tier_1_mandatory" },
{ label: "harness_defaults", why: "注入给 harness 的参数", forbidden: "permission_mode" },
```

三行都绿。三行都**什么都没判**：`charterSchema` 的 transform 交出的是 camelCase
（`perTaskUsd` / `mandatoryDomains` / `harnessDefaults`），那些 snake_case 键名
在读者拿到的那颗对象里**不存在**，所以「它没出现在提示词里」这一半**恒成立**。
一行反向断言的两个半边（**不在输出里** 且 **在输入里**），我只写了前一半，
而后一半在没有分母时是免费的。

改法有两层，第二层比第一层重要：

1. 每一行的 needle 换成**夹具里那个字段的真实取值**，并且**全夹具唯一**。
   不唯一会被**别的字段**供给：`reports_to` 用 `"director"` 时，
   `dissent_rights.escalation_path` 那句 `"director → ceo"` 也能供上"在输入里"，
   于是那一行在替**另一个字段**发言 —— 它仍然绿，而它绿的原因与它的标题无关。
   所以夹具里上级改名 `boss_of_dev`，三个预算数取 `1234 / 5678 / 99999`
   （**互不为子串**才是判据；第一版写 `901234`，把 `1234` 包进去了）。
2. **两个半边写在同一条 `expect` 上**，拼成一个字符串：
   `label + ": 在输入里=" + inInput + "，出现在提示词里=" + inOutput`。
   分成两条 `expect` 时，后来人删掉后半那半是 0057 §6 那种装饰；拼起来之后
   删掉任何一半都让**那一行自己**红，而红行里看得见是哪个字段。
3. 表的**覆盖面**从表**派生**，不另写一份名单：`NOT_INCLUDED = [...new Set(EXCLUDED.map(r => r.key))]`。
   我第一版在旁边手抄了第二份名单，那正是这个文件整个要治的"两个源"。
   再加一发「`INCLUDED ∪ NOT_INCLUDED` 必须**等于**全部键，且两份名单无交集、
   无凭空键」：contracts 的 `Charter` 加字段 ⇒ 这一发红，逼加的人当场决定
   「这个字段进不进提示词、不进的理由是什么」，而不是让它默认落进"没人决定过"那一堆。

**分母那发一度是八个手写的布尔**（`c.modelTier === "execution"` …），
表里有十一行而它只有八项 —— 它自己就是会漂的那类东西。换成对**表**发言：
每个 needle 在整颗输入 JSON 里**恰好命中一次**（0 次 = 夹具没给值，>1 次 = 会张冠李戴）。
这一发在我改完夹具取值之后**立刻红了**（`budget_discretion→"901234" 命中 0 次`），
是我本轮第一次被自己新写的守卫当场抓住，而不是它被我事后证明有效。

## 4. 第三条：两次变异，和一句写在文档里的「今天这个变异全绿」

**变异 B = O2 验收 (a) 本身**，设计文档原话：

> (a) 一条**变异**测试：把 `rolePrompt` 里读岗位书那一句注释掉，必须至少有一发红。
> 今天这个变异**全绿**（我量过：`engine/` 里对这些字段名的引用是 0）。

（**替换调用结果**，不删变量 —— 删变量测的是"编译器在工作"，0045 §9 G1′ 那条），

| 红的测试 | 死于 |
| --- | --- |
| 有岗位书 ⇒ 逐格出现 | 主断言 |
| 那一版读坏了 ⇒ 抛 | 主断言（`toThrow(/不是合法 JSON/)`） |
| 角色名跟着走 | 主断言 |

`expected '你在一人公司里担任角色 [dev]…' not to contain '没有你的岗位书'`，

这个价格必须付（不付就是那条测试完全隐形），但**要知道是谁杀的** ——
否则下一次有人精简那发、把"重复的"附录删掉，主断言仍然绿，杀掉变异的就没了。

## 5. 第四条：`stripComments` 吃掉真代码，以及我那个**杀不掉变异的复现夹具**

本轮我往 `store.test.ts` 写了一句普通行注释，内容里带一个 glob（`test` 后面两个星号）。
共用夹具 `packages/hub/test/fixtures/fixture-dir.ts` 的 `stripComments` 是两条 replace：

```ts
text.replace(/\/\*[\s\S]*?\*\//gu, "").replace(/^\s*\/\/.*$/gmu, "")
```

**块注释先剥、行注释后剥** ⇒ 那个 glob 里的块注释起始串被当成注释开头，
贪心地一路删到文件里下一个块注释的收尾串为止。被删掉的那一段里住着
`afterAll` 与 `rmSync(TMP, …)`。症状是普查红着报「这个测试文件没有清理」，
而清理好好地在那儿（实测 `stripComments` 后 `afterAll(` 的命中数：**1 → 0**）。

三件事值得单独记：

1. **这类"先粗删一遍再细删一遍"的剥法没有顺序能写对。** 块注释里的 `//`、
   行注释里的 `/*`、字符串里的两种（URL 里的 `//` 是日常形状），
   任何一种都可能被另一条规则的定界符骗到。唯一的形状是**一次扫描同时定上下文**。
   全仓那一份是 `test/arch/ts-lex.ts` 的 `lexTs`；本轮不 import 它有两个实测障碍
   （跨目录那条相对 import 会撞上 0007 §5.2 记的那个至今在仓的 TS2307；
   两个目录在 vitest include 与 `test/arch` 守卫射程里是两个不同集合）。
   所以本轮放的是**同一条算法的第二份**，并且**这是重复而不是收敛** ——
   仓里另有两份私有副本（`bindings/im.test.ts:102`、`web/renderer-criteria.test.ts:53`）
   **同样是这两条 replace**，同样有这个缺陷，本轮**没动它们**（见 §8）。
2. **它的方向是误红，不是假绿。** 0007 §4 那条规矩管"守卫静默不判"；这一发防的是
   反方向，而它比假绿更贵：被吃掉的是**真代码**，所以不是"少看一眼"，
   是"看见的那一眼里没有那块东西"。人对着这种红的第一反应是**再去补一句真的
   `rmSync`**（重复一份清理）或**放宽判据** —— 两条都往错的方向修。
3. **我第一版的复现夹具杀不掉这个变异，而它自己绿着。** 样例里那句行注释确实带
   块注释起始串，可它**后面没有任何收尾串** ⇒ 老的那条 replace 匹配不上任何东西，
   新旧实现输出逐字相同。判别力为零，而标题看着完全对症。
   ⇒ **复现型夹具必须包含成因链条的每一环，少一环就只是"长得像"**。
   这与 §3 那三行空针是**同一个错**：我给的输入供不上我断言的那个前提。
   现在那条测试的第一组断言判的是**夹具自己**（起始串在不在、其后有没有收尾串），
   并且把**老实现的等价式**写在测试体内直接断言"老实现确实吞掉 afterAll"，
   所以夹具再次失去杀伤力时会**先在这里红**，而不是安静地变绿。
   修好后重跑变异：**KILLED**（3 发同时红）；修表前那次跑是**存活**。

**另一发反向确认**：`prompt.test.ts` 里那颗"键根本不存在"的对象，我一度以为它是装饰。
按现实中最可能的改法造变异（读了 `prompt.ts` 自己那句「undefined 与空数组在契约里是两件事」
而把"没有这个键"也渲染成一句话），红落在 `:252` 那颗 `noKey` 断言上，
而 `a` 不含「不可信」与 `full()` 的阳性对照**都不会红** ⇒ 那一发是承重的。
这发是我自己造完才去验的，顺序对了；§5 第 3 条那一发是**验了才发现是空的**，
两者都记，因为**只有前者会被写进汇报**。

## 6. 结构上的装饰：`CharterPrompt` 曾有三个字段

`hasCharter` **恒返回 true**（"没有岗位书"那一支在 runtime 里直接拼 `NO_CHARTER_LINE`，
根本不构造 `CharterPrompt`），而它的注释在描述一条**不存在的 false 分支**。
`placeholderPending` 值是算出来的（不是恒真），但**零消费者**：唯一的读者只读 `.sections`。

**结构上的装饰比断言上的装饰更难发现**，理由具体：0057 §6 那判据靠变异执行，
而**没人会去变异一个数据字段**。同族的第三种形状：`CHARTER_READ_PATHS` 第一版有四个
kind 标为 `string` 的条目，而那个循环**从不读 `string` 这个值** ——
判了就是第二条 schema，不判就是装饰，我最后选了"不判并且删掉那一格"，
并把"第一版有这个形状"留在注释里。钉它的断言是**键名集合**：
`expect(Object.keys(r).sort().join(",")).toBe("sections")` —— 加一个没人读的布尔就红。

## 6.1 顺手的一处真缺陷：`assertCharterShape` 的名单口径

读侧那份必填名单原来按**类型**取（"Charter 有哪些必填字段"），本轮改成按**读者**取
（「`charter/prompt.ts` 会拆哪些路径」）。触发点是实测到的一个 `TypeError`：
一行 `config` 里缺 `decisionScope` 的历史数据**通过校验**，然后在渲染器里崩。
名单口径写死在文件头，含它**故意比类型严**的代价：`gateCriteriaForRole` 现在对同样的行
**也抛** —— 选它而不是"渲染器严、门控松"，因为那会是**一个事实两个答案**。
今天没有这样的行（这是一条**前瞻性收紧**，不是修一个现存的 bug，写清楚免得被当成交付）。
