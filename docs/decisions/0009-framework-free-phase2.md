# 0009　Phase 2 无框架实现：偏离了计划的哪些 pin，以及这些偏离各自挡住/挡不住什么

- 状态：已接受（§1–§6 是实现层已做的决定，可复算）；**§7 是等 CEO 的一项，已登记在 `docs/INDEX.md`「等待 CEO 决策」**
- 关联：0001（D6-a：`node:sqlite` + 自研 Saver，本篇一脉相承的先例）、0006 §6.2（与计划措辞的偏离怎么登记）、0008 §7（等 CEO 的项形状）
- 范围：Task 2.1 / 2.2 / 2.3 的产出，以及 2.4–2.9 的**可行性边界**。

## 1. 一句话

计划给 Phase 2 pin 了六个框架（Hono、Electron + electron-vite、React、`@ag-ui/client`、
testing-library、Playwright）。这一个环境里**六个都装不上**，我把其中三个的**承重逻辑**
用无框架的方式写了（HTTP 契约、IPC 白名单边界、事件投影），另外三个（渲染层、组件测试、
E2E）**我没有替代方案，也确实没写**。

本篇要交付的不是「我用别的技术也做好了」，而是三件更难看的事：
**① 装不上这件事现在有我复算过的证据**（§2）；**② 每一处偏离各自丢掉了什么**（§4，逐条）；
**③ 有一处我偏离了规格原文，而规格那句是错的**（§5，实测）。

## 2. 「装不上」的证据（此前我只是反复这么说，没给过复算方法）

2026-11-10 当场复算，三条独立通路：

| 检查 | 命令 | 结果 |
|---|---|---|
| DNS | `dns.lookup` | `registry.npmmirror.com` 与 `registry.npmjs.org` **都解析成功** |
| TCP 443 | `net.connect(443, …)` | 两个 registry **都 8 秒超时**，无 RST、无错误码 —— 就是不通 |
| 本地 store | `pnpm store path` 下 `find -iname` | hono / electron / react / ag-ui **四个都零命中** |
| 锁文件 | `grep -c` on `pnpm-lock.yaml` | hono **0**、electron **0**、ag-ui **0**、testing-library **0** |

`npm ping` 我第一版拿 `timeout 25` 包了一层 —— **这台机器没有 `timeout` 这个命令**，
所以那次「跑过了、没输出」实际是 shell 报 command not found 后整条没执行。
那条被我当成证据用了很久。现在换成上面这张表。

**锁文件里那两个看起来像 react / playwright 的命中，都不是依赖**（逐条核过原文）：

- `react: ^18 || ^19` 与 `react-dom` 出现在 `@langchain/langgraph-sdk@1.14.0` 的
  `peerDependencies`，且 `peerDependenciesMeta` 里写着 `optional: true`；
  另一处是 `transitivePeerDependencies` 的清单行。**没有一处是解析出来的 react 包。**
- `playwright` 的命中是 `@vitest/browser-playwright`，vitest 自己的可选 peer。

这条要写下来是因为：如果有人用 `grep -c react pnpm-lock.yaml` 得出「react 在锁文件里」，
他会以为渲染层缺的只是代码不是环境。6 这个数字**全部来自可选 peer**。

## 3. 为什么这一层值得写，而不是留空等依赖

留空是**默认该选**的。替代品最大的风险不是不兼容，是**它看着像做完了**——
「有 HTTP 服务、有测试、全绿」这三件事同时成立时，没人会去问它是不是计划要的那个东西。

真正让我改变主意的是我对自己一次说法的质询。我说「传输层测不了」，
那句里混进一个**没有根据的推广**：不能测的是【框架胶水】，
而 `node:http` 是内置模块，它**就能给真 socket**。所以「测不了」被我从「测不了胶水」
悄悄扩大成了「测不了传输」。

推广被戳破之后，两条**已经写在注释里、没有任何东西守着**的要求各红一次：

1. **带 query 的请求根本无法鉴权。** 客户端签的是它发出去的那一串（`/events?cursor=17`），
   服务端算的是剥过 query 的 path，两侧永远算不出同一个规范串
   ⇒ 任何带 query 的请求恒 401 ⇒ **断线重连整条路是死的**，而症状长得像「凭据不对」。
   contract 层那 37 例**看不见**这件事：那边手写的 path 与签名的 path 是同一个人写的同一个值。
   这不是「少写一条用例」，是那一层的**结构性盲区**——纯 handler 级测试无论写多少条都碰不到。
2. **SSE 断开不回收订阅。** 见 §5。

这两条都不是「无框架实现的质量问题」。第 1 条在 Hono 下一模一样会发生
（签名规范串与路由用的 path 是分开的两件事，与框架无关）；
换框架只会让它**继续没被测到**，因为缺的是那层真 socket 测试。

## 4. 六处偏离，逐条：各自丢了什么

| # | 计划 pin | 我实际做的 | 保住了什么 | **丢掉了什么** |
|---|---|---|---|---|
| 1 | Task 2.1 `app.ts`（**Hono**） | `node:http` + 框架无关的 `HubRequest → HubResponse` | 端点/状态码/鉴权/游标续订的**全部判定**，且跑在真 TCP 上（18 例） | 换 Hono 时那层胶水要重写并接受 review；`server.ts` 里 body 上限、SSE 头、优雅关闭这三件事的**实现细节**不可移植（判定可移植） |
| 2 | Task 2.2 **Electron 壳**（electron-vite） | `ipc-surface.ts`（白名单单一事实源）+ `preload/api.ts`（手写字面量）+ `main/channels.ts`（分发） | 「暴露面 == 白名单」这条**测试能钉的**性质；渲染进程不直连 SQLite / 不读写 `~/.opc-os` 的源码扫描 | **没有可启动的桌面程序**；渲染进程侧的真实隔离行为（`nodeIntegration:false`、`contextIsolation`、preload 沙箱）**一天没被测过**，测的是它的形状不是它本身 |
| 3 | Task 2.3 **`@ag-ui/client` + React** | `web/src/hub/projection.ts`：纯函数投影 + 断线退避（`contracts`） | 计划 Test 项**能测的那一半**（重复幂等、丢失标 stale、退避有上限、验收「渲染进程内无状态机」的源码守卫，22 例） | **没有界面**。「UI 显示降级标记」这条 Test 现在钉的是投影层的 `link` 字段，不是屏幕上有个标记；`useHubEvents` 那层 hook 不存在 |
| 4 | Task 2.4 / 2.6 组件测试用 **testing-library** | 未做 | —— | **四种卡片渲染、`BudgetPaused` 非琥珀色、空态不显示「一切正常」，全部未实现也未测**（规格 §19.2 配色那节，色彩语义写在那儿） |
| 5 | Task 2.9 **Playwright** E2E | 未做 | —— | 计划那句出口「输入想法→看板流转→收件箱审批→看板变 DELIVERED，**全程无命令行**」**无从判定**。这是 Phase 2 的验收本身，不是它的一个子项 |
| 6 | 全局 **vitest** | 仓库外夹具（`/tmp`，靠 `--import` 注入） | 一条能跑全部 `.ts` 测试的命令（576 例） | **它不是门禁**。夹具是 hand-rolled 的 `expect`/`it`，与 vitest 语义未穷尽对齐；**`pnpm verify` 至今跑不了**，Task 1.8 的门控分支覆盖率 ≥95% **一个数都没测过** |

**第 5、6 行是这篇里最该被读到的两行。** 前四行是「我用另一条路做到了同一件事的大部分」，
后两行是「这件事我**没有做到**」。Phase 2 的出口标准依赖它们，而它们在离线环境里
不是换个写法能补上的——需要的是网络。

## 5. 偏离了规格原文的一处：回收的触发点

规格 §5.8 那条背压规则（设计文档第 618 行；§5.8 起于第 604 行）原文：

> **背压**：SSE 写失败即视为消费者断开，回收其队列

我按这句写的实现在真 socket 上**不回收任何东西**：客户端 destroy 之后，
`res.write` 既不抛、返回的 `false` 是**背压信号**而不是断开信号，`res.destroyed` 那一刻
也未必翻真——循环一路 `await` 挂死，订阅连着它的有界队列**永远**留在总线上。

更深一层，也是这篇想留住的东西：**生成器只有在它自己执行代码时才跑得到 `finally`**。
一条正常长连接的取流生成器，绝大多数时候睡在 `for await (const item of sub)` 的 await 上;
连接断了**没人叫醒它**。要等它知道，得真的再来一条事件。于是每个关掉的浏览器标签
占着一条订阅 + 一条有界队列，直到下一条**无关**事件把它冲走——单用户本机可能几小时没有事件。
而规格 §5.8 要的是「断开即回收」，不是「下一条事件到达时回收」。

改法：回收的**发起权**交给传输层（唯一知道连接状态的一层，走 `res` 的 `close`/`error` 事件），
订阅的**所有权**留在 `ResumeStream`。两处回收不是冗余，各挡一条路，两个变异分别跑过、各自变红。
这**是对规格原文的偏离**，不是对它的实现——规格把「写失败」当成可检测信号，而它不可检测。

我在改之前给旧行为找过借口：「回收的触发点是一次写失败，空闲连接不写东西所以没人知道
对端没了」。那句话把一个**实现缺陷说成了一个性质**。原句留在
`packages/hub/test/http/server.test.ts` 文件头第 ③ 条，没删。

## 6. 复算方式

```
PATH=~/.nvm/versions/node/v24.14.0/bin:$PATH \
  node --experimental-transform-types --import /tmp/opc-harness/register.mjs \
  --test $(find packages/*/test test -name '*.test.ts' | sort)
```

本轮结果：**576 例 / 531 通过 / 37 失败**。37 条**全部**是缺依赖（`@langchain/*`、`yaml`、
`vitest` 真身）造成，与本篇改动前的基线**逐条相同**。
`node_modules` 里**没有**任何 hand-rolled 替身——夹具在 `/tmp`，靠 `--import` 注入，
只在这一条命令里生效。理由见 0007 一脉的立场：往 `node_modules` 塞假 `vitest`，
会让未来任何一次真 `pnpm verify` 用桩依赖报出「测试通过」，
那是把一次临时验证伪装成真门禁。

两条**没有**被上面这条命令覆盖的：`pnpm verify`（跑不了）、门控分支覆盖率（没测过）。

## 7. 需要 CEO 拍的：这条无框架路线，是路线还是临时脚手架

实现层能说的已经说完了：判定逻辑与框架无关、已经过真 socket 验证、换框架时判定不用重写。
**但「要不要长期走无框架」不是实现层能定的**——它决定的是这个产品的界面长什么样、
将来谁维护、以及 Phase 2 的出口标准由什么来判定。三个候选：

- **R 维持现状**：Hub 侧保持无框架（我认为这条**站得住**，`node:http` 是内置模块、
  边界已被真连接测过），但**桌面/渲染层仍按计划上 Electron + React**。
  代价：需要一次联网 `pnpm install`；收益：Phase 2 出口标准重新变得可判定。
  这是我在实现时**默认按它准备**的一条——`HubRequest/HubResponse` 那道接缝就是为此留的。
- **S 一路无框架**：连桌面端也用 `node:http` + 浏览器 + 手写渲染做完。
  我**不倾向**这条。理由不是技术难度，是**它会静默改掉规格 §16/§18 描述的产品形态**
  （今日视图四色卡、六列看板、拖拽编排画布用 `@xyflow/react`），
  而那属于「CEO 决定的产品形状」，不该由我在实现时顺手换掉。
- **T 先补门禁再谈功能**：先在能联网的环境把 vitest/覆盖率/E2E 打通，
  确认 37 条红都是环境问题、确认规格 §8.1 那张表真的被门控读到了，
  再往 Phase 3 走。**这条与其他两条不互斥**，它管的是「我报的绿值多少」。

**我的倾向是 R + T**，但这两条都需要一次网络，而这一台机器上我拿不到
（§2 那三条通路）。所以真正在等的东西很朴素：**一个能装依赖的环境**。
在它出现之前，Task 2.4–2.9 我只能继续写「投影与判定」那一半，
而 Phase 2 的出口标准**持续处于未判定状态**——这句是状态报告，不是牢骚，
它应当由你而不是我来记账，因为它决定后面几周的风险敞口。
