## 1. 抽象层的真正判据在哪一格

接口本身（`Channel` / `NormalizedMessage` / `ChannelEnvelope`）是翻译【规格】§11.3，
没有可记的。有内容的是**判决的顺序**：

```
① 是不是卡片动作 → ② 身份 → ③ 通道许可(canAct) → ④ 幂等键 → ⑤ 卡片状态与可逆性 → ⑥ 落库
```

顺序不是风格问题，而**错法是静默的**，所以每一格都配一发「放错位置就红」而不是
「这一格能挡住」的断言。两件事的区别：后者对顺序错**完全无感**（判决字符串一模一样）。

| 错法 | 后果 | 哪一发红 |
|---|---|---|
| ② 放到 ⑤ 之后 | 未授权的人靠发一堆卡片 id 就能让 Hub 每次点击做一次库读；判决仍是 `unauthorized` | 「未授权 ⇒ 拒，且【连库都没读】」—— 断言的是 `loadCalls` 是空数组 |
| ③ 放到 ④ 之后 | 一次被通道拒掉的点击**占住那把键**，这个人换到桌面端再点同一张卡 ⇒ `duplicate` ⇒ **他的决定被吞掉，而他看到「已经处理过了」** | 「canAct 说不行 ⇒ 通道拒；而键没被占住，撤掉限制后同一次点击仍算数」（同一发里的第二半）|
| ⑥ 失败之后不撤键 | 一次 `SQLITE_BUSY` 永久吃掉一个决定 | 「落库抛错 ⇒ 键还回去，重试能落成」+ 「act 返回业务失败 ⇒ 同样还键」|

`canAct`（③）与可逆性（⑤）是**两条不同的规则**，而只写后者是很容易的选择：
【规格】§11.2 白纸黑字写着 **QQ 是只读查询通道、不适合作审批主通道** ——
那是一条**平台属性**，不是这条消息的属性。只判可逆的话，一个**可逆**的审批会
**合法地**从 QQ 被批掉，而「QQ 不能批」这句话在代码上**一行都不存在**。
所以 `Channel` 上有 `canAct?`，而 fake 里有一个「策略说可以、通道说不行」的档位，
让那条规则有真分母（不是只有注释）。

## 2. ⭐ 我写下「那张 IM 账号绑定表今天不存在」—— 它在 0001 就建好了

我在 `ChannelActor` 上面的注释里原本写的是：

> 那张绑定表是「这个 IM 账号属于哪个角色」的事实源，属于 org 层，而它今天**不存在**
> （`roles/` 里没有 IM 账号这一列）。

**这句是错的**，而且错的方向很坏。实测：表**在** `0001_init.sql:249`，
`grep -rn im_bindings` 在 src 与 test 里**读写方 0 处**。我大概是 grep 了 `roles/` 目录
没找到列名，然后把「我搜的那个位置没有」写成了「它不存在」——
又一次**没实测就下全称**（0027 §5-① 那个 `grep -E "^✖ "` 是同族：
仪器只回答你问它的那个问题，而你问的是「roles 目录里有没有」。

**为什么这个错比一般的错贵**：两个说法指向完全不同的下一步。

- 「表都不在」听起来要**从头设计一张绑定表 + 一次迁移 + 一个绑定流程**；
- 「表在而读写方 0」是**接上去就行**（同 0027 §0 那张 `im_tokens`：
  一张表存在了二十几个决策周期而没人写过它）。

前者会让人多花几天，而**不会有人发现自己多花了几天**，因为做出来的东西也能用。

而这张表的默认值本身是个陷阱：

```sql
ceo_role TEXT NOT NULL DEFAULT 'ceo',
verified INTEGER DEFAULT 0,
```

**「把 `actorFor` 直接接到这张表上」这一行代码，今天会造出**：任何一个在平台上发过消息、
而有人替他插过一行绑定的账号，**默认就是 CEO**，而 `verified` 是不是 0 完全不看。
那不是待补的缺口，是**一条能批准的冒充通道** —— 而且它**今天全部测试都会绿**，
因为 fake 用的假定正是「这个人就是 CEO」。

所以本篇做的两件在范围内的事情：

1. 判据写成 `actorFor` 返回 null ⇒ 未授权 ⇒ 拒，**默认就是 null**（装配方接那张表时
   必须自己回答「`verified = 0` 的行算不算数」，那句话写在注释里）；
2. 补两发守卫，因为这个错的形状是「注释里的一句全称」，机器本来管不了：
   - 行为层：`actorFor` **只拿到消息里那两个字段**（变异：把入参换成常量 sender ⇒ 红）；
   - 源码层：本模块**不许出现角色字面量、不许出现 SQL 语句形状**
     （变异 M1 加 `const ROLE = "ceo"` ⇒ 红；M2 加一条 `SELECT` ⇒ 红）。

⚠ 那条源码守卫**第一版是误报的**：我写的是 `not.toMatch(/\bDELETE\b/iu)`，
于是它撞上 `seen.delete(key)`（Set 的方法名）。**一条会因无关代码变红的守卫，
下一次就会被放宽成「算了不拦了」** —— 那才是它真正的失效方式，而不是「漏了什么」。
改成按**语句形状**拦（`DELETE FROM` / `INSERT INTO` / `SELECT … FROM` / `UPDATE … SET`）。

## 3. ⭐ 我写了一个装饰属性，而它是重读源码时发现的

`Channel.supportsActionReturn` 我写了，注释里论证了它和 `canAct` 的区别
（「人没权限」该让人去别处点；「平台不回传」该让**卡片根本不要带按钮**）。
写完重读一遍才发现：**没有任何代码读它**，而 `Channel.send` 也没有任何调用点。

一个没人读的属性就是**装饰**：它能编译、能被 fake 如实设置、能让全部测试通过，
而它的有无不改变任何行为。那正是 0027 §2 那条「自称结构守卫而实际测不到它声称的那件事」
的形状，只是发生在**源码**里而不是测试里。而装饰的属性比没有属性更糟 ——
**读代码的人会以为那条限制生效了**。

两个选择：

- **删掉它。** 更短，也确实消灭了装饰。但 §11.2 那条「QQ 主动消息有条数限制、以被动回复为主」
  是真实存在的平台差异，它需要代码上的落点；**缺的从来不是那条事实，是读它的那行代码**。
  删掉等于把一条已知规则从代码里抹回规格文档。
- **补上读它的那行。** 我选了这个：加 `deliverCard(channel, snap)` ——
  `supportsActionReturn === false` ⇒ 卡片**降级成只读**（三行三按钮照旧，按钮不可点，
  带一句人话），而不是**干脆不发**（不发的那张卡在主界面上是【不存在】，
  而 CEO 需要看到的是「这件事在等你，只是不能在这里点」）。

顺手钉的两条：`deliverCard` **不许盖掉更强的理由**（不可逆 > 收不到回传，
报后者会把人支到桌面端再点一次而那张卡在桌面端也不能一键批）；
`send` 失败**报成判决而不抛**（抛到 poll 循环里 ⇒ 那一轮剩下的卡片全发不出去）。

⚠ 这一格仍然有一个我**没解决、只是记下来**的洞：`send` 静默丢（不发也不抛）时，
`deliverCard` 照样报 `{kind:"sent"}` —— 那是一句谎，而抽象层拿不到任何信号。
真要挡住它得让 `send` 交出**平台回执 id 并落库**，那是 Task 4.4 的活。
违约实验里这一格的期望表**写的就是这条**（红是 fake 的 `sent` 日志抓的，不是抽象层抓的）——
**记成一条有主人的缺口，比改成「测不到，删掉这格」诚实**。

## 4. 「换成 fake channel 全部测试仍通过」—— 这句话证明了什么，没证明什么

计划 Task 4.5 的验收原文是：「飞书实现必须通过抽象层接口测试（换成 fake channel
全部测试仍通过）」。那句话的结构是「**同一套断言**跑在多个实现上都得绿」，
所以测试文件不是一个测试，是一份 28 条的**清单**（`CASES`）跑在**两个** fake 上：

| | fake A | fake B |
|---|---|---|
| 内部队列 | 一个平坦数组 | **分批**（每 4 条一批，模拟长连接每次回调 append 一段）|
| `pull()` | `splice` 整段换出 | 逐个 `shift`，跨批次 |
| 溢出检查 | 数组长度 | **跨批次求和** |
| `canAct` | 闭包读变量 | 方法 |
| `send` | 直接 push 对象 | `JSON.stringify` 再解回来 |
| `deliveryId` | 有 | **恒 null**（有些平台不给）|

最后那一行是刻意选的：它逼着幂等判据落在 `channelActionKey` 而不是 `deliveryId` 上，
于是「只用 deliveryId 去重」那种写法会在 B 那一节当场塌掉。

**这句话证明的**：抽象层的判据不依赖某个实现的细节。
**这句话不证明的**：飞书接得进来。fake 是我照着自己的接口写的，**永远等价**。
真实会被飞书推翻的那部分是**表达力**（飞书卡片回调把签名放 header 而 QQ 放 body，
`ChannelEnvelope` 那天可能发现不够用），那种失败**今天不可能被发现**，
写在 `abstraction.ts` 文件头而不是等那天解释。

因为上面那段是自评（不可证伪），测试文件末尾加了两节**自我拆台**的东西：

**① 违约实验**：把 fake 改坏，看清单是不是恰好红在管那一维的那一发。

| 违约 | 结果 |
|---|---|
| `pull` 只看不取（把 pull 当 peek）| 红「取走的【每一条】都必须被判决」 |
| `pull` 倒序（LIFO）| 红「pull 必须按【到达顺序】交出」 |
| 实现无视 `canAct` | 红「canAct 说不行 ⇒ 通道拒」 |
| `send` 静默丢 | 红，而**抓住它的是 fake 的 `sent` 日志，不是抽象层**（§3 那条洞）|

**② 旋钮自检**：每个旋钮在**两个** fake 上都必须真的改变行为。
一个只在 A 上生效、在 B 上被无视的旋钮，会让「B 那一节也绿」变成假的
（B 跑的其实是另一件事，而满屏绿灯看不出来）。**夹具里的装饰品比源码里的更难发现** ——
它红的时候看起来像夹具的 bug，于是有人会把断言删掉。

还有一发是拆自己的：「两个 fake 的 pull / deliveryId 语义确实不同」。
如果哪天有人把 B 改成 A 的复制品，那两个 describe 会一起绿得更好看，
而「换实现也过」这句话同时作废 —— 所以直接钉住两处真实的实现差异。

## 6. 做到了什么强度，以及没做到的

做到了：入站只有 `pull()` 一条路（接口上**没有** `onMessage`/`subscribe`，
理由见 `Channel` 上面那段 —— 回调式入站会造出**第二条入站路径**，
那条路径上没有策略、没有幂等、没有审计，而它的症状与 0026 §1 同形：
「飞书那边点了，卡片批掉了，而审计里没有那次点击」）；
出站卡片三行三按钮由 `APPROVAL_BUTTONS` 生成而不靠调用方传；
一条通道坏了不带走其余（进与出两侧都是）。

没做到，**别当成做到了**：

- **运行时的生产调用点是 0。** 我没有把它接进 `serve/assemble.ts` ——
  今天没有任何一个通道可以注册（飞书 SDK 离线装不上，Task 4.4 仍未做），
  装一个「巡检循环 + 零条通道」是一个**看起来接上了而实际空转**的东西，
  正是本篇在 §3 里批评的那种装饰。**接不上就是接不上**，写在计划里而不是写进代码里。
- **`abstraction.ts` 确实 import 了 `http/tokens.ts`**，而只 import 一个纯谓词
  （`isIrreversibleApproval`）。理由与代价写在那个函数上面：一条规则只实现一次；
  要解开这条依赖边，正解是把谓词提到一个中立模块，**不是**在 channels 里再写一遍。
- **卡片 → 证据包那条边仍然缺**（§0 第 3 行）。本篇只做了一件在范围内的事：
  把它留成类型上可见的 `evidenceRefs: readonly string[] | null`，
  而不是塞一个 `[]` 抹平 —— `[]` 会让适配器渲染出「证据：无」，
  那是把【我们没存这条边】说成【这张卡没有证据】，对 CEO 是两个不同的结论，
  而**后者会被当成一次追责依据**。补那条边要一次迁移 + 一个「谁在建卡时写下它」的决定，
  不在「通道抽象层」这一篇里。
- **`seen` 那张幂等表是一个已知的内存增长点**，今天没挡。注释里写清了
  **为什么不能用 LRU**（LRU 会**静默打开重放的门**：被逐出的那条重投就能重放），
  正解是 TTL 且 TTL 不小于卡片的可决策窗口 —— 而卡片今天没有
  「多久之后重放必然无害」这个数（超时行为没有执行者，0026 §3）。
- **`pnpm verify` 今天仍然跑不起来**（离线缺依赖）。实际跑的：
  `channel.test.ts` **70 发全绿**、全量 **1505 / 1460 通过 / 37 失败**
  （红名单 60 行与基线**逐条相同，无新增无消失**）、
  `tsc -b --force` **34 条 = 基线**、`test/arch/` 的红**全在基线内**、8 发变异。
- **Task 4.5 那句验收里的「为企微 / QQ 留口」我只做到了接口上留口**。
  计划自己写明「本期不实现企微 / QQ（抽象层由一实现验证，不做二实现）」——
  我用两个 fake 代替了那「一实现」，因为飞书那个装不上。
  **这两件事不等价**，差别就是 §4 第二段。
