## 0. 这一篇补的是什么

0041 把 `hub work` / `hub decide` 那条 CLI 链接通了，产出是「`approveCard` 这个模块写完了」。
本篇是**它的第一个生产调用方**：CEO 在常驻 Hub 里点一次批准，任务**真的往前走一格**。

量出来的改前改后（同一支探针、同一份夹具，跑真的 `buildHubDeps`，一条写路径替身都不用）：

| | 第一次点批准 | 卡片 | 任务 | 第二次点 |
|---|---|---|---|---|
| 改前 | **500** `graph_not_wired` | `approved`（删不掉） | `CHARTER_PENDING` | 200 `replayed:true` + 任务仍不动 |
| 改后 | **200** `{ok:true,replayed:false}` | `approved` | **`CHARTER_APPROVED`** | 200 `replayed:true` + 任务确实动过 |

改动本体是**四行**（`assemble.ts` 少装一个默认值 + `real-deps.ts` 一个适配器），
其余全是「让它不再能悄悄坏回去」的那部分：一条端到端证据（9 发）、启动横幅两条路线各说一句、
以及 §7 那三条坐标漂移。

## 1. 那条 500 长什么样，以及为什么它比「什么都没发生」更坏

探针在 `/tmp` 里起一份真库、走真的 `insertCard` 建一张章程卡、然后按 `assemble.ts`
的装配方式起 deps（关键就是**不传** `graphFor`，也就是生产走的那条），发一次
`POST /approvals/:id`：

```
第一次点批准 : 500 「这个 Hub 入口【没有】接上图运行时（graph_not_wired）」
  任务状态   : CHARTER_PENDING        ← 一步没动
  卡片状态   : approved               ← 已经批了，append-only，删不掉
再点一次     : 200 {"ok":true,"replayed":true}
  任务状态   : CHARTER_PENDING        ← 永远停在这里
```

坏在两处，**第二处更坏**：

1. `applyDecision` 先提交（卡片落 `approved` + 一条 `action='approval'` 审计），
   `resumeGraph` 后抛。顺序是 0010 §5 定的（决策与审计先提交、图后跑），
   在那条路线内部是对的 —— 它假定「图一定能跑」。
2. 第二次点返回 `replayed: true`，而渲染层按规格 §7.2 把它读成「已经生效了」。
   于是**重试这条路在语义上被关掉了**：屏幕先说 500、再说成功，任务从未动过，
   而那个 `true` 是**真话**（那张卡确实已决策）说的一个**假意思**。

那句报错教的补救 —— `hub resume --db … --task …` —— 在 `cli.ts` 那一侧，
而 `cli.ts:28` 顶层 `import "@langchain/langgraph"`，本机 `ERR_MODULE_NOT_FOUND`（0039 量过）。
**也就是说报错给出的那一步在这台机器上跑不起来，而那一次失败的副作用已经不可撤销。**

这一族是本仓反复定义的最贵形状（看起来接上了、跑起来必炸、测试全绿），
本篇多记一笔：**它还会顺带把重试路径关掉**，因为幂等语义会把第二次点击吞成"已生效"。

## 2. 为什么 207 发 http 测试一条都没抓到它

`test/http/contract.test.ts` 那批用例的 `deps` 是**手搓字面量**：

```ts
recordDecision: async () => { calls.decided += 1; return true; },
resumeGraph: async (id) => { calls.resumed.push(id); },
```

它们测的是 **handler 的分支**（404 不调、重放不调、只有首次调），那部分至今正确，
也**至今与生产无关**。`buildHubDeps` 装出来的那两条真实写路径一条都不在被测路径上。

⇒ **被测的那一层不含坏掉的那一半**，所以 http 那一层全绿了不知多久。
本篇新增的 9 发（`test/http/decision-engine-route.test.ts`）因此**一条写路径替身都不用**，
全部跑在 `buildHubDeps` + 真 `WriteQueue` + 真库 + 真 `insertCard` 上 ——
**替身是这个缺陷的成因，不只是它的遮羞布**。

## 3. 换的是哪条写路径，以及为什么不是「在 applyDecision 后面补一拍推进」

三个候选，只采纳第三个：

- **① 在 `resumeGraph` 里补推进**（事后 advance）。**否决**：`resumeGraph(taskId)`
  这个注入点的形状是**为图设计的** —— 它只拿到 `taskId`，**既不知道是哪张卡、也不知道点的哪颗按钮**。
  事后推进只能是**按钮无关**的，而按钮无关的推进对 `reject` / `defer` 就是静默空转：
  卡片记成 `rejected` 而任务被往前推一格。要修它得先把 seam 改成带按钮，
  那等于把决策语义搬进「恢复」这个名字里。
- **② 第三份决策写路径**（自己写认领 + 审计 + 边）。**否决**：`approveCard` 里那段认领 SQL、
  payload 形状、`KIND_TO_ACTION` 取值都是已定过的（0016 §4 那格刚被它们漂过一次），
  再抄一份就是 0006 §7 的「两份必然漂移」长在**最不该长的地方**。
  （我第一版真的写了这个文件 `serve/advance.ts`，两稿都删了：第一稿末尾是
  `publishPersisted?.(undefined as never, 0)` + 一句 `throw new Error("unreachable")`
  —— 占位垃圾；第二稿重复了整段 body 并假定 `resumeGraph` 能拿到卡片和按钮，**那是它拿不到的东西**。）
- **③ `approveCard` 整个用作 `recordDecision`**（**采纳**）。认领卡片 + 状态边 + 两条审计
  在**同一个事务**里 ⇒ **「已批准而未推进」这个状态在库里不可表达**，
  而不是"很可能不会发生"。§1 那个坏形状从此不是被防住，是**没有对应的库状态**。

代价与取舍记在 `real-deps.ts` 的 `decideWithEngineEdge` 注释里，两条值得单独说：

- **`approveCard` 有六条 outcome，boolean 那道缝只映射得到两条。**
  `decided → true`、`already_decided → false`，**其余四条抛**。
  咽进 `false` 会被 `app.ts` 末尾那句 `replayed: !applied` 翻译成「已经有人决定过了」——
  一句听起来像幂等、实际是「你没给理由 / 卡片挂在别的任务上」的谎。
  换写路径换来的是**更严的失败面**，不是新的静默。
- **`resumeGraph` 在引擎路线上装的是一个【有名字的空】**（`engineRouteNothingToResume`）。
  它是必填注入点，而「装配忘了传」与「这条路线不需要它」在类型上长得很像；
  让它成为一个叫得出名字的决定，而不是一个缺席。

## 4. 「不传 = 走引擎」而不是加一个 `engineDecide?: boolean`

`RealHubDepsOptions.graphFor` 从**必填**改成**可选**，选路判据就是「图给了没有」：

```ts
const engineRoute = o.graphFor === undefined;
```

**为什么不加一个显式开关**：那样会引入一对**可以互相矛盾的输入**
（`graphFor` 给了而 `engineDecide: true`，或反之），而每一对矛盾都得再写一段代码去判或去抛。
判据的输入应该是**事实本身**，不是事实的一句转述 —— 与 `bindForAssembly` 那条
「判据的输入被装配焊成常量 ⇒ 判据恒真」是同一条判据的反面用法。
`assemble.ts` 那句启动横幅也因此**不可能与事实漂移**：它读的就是分岔的那个值。

`unavailableGraphFor` **保留导出**，但⚠ **它今天只有测试在调**（grep 实测：`src` 里零调用方，
调用点全在 `test/serve/assemble.test.ts`）。所以"保留它"目前是**保留一条接法**，
不是保留一条在跑的路 —— 这正是 0016 §4 那族「零生产调用方」，
区别只在于这一次是**写在注释里的**（那一族的第一课就是它平时零症状）。

## 5. 鉴权：为什么**不**新开辟一条回环专属的决策路由

想过一条「回环 + HMAC、跳过 `remoteTokenAuth`」的引擎决策路由，**否决**。
`mintToken` 是**独立**的回环专属端点；如果决策路由绕开 token 校验，
远程对端那次 `POST /approvals/:id` 就**完全裸奔**（原来它是靠 token 那条门进来的）。
**为了修写路径而放宽那道门，是拿一个能见的坏换一个不能见的坏。**

而真正的事实是：`decide()` 这个 handler 被**两条鉴权路径共用**。
所以修写路径**顺带把远程那条也修好了** —— 手机上的批准同样是 200 + 任务真的推进，
一行业务代码都不用为它多写。这条记下来是因为「加一条专用路由」看起来总是比
「让共用那条真的能跑」更像在做事。

## 6. 本篇关闭了什么，以及**没有**关闭什么

先纠正我自己在初稿里写过的一句：我原本写「本篇关掉了 `phase3.test.ts` 第 6 条 blocker 的后半」，
**那是错的**，改完了才去核对。那条 blocker 的原话是
「卡片生产者有了，但只在跑不到 CEO 的那一侧：`src/engine` 两条路径经 `insertCard` 真建卡，
而 `http/` 与 `serve/` 里**一行都不建**」—— 判的是**卡片从哪来**，
而本篇一行卡片都没建（改完复跑一次 grep 确认 `http/` + `serve/` 仍然零处 `insertCard`/`createCard`）。
**本篇关掉的是那条 blocker【没在说】的另一件事**：卡建出来之后 CEO 点它，以前必炸。

（那一格**没有**进 `doc-refs` 的快照，是**取舍**不是遗漏：它的锚点是一段两百多字的 blocker 文案，
那种锚点每改一次文案就要动一次快照，而它证的从来不是"这一行存在"，是"这条缺口还在" ——
后者由 `phase3.test.ts` 自己那条 `toHaveLength(6)` 判，比行号准。）

所以准确的说法是：**这条链上原来断两处，本篇接上了第二处，第一处原样保留。**

- 第一处（**没接**）：**卡片从哪来**。`ensureCharterCard` 只在引擎 CLI 那侧，
  常驻 Hub 里没有任何东西起草卡片 ⇒ 不跑 CLI 时收件箱仍然是空的。
  上面那条 blocker 说的就是这一处，它**今天仍然成立**、我没有让它变近一格。
  这是下一个提交（pump）的靶子。
- 第二处（**接上了**）：**卡片被点之后会发生什么**。`approveCard` 从今天起有第一个生产调用方。

**其他没接的，逐条列**：

- `hub:engine work` **需要 `tsx`，本机装不上**（0039）。启动横幅现在**如实说出这一点**，
  而不是给一句照抄会挂的补救命令 —— 那正是改前那句 `hub resume` 犯的错。
- **只有 `approve` 有出边**（`HUMAN_EDGES`，`dispatch.ts:137`：出边那个维度的类型是
  `Partial<Record<"approve", …>>`，**不是运行时忘了填，是类型上就只有这一个键**）。
  `reject_with_comment` / `defer_deep_review` 落库而任务原地，这是**规格的现状**
  （[规格] §7.1），本篇把它钉成断言而不是修掉它 —— 但它曾经是 500，
  一个合法决策换来一个看着像失败的答复。
- **`orgVersionUnchecked`** 照旧写在 `approveCard` 返回值上（0041）。
- **0041 §5 / §7 仍在等 CEO**：同源审阅那张卡今天**每次都触发**；
  预算跨限**没有合法的停法**。
- [规格] §7.4 终止那一格没有合法目标状态；证据包那一格（[规格] §8.2 第 2 条）今天**无处可满足**。

## 10. ⭐ 补 pump 之前先补的一格：零花费的失败轮**在审计里是零行**

这一节是 §6 那条「第一处没接」（卡片从哪来）动手时**撞出来的前置缺陷**，
所以写在本篇而不是下一篇 —— 它是本篇那条链的**下一环**上的洞，
而它的存在让下一篇（pump）**根本不该上场**。

### 10.1 症状：探针实测

`engine/charter.ts` 起草失败那一支（角色跑了一轮而没交出可用提案）旧形状是：

```ts
if (cost > 0) { await w.node(() => { 写审计; 记账; }); }
```

那句「失败了也要结账」是对的（这一轮真花了钱，claude.ts / dispatch 同一条理由；
「卡没建 ⇒ 当什么都没发生」会让账面比实际乐观）。**错的是把审计那一行也一起关进了那个 `if`。**

探针（`runTurn` 返回 `ok:false, costCents:0, error:"spawn claude ENOENT"`，真库真事务）：

```
outcome            = no_draft
events 行数         = 0        ← 零行
tasks.consumed_cents = 0
budget_events 行数   = 0
```

也就是「intake 试过了、失败了、**什么都没留下**」。
而本机最可能的失败**恰恰就是这一支**：`claude` CLI 装不上 / spawn ENOENT / 权限不对，
那几种情况 `costCents` 恒为 0。

### 10.2 一个判据管了两件事

`cost > 0` 这一个判据同时管着：

| 它管的事 | 该不该跟着钱走 |
|---|---|
| 该不该**记账** | **该**。没花钱就该记 0，什么都不该加。 |
| 该不该**留痕** | **不该**。「这一轮发生过、失败了」与花没花钱是两件事。 |

`bill()` 自己一直有 `if (res.costCents <= 0) return;` —— 也就是说**外层那个 `if` 从第二次编辑起就是冗余的**，
而冗余的守卫比缺失的守卫更危险：它看起来是在保护什么，实际上它在**决定谁有资格被记住**。

### 10.3 为什么在 CLI 那一侧只是不便，在这里是致命

CLI 那条 `hub work`：失败那句话会经 `CharterResult.note` 打到 stderr，人看得见 ⇒ **只是不便**。

常驻泵要把它当**重试判据**：有界要能数「这是第几次」，而**没有痕迹就没有计数** ⇒
每个心跳一次 `no_draft`、零行审计 ⇒ 没有任何东西能数出"这是第几次"，
也就没有任何东西能决定"别再试了" ⇒ **一个没有痕迹的无限重启子进程**，
静默、花不出钱、也停不下来，而且事后从库里**看不出来发生过**。

所以顺序是**先修这一格，再上泵**。

### 10.4 ⚠ 我**翻转**了一条既有断言，所以要先检查反对意见

被翻转的那一发原来的标题是「零成本的失败轮**不写 events**（不为一个空事实消费一个 seq）」，
那句理由**听着是对的** —— 一条空事实凭什么占一个 seq。翻转一条既有断言之前
要先把它的理由当**真反对意见**检查一遍，两条都查了：

| 反对意见 | 查完的结论 |
|---|---|
| 多出的 `tool_call` 行会污染角色记忆 | **不成立**。`MEMORY_ROWS_SQL` 只捞 `action IN ('approval','review_decision')`，而 `RoleTurnReported` 的 action 是 `tool_call`（`recorder.ts:52` 那一行就是 `RoleTurnReported: "tool_call"`，而它上面那段注释早就写明「这一行天然不进记忆」）。 |
| CHARTER_PENDING 上多写一轮留痕会和 dispatch 的席位判据撞 | **不撞**。那一格是**人类席位**，dispatch 见它连 token 都不烧；而本模块**一行状态边都不写**（§6 那条 blocker 判的就是这个）。 |
| 「不消费 seq」 | **顾虑本身不成立**。seq 不是稀缺资源，**发生过而没记**才是。 |

修法是把两件事拆开：**审计无条件写**，记账仍由 `bill()` 自己判 `costCents`（它一直这么判）。

### 10.5 判据与变异

新增两发（`test/engine/charter.test.ts`），各断一件事，缺一不可：

- 「零成本的失败轮**照样留痕**」—— 证**有一行**，且**同时**断两面：
  `consumed_cents=0` + `budget_events=0`（留痕而**不记账**）、note 里带着失败原因与「没花钱」、
  广播了 `RoleTurnReported`（写了 events 就必须广播，0010 §4）、卡片**仍然不建**。
- 「连续两次零成本失败 ⇒ 审计里**两条**，数得出『这是第二次』」——
  证**能数**。少这一发，上面那条可能由一个「每次覆盖同一行」的实现满足，照样绿灯。

| 变异 | 红在哪 |
