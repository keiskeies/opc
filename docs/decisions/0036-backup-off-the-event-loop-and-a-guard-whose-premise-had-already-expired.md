- **状态**：已定案。零生产调用方的东西本篇**没有新增**，本篇**去掉**的是「同步占住事件循环」这件事。
- **产出**：`src/db/worker-entry.ts`（新，全仓**唯一**一处由自己的 URL 推 worker 入口的地方）+

  **一条「同步所以没有缝」的论证，在它保护的东西换过一次实现之后就作废了，

## 0. 先给实测（三发，都在同一台机器、同一份夹具上）

夹具：`events` 表 5 万行、每行约 200 字节填充，库文件 **11.5 MB**；
探针是**一个 5ms 的 `setInterval`**，量它相邻两次被叫到的间隔 ——
心跳、写队列、HTTP 全在同一个事件循环上，**那个 gap 就是它们一起停拍的时长**。

| 跑法 | 备份耗时 | 探针 gap P50 | gap P99 | gap **最大** |
| --- | --- | --- | --- | --- |
| 现在：主线程同步 `createBackup` | 91 ms | 6 ms | 91 ms | **91 ms** |
| 本篇：`new Worker` + worker 里跑同一条 | worker 内 212 ms / 总 267 ms | 6 ms | 7 ms | **7 ms** |

⚠ 这三行是**单次**读数，写完之后复算过一遍（抖动与「哪一列才撑得住结论」见 **§8.0**）。

第三发是本篇能不能成立的**唯一**理由，所以单独量了一次：

```
一个「只 postMessage 一句、什么都不干」的 worker，冷启动 = 95 ms / 96 ms（跑两遍）
```

⇒ worker 里那 212 ms 里**约 95 ms 是起线程的固定开销**，真正干活的部分与同步那次同量级。
⇒ **备份这件事本身变慢了（91ms → 212ms，多约 1.2 倍），换到的是主循环一毫秒都不停**。
这笔账为什么划算，只在这一句上：**备份是后台任务，HTTP 请求不是**。
一份 11.5MB 的库停 91ms 不算什么，而 `backup.ts` 文件头记过的夹具形状是 20.4MB / 5 万事件，
那条路径上还要再叠一次恢复演练（0032 让每日那一轮多做一次真恢复）——
**同步路径的代价随库大小线性增长，而它停的是整个 Hub**。

⚠ **这一格我差点写成「备份变慢了 1.2 倍，可以接受」**。那是**没有代价的写法**：
它把两件事压成一个数，而读者无法复算。表里那三个 gap 才是结论，
「变慢 1.2 倍」只是它付的价钱 —— 报结论要连**付的价钱**一起报（0032 §1 同一条）。

## 1. 为什么必须有第二个线程，而 `integrity.ts` 早就回答过一次

`node:sqlite` 是同步 API（规格附录 C.1 那句「大查询会冻结整个 Hub」说的就是它）。
`integrity.ts` 在 Task 6.2 已经为**同一件事**装过一次 worker，那三条约束我照抄而不重写：

1. worker 入口必须挂 `parentPort` 且**判 null 就抛**（被主线程 import 时静默什么都不做 =
   一次检查从未发生而没人报错）；
2. **不得 import 任何 `@langchain/*`**（worker 拿到的是主线程的 execArgv 而**不是**模块图；
   带框架 import 会让入口在缺那几个包时连加载都做不到，本机就缺，0009 §2）；
3. **一切异常都必须变成一条消息回给主线程**（一条坏消息让主线程判失败，
   与一条消息都不发让主线程**永远等**，后者才是不可接受的失效）。

`backup.worker.ts` 三条都守，第 2 条本篇尤其要守：`backup.ts` 本身不 import 图，
而 worker 入口**只 import `./backup.js`**，模块图比 integrity 那份还小。

**但 worker 起不来时本篇不退回主线程** —— 这条立场是从 integrity 抄的，理由同样成立：
自动兜底等于在「最像出事的时候（环境坏了）」悄悄违反本篇唯一的验收。
`createBackupOffLoop` 如实报 `worker_unavailable`，要同步备必须调用方自己调 `createBackup`。

## 2. 一处**共享**的推导式，以及我为什么去动了一条别人写下的守卫

`integrity.ts` 早在 Task 6.2 用一个表达式推自己的 worker 入口
（把自己的扩展名换成 `.worker<同扩展名>`，见该文件里 WORKER_URL 那一行），
一个表达式同时覆盖源码态（`.ts`）与构建产物（`.js`）。它旁边写着
「**全仓只允许这一处**由自己的扩展名推导 worker 入口」，并由 `integrity.test.ts` ⑦ 钉住。

本篇需要第二个 worker 入口，于是撞上那条。三个候选：

| 候选 | 问题 |
| --- | --- |
| `backup.ts` 再写一份同样的表达式 | **直接违反那条不变量**，而且它当初要防的正是这个：推导式多一处，就多一处「有人猜扩展名」而两边各改各的 |
| 每个消费者写死自己的入口路径 | 只在一态下成立（写 `.ts` 则 `tsc -b` 之后产物里没那个文件；写 `.js` 则源码态 ENOENT）。integrity 那个表达式就是为了同时覆盖两态才那么写的 |
| **抽成一处共享（选了）** | 原话「全仓只允许一处」**从「一句注释 + 一条只看单文件的断言」变成一条真的扫全仓的断言** |

⚠ 所以本篇**动了 `integrity.ts` 和它那条守卫**，而不只是加新代码。
读到这里该问的是：那条断言原来真的能守住「全仓只有一处」吗？
**不能** —— 它 `readFileSync` 的是 `src/db/integrity.ts` 一个文件，数的是那一个文件里的命中数。
第二处出现在任何别的文件里，它都看不见。**一条声称管全仓的不变量，配一条只看一个文件的断言**，
这正是本仓反复记的那个形状（判据写在名字里，射程写在实现里，而名字赢了）。
本篇把断言改成扫 `src` 下全部 ts 文件：**恰好一个文件**含那个推导式，
而那个文件是 `worker-entry.ts`；`integrity.ts` 与 `backup.ts` 各含**恰好一次** `selfWorkerUrl` 调用。

⇒ **改别人写下的守卫之前先读它的断言，而不是读它的注释**：
注释说「全仓」而断言只看一个文件时，你以为的约束并不存在。

### 2.1 ⭐ 把那条守卫换成全仓之后，它**两个方向都是错的**

上面那段是「改之前的洞」。改完之后**第一次跑就红，而红的是注释**，这一格比洞本身更值得记：

| 方向 | 实情 |
| --- | --- |
| 误报【有】 | 旧判据是 `/import\.meta\.url\.replace/`。我在 `integrity.ts` 里留了一段话记录「本节原本是内联那串 `import.meta.url.replace(...)`」—— **那段话本身就含这几个字**，于是它被当成第二处推导式 |
| 漏报【无】 | 推导式搬进 `worker-entry.ts` 之后，那里那一行写的是 `callerUrl.replace(CALLER_EXT, ".worker.$1")`，**不含 `import.meta.url`** ⇒ 那个正则【匹配不到真正的代码】 |

两边合起来是一个很难看的位置：**它唯一匹配到的是历史叙述**。
所以「有人把那段注释删掉」这个动作会让这条守卫**变绿**，
而绿的时候它守的是「全仓零处推导式」—— 那正是它最该红的形状。

⇒ **把一条判据搬进新射程时，它的特征往往是照着旧代码写的，而旧代码正是被搬走的那个东西。**
修法不是给正则打补丁，是**换特征的种类**：从「当年那行代码的字面」换成
「这件事的形状」（同一行里既有一次 `.replace(` 调用、又有一个 `.worker.` 那个替换目标），
并给判据自己配一发正向自检 + 一发反向对照（那句散文**不许**命中）。

⚠ 同一族的东西**在同一次改动里出现了第二次，方向相反**：
`assemble.test.ts` 那条「区间里不许有 await」的文本守卫，我给它新加的终点
`backupWatch.start(` **匹配到了我自己写在区间上方的一句注释**，
于是区间被切成两行 ⇒ 「没有 await」白过、而「必须有 lastBackupAtMs」红。
⇒ **给源码形状写守卫时，注释是判据的输入之一，而它是【会被匹配到】的**；
本篇最后改成「先滤掉注释、再切区间」，顺序反过来就是这两种红。


## 3. ⭐ 那条「同步所以没有缝」的论证，作废之后还留在原地

`assemble.ts` 心跳那一段（本篇改动前）原文写着两句话：

> `createBackup` 是同步的 ⇒ job 走到这一行时上一份必然已经落地，
> 一个「永远为假」的判空只是让人以为有人管过这件事。
> ⚠ 这里【不假装】备份是并发的……**同步的东西没有缝**，也就没什么可等的。挪进 worker 是下一篇的事。

而它上面还有一段更长的 ⭐ 注释，记的是**上一版**为什么被删：
上一版有 `backupInFlight`，而那份声明被**局部同名声明遮蔽**，
于是 `giveUp` 里的「等备份落地」读到的永远是 `null` ——
**一次测试全绿的失效**（0025 §3 第 ③ 条）。删掉它的理由就是上面那句「同步没有缝」。

本篇把备份挪进 worker，于是：

- **「没有缝」这句前提变了**，而它下面挂的**结论**（不需要守卫、不需要 cancelling 状态）
  在原地不动，且**没有任何一条测试会因为前提变了而红**。
  ⇒ **一条论证的有效期由它的前提决定，而前提写在另一个文件里（`backup.ts` 的同步性）时，
  改那个文件的人不会知道这里有一条结论靠它撑着。**
  这是本篇唯一值得被读走的一条：注释里那句「挪进 worker 是下一篇的事」**是这篇注释最好的地方**，
  它让下一个人知道要回来补 —— 而它仍然只是一句注释，
  **没有任何东西强制那个人真的回来**（`test/arch/run-fixtures.ts` 文件头那句「注释不是机制」第三次适用）。
- 本篇就是那个人。补回来的两样东西各自配一发**能红**的用例（§5 的 P-A / P-B）。

**「在飞的备份」这个状态本篇是显式建模的，不是靠 Promise 是否存在猜**：
`BackupWatch = { inFlight, cancelling, settle() }`，
`inFlight` 给「同一个 tick 里会不会开出第二份」，`cancelling` 给「关机中不再**开始**新的」。
0025 §7 第 2 条点名的就是这两个词，所以它们**必须是能读到的字段**而不是两段隐式逻辑。

## 4. 回调**不能**过边界；而「注入的时钟也不能」是我写错的那半句

`BackupRequest` 有两个函数字段：`now?: () => number` 与 `onWarning: (message) => void`。
**函数不能过 `workerData` / `postMessage`**（结构化克隆会当场抛）。三条路：

| 候选 | 后果 |
| --- | --- |
| 悄悄不带它们进 worker | `createdAtMs` 变成 worker 自己的 `Date.now()` ⇒ **测试注入的时钟不再生效而测试仍然绿**；`onWarning` 消失 ⇒ **备份静默失败**，而那正是 Task 6.3 验收明令禁止的一条 |
| 在 worker 里另造一份假时钟 | 造出来的时间不是调用方给的那个时间，比不带更坏 |
| **类型上收掉 + 运行时抛（选了）** | `createBackupOffLoop` 的入参是 `Omit<BackupRequest, "now" \| "onWarning">`；有人从 JS 那边硬塞 ⇒ 当场抛，指路「异步版从返回值拿 reason/message」 |

⇒ **「跨进程边界传不过去的东西」要在类型层消失，而不是在运行时被丢掉**。
这条与 `0033 §3` 那条「只有 import 形态能表达的约束要用 import 表达」是同一族：
**能用形状表达的约束，写成运行时检查就会有人绕过运行时检查**。

### 4.1 ⭐ 我登记的那条「限制」只对了一半，而它差一点直接变成缺陷

上面这个表我最初还多写了一行结论，原话是：

> ⚠ 反向的一格要如实说：`now` 收掉之后，**worker 里那次备份的时间戳来自 worker 的墙钟**。
> 单机上这是同一次 `Date.now()`，跨不过去的只是**注入**。

**那句是错的，而且错在关键的一格上**：跨不过去的是【函数】，
而 `now` 这个函数的**返回值是一个 number**，number 过结构化克隆毫无问题。
把「注入的东西传不过去」当成「时间传不过去」，我就把一个可以解决的问题
**登记成了一条限制**——登记这个动作还让它在文档里看起来像已经想清楚了。

发现的方式不是想到了，是**测试红**：把 job 改成异步版之后，
`第二天 ⇒ 该再多一份` 那一发红了。追下去是：

- 相位判据用的是**注入的时钟**（`scheduler.now()`，测试里是 2026-03-10），
- 而备份文件名用的是 **worker 的墙钟**（真机上是 2026-11-10），
- ⇒ `shouldBackUp(2026-11-10, 2026-03-10)` 判「日期不同 ⇒ 该备」，
- ⇒ **同一个时钟下每轮心跳都重备一份**，7 份保留位被同一天挤满，把上周那份真备份挤掉。

⇒ **「注入在这里不生效」和「这里不需要注入」是两句不同的话**，
而把它们混起来的人是按【生产上等价】推理的（生产上两者确实是同一个系统时钟）。
差别只在**注入存在的那一刻**，而那正是测试与回放所在的那一侧。

修法是 `nowMs`：过界的是【时刻】而不是【时钟】（`BackupOffLoopRequest.nowMs`）。
两处拼装各带一次（主线程拼 `workerData`、worker 拼 `BackupRequest`），
而**任何一处漏了都【不报错】**，症状就是上面那条「每轮都重备」。
所以本篇给这一格配了两道锁：一条断【文件名本身】的行为用例（M-H 那发变异验它会红），
和一条钉「派发时带上 nowMs」的源码守卫。

⚠ 这一格还留下一条**真的**收窄（不是被我误登记的那种）：`nowMs` 是一个数，
所以一次异步备份只有**一个时刻**（开始那一刻），拿不到「备份中途的 now」。
`createBackup` 本来就只在取名时调一次 `now()`，所以没有丢掉现有语义 ——
但这是**核对过才成立的**，不是显然的。

### 5.1 ⭐ P-B 只红了一半，而那一半红的方式让我删掉了一行代码

「关机中不再派新备份」这件事在装配层有**两道门**：
`start()` 里那一道，以及 job 顶部一句 `if (backupWatch.cancelling) return`
（我照着旧写法 `if (cleaned) return` 的位置写的）。
拆掉 `start()` 里那一道之后 `assemble.test` **一条都不红** ——
因为 job 里那一道还在挡，行为一字不差。

这句话反过来说才是要点：**我那句「补回来的守卫」是一句拆掉不红的话**，
而 0025 §3 第 ③ 条给「测试全绿的失效」下的正是这个定义。
也就是说：我为了修一个「守卫被遮蔽而没人发现」的缺陷而补的守卫，
本身会以另一种形式成为同一个缺陷。

处置不是「再补一条能打红它的用例」，而是**让门只有一处**：

- 删掉 job 里那一句，状态与判据都收在 `start()` 里面（唯一来源）；
- `start()` 的返回值从 `boolean` 换成 `{started, reason: "cancelling" | "in_flight"}`，
  调用方**读原因**并把该说的那句话说出来（`in_flight` 要 warn，`cancelling` 保持安静）。

⇒ **一个返回 boolean 的守卫，测试只能断「挡没挡住」；一个返回原因的守卫，测试能断「被什么挡住」。**
P-B 之后重新跑，`timer.test` 里两条（含一条专测「两个条件同时成立时先报哪个」）红，
而装配层不再有一道重复的门可以去拆。

⚠ 诚实的另一面：装配层「关机后不派新备份」这件事现在**仍然没有一条能打红的用例**
（`ticker.stop()` 先挡住了，那是第三重保险）。
本篇**没有**为了凑红而把 ticker 的 stop 挪到后面去。那一格的真实状态是：
**由三重保险共同成立，而其中只有两重（`start()` 那道门、settle 的顺序）分别有能打红的用例。**

## 6. 与「更严」的距离：本篇**没有**做的三件事

1. **没有把 `restoreDrill` 挪出事件循环。** 它在 `maintenance.ts` 那条 CLI 路径上，
   那条路径**本来就只有一件事在跑**，没有别的东西被它冻住。
   ⚠ 但 `heartbeat/maintenance` 如果被谁挂上常驻进程（0025 §7 第 5 条那格），
   这条结论立刻不成立 —— 那时要挪的是整个 `runMaintenance`，不是再单点补一个 worker。
2. **没有让备份并发化**（同时备两份）。恰恰相反，本篇**禁止**它（`inFlight`）。
3. **没有做 worker 复用/常驻**。每次 `new Worker` 付约 95ms 冷启动。
   常驻线程能把这笔开销省掉，代价是一个需要管生命周期的资源（它会让 §3 那个
   「关机时在飞的备份」多一层：线程本身也要能被关掉），
   而每日一次的频率上不划算。**这一格是判断不是测量**（没有测过常驻版省多少）。

## 7. 别当成做到了

- ⚠ **worker 里那次备份用的是 worker 自己的连接**，它**不与 `WriteQueue` 共享任何连接**。
  这与 integrity worker 同理（物理上抢不到那个单写者），而**WAL 只保证它读到一个一致快照**，
  不保证「备份里包含到最新一次写入」—— `eventsInBackup` 与 `eventsInSourceNow` 本来就会不等，
  那在同步版也一样。**本篇没有改变这一点，也没有修它**（它不是缺陷，是备份语义）。
- ⚠ ~~`now` 不可注入~~ **这一条被我撤了**（原来是这么写的，留着）。
  注入改走 `nowMs`（一个 number），见 §4.1。仍然在的是那条**收窄**：
  一次异步备份只有一个时刻，拿不到「备份中途的 now」。
- ⚠ ~~`onWarning` 不可用，失败只能从 `reason` / `message` 拿~~ **也写错了**（同样留着）。
  worker 里的告警是**攒成数组原样带回**的（`warnings`），
  而「只能从 reason 拿」那一版会把【成功而清理失败】那一种报成失败 —— 详见 §7.1。
- ⚠ ⭐ **一条可观察的顺序变了**：同步版里「文件落盘」与「这一轮备份结束」是**同一时刻**；
  异步版里文件由 worker 写，而主线程要等一条消息才知道它结束。
  ⇒ 「目录里能看见文件」**不再等价于**「备份这件事在主线程看来结束了」，方向只有一个：
  有那句 `备份完成` 日志 ⇒ 一定有文件；反之暂时不成立。
  这不是缺陷（备份已经落地，日志晚一拍无害），但它**已经红过一条用例**：
  `第二天 ⇒ 该再多一份` 原来写的是「先等到文件、再推进时钟」，
  而那现在等于「在上一份还挂着的时候推进」⇒ 第二次派发被 `in_flight` 拒 ⇒ 间歇性红。
  修法是把等待条件换成那句日志（不是把超时调大 —— 我第一反应正是调大超时，方向是错的）。
  ⇒ **给一个从同步改成异步的东西写测试，要重新问一遍「好了」的信号是什么。**
- ⚠ **`run` / `failure` 两种形状各自还分 ok / 不 ok，加起来五种结论各有各的文案**，
  其中 reject 那一支**不经过** `settle()`（watch 会吞掉它，好让清理路径不中断）。
  所以「谁负责说这句话」在派发处那个 `catch` 里 —— 只读 `timer.ts` 会得出「失败被吞了」。
  这一格我第一版**真的**差点据此给 `settle()` 加一个 `onRejected` 参数。
- ⚠ **worker 超时那发用 `timeoutMs: 0` 造**（抄 integrity 的写法）。
  它证明的是「超时会被判失败而不是判通过」，**不是**「真卡住的备份会在 N ms 被打断」——
  后者需要一个真会卡的备份，本机造不出来。
  ⚠ 而且超时那一支**收不回 worker 攒的告警**（它没来得及回话），`warnings` 只能是空数组，
  而**空数组不等于「worker 里没有告警」** —— 这一句区别在实现和用例里都写了。
- ⚠ **`worker_unavailable` 那一支没有用例**（入口恒存在，本机造不出「入口丢了」；
  integrity.test ① 撞过同一格，那里也只测到「库路径不存在」那一半）。
  同理 `exit` 那第四条通道今天**没有任何路径能走到**，它写在那儿是为了让
  「一定给答复」这条契约在形状上完整 —— 别把它当成「已经测过 worker 会死」。
- ⚠ **本篇没测真 vitest 下的行为**（vitest 本机装不上）；`pnpm verify` 仍跑不起来，
  那些绿是 node:test + 自制 harness 给的，**不是门禁过了**。
- ⚠ **§0 那三个数是单次读数**，不是多遍统计。§8.0 复算了一遍：同步那一发 85–93ms、
  裸 worker 冷启动 67–90ms（**抖一倍量级**，所以「约 95ms」是个上沿估计），
  而 **gap 最大 = 7ms 那一列四遍完全相同** —— 结论只站在后者上。
  ⚠ 同一节还记了「第一版探针把要量的那个样本当噪声丢掉了」那一发假读数。
- ⚠ **并发跑全量仍然不是被支持的用法**（`contracts/dist` 仍共享，0035 §7 第四条一字未动）。

### 7.1 本篇写错过、并且在代码里改回来的两处「看起来更安全」

| 我写的 | 为什么是错的 | 改回来之后 |
| --- | --- | --- |
| worker 里 `onWarning` 直接 `throw`，理由是「createBackup 每条告警之后都紧跟一条 `ok:false`，消息不会丢」 | **那句前提是假的**：`pruneBackups` 失败那一条告警之后返回的是 **`ok:true`**（那份备份确实可用）。于是这一版把一份【已经成功】的备份**报成失败** ⇒ 调用方再备一次 ⇒ 目录越堆越厚，而那正是保留策略要防的事 | 告警**攒成数组带回**，结论照原样；配一条用例断「`ok:true` 且 `warnings` 有一条」（M 系列之外最贵的一条） |
| worker 内部抛错时回 `reason: "verify_failed"` / `"source_missing"`，理由是「总得给调用方一个 reason」 | 那两个枚举值有**既有语义**（产物校验没过 / 源库文件不存在）。拿它们表示「worker 忘了收参数」是**不对症的报错**（0032 §0 那条：照它改完照旧触发）—— 读的人会去查一份并不存在的产物 | 「抛」这一支**不带 reason**，只带原文，并且走 **reject**（与同步版「keep 非法 ⇒ 抛」只差一个通道）；「装配/环境」层的失效另立 `BACKUP_WORKER_FAILURES` 三个值，**不混进** `BACKUP_FAILURE_REASONS` |

两处的共同点：都是**「压成一个已有的枚举值」比「新增一条通道」省事**，
而省的那一步正好是把诊断信息丢掉的那一步。
