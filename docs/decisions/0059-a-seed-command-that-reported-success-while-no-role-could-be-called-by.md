- 状态：已接受
- 关联：0058 §8（岗位书接进运行时但没通电）、0020（「这个字段没人读」能说到多强）、
  0008 §7（验收标准的语义属 CEO，实现层不代笔）、0057 §6（删掉而全绿的断言是装饰物）、
  0006 §7（两份抄本）、0056 §1（恒不可能通过的验收命令）
- 范围：O2 的动作 2 / 3 / 4 —— 播种命令本身、它撞开的两处文档口径、以及它**没有**解决的那件事。

> 或者加一条**显式的**迁移命令」。我加了命令，它退了 1，测试全绿，九发变异全杀。

> 还隔着两张别的表。那句话我读了三遍都没看出来。

## 2. 落地的东西

新增 `packages/hub/src/charter/seed.ts`（`pnpm hub:charter seed --db <path> [--from <dir>]`），
刻意**不 import** `cli.ts`：那个文件顶层 `import { Command } from "@langchain/langgraph"`，
而本机装不上 langchain —— 挂在 `cli.ts` 上的命令在这台机器上**根本跑不起来**，
它的测试也就从没跑过（这是本仓第五次撞上「langchain-free 入口」这件事，
第一次是因为装不上，这一次是**不需要**它）。

三条**并列**的拒，全部做进类型里（`SeedPlan` 是判别式：有问题时调用方**拿不到** `actions`）：

| 判据 | 拒什么 | 为什么必须是它自己一条 |
| --- | --- | --- |
| A 占位串未签 | 验收标准里还有 `CEO-PLACEHOLDER-ACCEPTANCE`（`condition` 与 `message` **两侧都查**） | 文档只要求了这一条（动作 3） |
| B 与库里最新一版逐字不同 | 覆盖人在编辑器里改过的内容 | 播种只能给出一句模板化的 `changeSummary`，而它是回放里唯一人可读的那句「为什么改」 |
| C 文件名 ≠ `role_id` | 身份不一致的模板 | `validateCharterDraft` 里那条同名的检查在播种路径上**恒真**（它比的两个值出自同一份文件），挡不住这件事 |

**任一角色不合格 ⇒ 一个都不写**。半套岗位书比没有岗位书难查：七个角色进了四个，
另外三个下一轮走 `NO_CHARTER_LINE`，而屏幕上那四个看起来一切正常。

副作用也说出来了：播种走 `saveCharterVersion` 的默认 `applyBudgets: true`，
⇒ 模板里 `budget` 那两格**同时**开始限流（实测 2 份岗位书 ⇒ 4 行 `budgets`）。
这条文档没提。它必须看得见，所以第一次写入前在 stdout 打一行，
指向审计的 `limits_applied` / `alarm_silenced`（调低上限会让那一格的突破警报永久哑掉）。

## 3. 本篇的正题：那句「播种完成」在说什么，以及它没说什么

### 3.1 链条上有五站，命令只负责第一站

```
resources/charter-templates/dev.yaml
  → ① 播种命令读它、校验、按 role_id 写进 role_charters        ← 本命令做到这里
  → ② rolePrompt(roleId) 按 roleId 去 role_charters 读最新版
  → ③ 这个 roleId 从哪来？tasks.assigned_role
  → ④ 任务能带着这个角色跑吗？门 0：graph.nodes[task.role] 不存在 ⇒ 不跑
  → ⑤ 组织图上的节点名，是【另一套命名】
```

②那一站是上一轮（0058）接上的。③④⑤ 这三站**一直在那里**，而它们决定：
**「表里有这一行」与「有人读得到这一行」中间隔着两张别的表。**

实测的两套命名（`roles/preset.ts:27`）：

| 组织图 / 图节点 | 挂的模板 | 相等？ |
| --- | --- | --- |
| `intake` | `assistant` | ✗ |
| `charter` | `assistant` | ✗ |
| `report` | `ceo` | ✗ |
| `product` / `tech` / `dev` / `test` | 同名 | ✓ |

而 `tasks.assigned_role` 的**建卡初值**是 `intakeRole`，它的缺省值是 `"intake"`
（`http/real-deps.ts:856`，公开装配 `serve/assemble.ts` 不传它）。
⇒ **一条新任务默认落在 `intake` 这个名字上，而 `intake.yaml` 这个模板不存在**：
七份模板播完，第一个要干活的角色仍然读 `NO_CHARTER_LINE`。

这不是"少了一个模板"那种能顺手补的缺口。`intake` 与 `assistant` 不相等这件事
是 §10.2 D11 那条**尚未拍板**的命名约定的下游 —— 规格附录 B 用语义名
（`test_engineer` / `tech_director`），仓里用文件名短名。**拍板之前任何一方都不该被改**，
所以我没有改命名，我让这条命令**把这道缝说出来**。

### 3.2 为什么是警告而不是第四条拒

判据 A/B/C 拒的都是「**这次写本身不该写**」。这里写进去的岗位书内容是对的，
缺的是另一张表上的一个名字，而那张表**按 O8 的路线本来就可以晚于播种存在**
（新库先播种、`POST /org` 后建图）。把「图还没建」判成拒 ⇒ 全新库永远播不进岗位书，
正好把 O8 要的那条路堵死。

所以它**只说**，而且说在 stdout（不是 stderr）：一次成功的播种不该因为
"另一张表还没配"就让脚本作者看到 stderr。这条分界有发测试钉着（`c.err()` 必须逐字为空）。

三格输出，**判不了也要说一句「判不了」**：

- 库里没有任何一版图 ⇒ 「没有判可达性 + 建图走 `POST /org`」。沉默是最坏的读数，
  因为它与"全都可达"长得一模一样。
- 图上有 ⇒ 「✓ 可达性：… 在组织图 v7 上」。版本号上屏，因为任务跑的是**创建时那一版**（§18.4），
  判最新版是**刻意的偏差**，方向写在输出里。
- 图上没有 ⇒ 点名角色，并给出**两条出路**（改组织图 / 让模板文件名等于节点名）。
  只说"不可达"而不说怎么对上，等于把人扔在一个他改不动的事实前面。

### 3.3 这一格能被证明有判别力吗

六发变异，全部由真实失败的红发杀掉（红发数 1/1/2/1/2/1）：

| 变异 | 结果 |
| --- | --- |
| `missing` 恒空（不可达也报可达） | KILLED |
| 没图当成"全都可达"（沉默 → 假绿） | KILLED |
| 那句警告改打 stderr | KILLED |
| 去掉 `.sort()` | **第一次存活** |
| 整个判据不查图 | KILLED |
| 不可达时不给那两条出路 | KILLED |

第四条**一开始活着**，而这正是 0057 §6 那个判据的又一个现场：我传的是
`["dev", "ops"]` —— 输入**本来就带序**，所以输出那行 `.sort()` 删掉也给出同样的数组，
那一行排序是绿色测试里的**装饰物**。修法不是"再补一行断言"，是**让输入不带序**
（改传 `["ops", "dev"]`，并把顺序同时钉在**那句话**上而不只钉在数组上：
数组相等可能靠巧合同序）。改完 KILLED。

## 4. O2-4 那条「要么进装载表，要么删掉」是假两难

原文：「`ops.yaml` 要么进装载表，要么删掉。**留着它最坏** —— 它读起来像「运营角色已经存在」」。

两个选项都不成立：

1. **「进装载表」没有那个位置。** 那张表（`NODE_TO_TEMPLATE`）的键是 `CompanyNode`，
   一个编译期闭合的**图阶段**联合（`intake`/`charter`/`product`/`tech`/`dev`/`test`/`report`）。
   把 `ops` 塞进去只能挂在某个阶段上，而那是让**那个阶段的活儿**拿运营的岗位书干活 ——
   凭空造一次组织变更，而组织变更不该由实现层代笔（0008 §7）。
2. **「没有任何代码路径装载它」已被本轮自己推翻。** 播种命令 glob 整个目录，
   `ops.yaml` 现在有一条真的入口 —— 签字之后它就能进库。

**决定：留下**，并把「它今天到底算什么」变成**算出来的**：
`roles/charter.test.ts` 新增一发，孤儿集合由 `NODE_TO_TEMPLATE` 反推、
文件清单复用播种命令自己的 `templateFiles()`（不是再抄一份 glob 正则 —— 那会是第二个源），
断言 `orphans` **集合相等**于 `["ops"]`。加一份新模板而不装配 ⇒ 这一发点名它。

判别力实测：把 `report: "ceo"` 改成 `report: "ops"` ⇒ 这一发红，
报错是 `expected [ 'ceo' ] to deeply equal [ 'ops' ]`（**新孤儿是 `ceo`**，
正是"装配表挪走了一个名字"该说的话），恢复后逐字节回到基线。

而「留着它最坏」这半句**现在不成立**了：判据 A 让没签字的模板进不了库，
所以它读起来是「有一份没签的运营岗位书」—— 这句话是真的。
一条读得出真假的主张被换成另一条读得出真假的主张，这就是全部收益，没有更多。

## 5. 我第二次犯同一个坐标错，而且错法比第一次更没道理

上一轮 0058 我写下：「**同一轮里凡是改过某个文件，引用它的坐标要等这个文件停手之后再数**」，
`doc-refs` 那次抓到的正是我按"改动前的行号"写文档。这一轮我改 `store.test.ts` §④ 时：

```
快照 [return m ? { f, names: (m[1] ?? "")... } : null;]
现在是 [* 另一半：只读的那几个预算查询函数【允许】被 charter/ 外面用，]
```

我**推**了一个数（上次 663，这次我在它上面插了 12 行 ⇒ 675），推的过程没错，
错在**我还在往那个文件加行的时候就写了文档**。改完文档、登记快照、跑守卫才绿。

这一条我上一轮已经写进 `doc-refs.test.ts` 的注释，而它**没有挡住我**——
所以教训不是"写下来"，是**这条纪律的执行者是测试而不是我**：只要动了被引用的文件，
**同一轮内**跑 `doc-refs`，不要留给"最后一起跑全量"。快照这个形状在这里仍然值回成本：
**key 存行号、value 存那一行的内容**，所以"看着像"的行号一个都混不过去（这一发就是证据）。

## 6. 别当成做到了

- **`role_charters` 今天仍然是 0 行。** 七份模板全带占位串 ⇒ 判据 A 当场拒、退出 1、零写入。
  本篇**没有**让任何一份岗位书进过库，也**没有**让 `rolePrompt` 多渲染一个字。
  O2 的验收 (b) 达成，O2 的目标（「一份真的岗位书，当场进提示词」）**没达成**，
  缺的那一环的执行者是**人**（CEO 逐条替换验收标准），不是代码。
- **那句可达性警告今天一次都不会打。** 它在成功路径上，而成功今天不可达。
  §3.3 那六发变异测的是**判据**，不是「这句警告已经在生产里出现过」。
- **可达性判的是最新版图**，不是任务创建时那一版（§18.4）。方向写在输出里，
  但"老图有这个名字、新图把它删了"这一格**不在射程内** —— 那该由组织提交那一侧拦。
- **两套命名我没改。** 那是 §10.2 D11 一条**未拍板**的约定，拍板前改任何一方都是
  拿实现层的手替 CEO 做组织决定。本篇动的只是"这道缝会不会被说出来"。
- **`ops.yaml` 的处置依赖判据 A 还在。** 哪天有人把占位串判据放宽，
  「它读起来是有一份没签的运营岗位书」这句立刻变成假的，而 `roles/charter.test.ts`
  那发孤儿守卫**不会红**（它只判集合，不判签没签）。
