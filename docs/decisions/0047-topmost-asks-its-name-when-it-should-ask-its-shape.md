# 0047 顶层是谁，问的是【名字】而该问的是【形状】 —— 于是 hub 起了个子进程去扮演 CEO 本人

## 0. 一句话

「这格是谁的上级」「这个组织有没有顶」这两件事，在图里都是【结构事实】
（`reports_to` 那一列读出来就完），而代码问的却是【名字】：
`up === o.ceoRoleId` 那一句字面量比较，把「已到顶层」这个判断降级成了
「根那一个节点的角色名是不是恰好叫 ceo」。

两发探针，同一颗根（原话抄在 dispatch.ts 的门 0.5 / 门 0.6 注释里）：

```
探针 A（根叫 boss）:
  IN_REVIEW/director + pass ⇒ IN_PROGRESS/boss → IN_PROGRESS/boss（没动）
  spawn 次数 = 2
  note = boss 在组织图上没有上级，产出无处可交

探针 B（ceo ← manager ← lead ← dev，任务停在 manager/IN_PROGRESS）:
  轮1: IN_REVIEW/ceo  moved=true      ← manager 的 pass 把任务交给了 CEO 那一格
  轮2: ⚠ 起了一个子进程，身份 = "你在一人公司里担任角色 [ceo]。CEO（角色 ceo）
         是唯一的决策者…"           ← hub 扮演 CEO 把审阅做完了
  被叫去干活的 = ["manager","ceo"]
  审计里 actor_type='agent' AND actor_id='ceo' 的行数 = 1
```

两发不是边缘形状：汇报深度上限 5（`ORG_MAX_DEPTH`），所以【任何比 ceo←dev 更深】
的组织图第一次 pass 上去都会踩 B，而一人公司画到第三层就中招。

## 1. 修的是什么，不是修什么

修的是【判定】与【谁被叫去干活】：

| 形状 | 修前 | 修后 |
| --- | --- | --- |
| 根叫 boss（A） | `topmost` 判据恒假 ⇒ 任务停在 agent 席位、每轮白烧、收件箱空 | `resolveCeoRoleId` 从图里读出根 ⇒ 顶层照样判得出 |
| 上级是 CEO 本人（B） | 下一轮起子进程【扮演 CEO】，往 append-only 审计写 `agent/ceo` | `thenEscalateToCeo` 标志 + 第三格：直接升 `ESCALATED_TO_CEO`（人席 + 卡片），CEO 那一轮**不起** |
| 任务【一开始】就建在 CEO 角色上 | 每轮都起一次子进程「自己批自己」，note 里还写着"产出交上去" | 门 0.6：`runTurn` 之前 `stop()`，不烧 token、不写审计 |
| 图没有根（成环 / 空图） | 每轮白烧，note 是「没有上级」这种与成因无关的话 | 门 0.5：`runTurn` 之前 `stop()`，报错里列得出修法 |
| 装配指定的 `--ceo` 在这版图上不存在 | 静采用一个无效名字，症状与 A 逐字相同 | 门 0.5 拒绝：「优先而须有效」，报错里把图里的根列出来 |

**不修**的（写在这里而不是装没看见）：

- 状态机本身一字未动。三格链条
  `IN_PROGRESS → EVIDENCE_SUBMITTED → IN_REVIEW → ESCALATED_TO_CEO`
  里的**每一条边都是【规格】§7.1 已有的**（769→770 / 770→771 / 774）——
  本篇改的是「这三条边现在被**走通**」，不是「加了一条新边」。
- `assigned_role` 保持产出方（`manager`），**不写 ceo**：
  `approveCard` 那一支会原值回填负责角色，写 ceo 等于把一次「升给 CEO 看」
  变成一次**组织分配**，下一格（FINAL_REVIEW 之后）的负责角色也跟着错。
- 门的位置在 `runTurn` **之前**（探针 B 的量法就是数 spawn 次数：
  判在之后 = 判据正确而**代价照付**，那一轮是真的起了子进程烧了 token 才拦下的）。
- `runtime.ts` 那条 `?? "ceo"` 改成从【任务那一版】的图里读
  （`cacheGraph`，不新开一个版本来源）；判不出时简报里写「说不出」，
  **不退回任何名字** —— 编一个名字出去，agent 会照着对着一个不存在的同事汇报。

## 2. ⭐ 两发缺陷是同一颗根，写在两半上

「顶层是谁」这件事被代码问了**两次**，两次都问的是名字：

1. `planEdge` 的 `topmost` 那一支：`upstreamOf(graph, o.role) === o.ceoRoleId`，
   而 `o.ceoRoleId` 的默认值一路是字面量 `"ceo"`（`makeDispatch` 里那格被删掉的
   `?? "ceo"`）。
2. `runtime.ts` 的简报：`rolePrompt` 里那句「CEO（角色 " + ceo + "）是唯一的决策者」，
   `ceo` 也是同一个回退。

两处各修一半只会得到一个「判定对了但简报里还写着 ceo」的形状 —— 而那种形状
**每一层都绿**。所以 `resolveCeoRoleId` 只写在 dispatch 一份，runtime 那边是
它的**读者**而不是第二个实现。

为什么【不回退】到 "ceo" 那个字面量：回退分支正是探针 A 的成因。
补一条「读不出根就用 ceo」等于把同一颗雷重新埋回去，而埋的地方比原来更深一层
（原来只在"名字不匹配"时炸，现在在"图形状意外"时炸）。
判不出就明说 —— 与本仓对「append-only 审计里不写猜的东西」是同一条纪律。

`Object.hasOwn` 而不是 `nodes[name] !== undefined`：`nodes` 是普通对象，
`"constructor"` / `"toString"` 这类**原型键**会命中而它根本不是角色。
同一个坑在 `graph/status.ts` 的 `assertKnown` 里记过一次并那样修的。

## 3. 为什么落「等顶层裁决」那一格而不是停着：那条边不需要造

我第一版写的是 `stop()`（不写边、给一句人话）。跑探针之后发现**不够**：
`IN_REVIEW` **不在 `HUMAN_EDGES` 里** ⇒ `needsSeatCard` 判 false ⇒
收件箱**一张卡都没有**。那等于用「不花钱、不造假」换来了「任务停在一个
既没有 agent 会动、也没有人类入口的格子里」—— 正是 0046 在修的那个症状的
**第三种皮**，我不能一边修 0046 一边造出新的 0046。

而落 `ESCALATED_TO_CEO` 不需要造任何边（§1 那张表），语义也说得出口：
「这件事需要 CEO 拍板」—— 它**没有**说「审阅通过了」（那才是 `ESCALATED`
说不出口的话，也是为什么不落 `APPROVED_UPWARD` / `FINAL_REVIEW`：
那两个会把「没人审过」包装成「审过了」）。

## 4. 第三格的起点取自【链尾】而不是写死 `"IN_REVIEW"`

```ts
if (plan.move && plan.thenEscalateToCeo === true) {
  const prev = chain[chain.length - 1];
  ...
  chain.push({ to: assertTaskTransition(prev.to, "ESCALATED_TO_CEO"), ... });
}
```

写死 `assertTaskTransition("IN_REVIEW", "ESCALATED_TO_CEO")` 的那版
**在今天的边表上照样通过** —— 校验的是我脑子里那条边，写下去的是另一条。
这是 0046 §9 那条 M3（验位置而不验性质）的**同一类错**：一旦将来给别的状态
也加了自动边，写死那版会写出一条 `某状态 → ESCALATED_TO_CEO` 的假边，
而那个 `assertTaskTransition` 还照过不误。从链尾推 ⇒ 校验的边与写的边**必然是同一条**。

变异那一段（§8 G8）把写死版跑了：**全绿** —— 即写死版在今天的边表下是
**不可观测**的，它防的是将来的形状。留着它当「无效变异」的证据，理由同 0046 M3。

## 5. 那行假审计为什么比钱更坏

钱坏得**看得见**（账单会涨），而 `actor_type='agent', actor_id='ceo'` 那一行
坏得**像成功**：回放查得到那一步、审计数得齐、而它说「CEO 跑了一轮」——
**而 CEO 本人从未被叫去跑过任何一轮**。`events` 是 append-only（§20.4），
写下去删不掉。且【规格】§7.2 步骤 8 那一格（琥珀卡、CEO 裁决）
被**它自己要回答的那个问题抢先答了一遍**，而界面与审计都不会说这件事发生过。

⚠ **探针 B 的措辞要写准**（我第一版写成「那一轮白烧而到不了人席」，**那是错的**，
写完代码回头看才发现）：那一轮烧完**确实**把状态推到了 `ESCALATED_TO_CEO`，
落点是对的。真正的代价是**多烧一轮真钱 + 留下一行假审计，才走到一个
上一轮结束时就能免费走到的落点**。写错这一句的后果不是文笔问题：
它会让人以为修法要改的是【落点】，而落点一直没错 —— 要改的是【谁去走那一步】。
探针 A 与「图没有根」那两发**才是真的到不了人席**，所以 §1 那张表里
只有那两行写着「白烧」。

## 7. 等 CEO 拍的一项：`BUDGET_PAUSED` 那一格要不要「免一轮钱」地走过去

⚠ **本节改写过一次，因为我第一版把前提写错了，而错的经过是查过的**。
原文写的是「驱动器若把 `BUDGET_PAUSED` 算进候选，它做的每一轮都是**替 CEO 决定
追加多少钱**」。**那不是代价，那是不存在的东西**：

- 我那句话是从 `AGENT_EDGES.BUDGET_PAUSED.blocked` 的 `why` 字符串
  （「预算暂停需 CEO 决定追加/终止」）读出来的 —— **读了一句注释而没查这一格谁写**。
- 查了：`grep -rn "BUDGET_PAUSED" packages/*/src/` 的 22 处命中里，
  **没有任何一处把它写进 `tasks.status`**（`to: "BUDGET_PAUSED"` 零处，
  `SET status` 零处）—— 0041 §7 量到的正是这件事（「跨限不暂停、不建卡」）。
- 也查了那一格的出边：唯一的 agent 出边是 `blocked → ESCALATED_TO_CEO`。
  所以驱动器真跑到那一格，做的是**花一轮钱把这件事升到 CEO 面前**，
  与「替她续预算」**方向相反**。

于是待决的那一格比我原来写的小而更具体，两件事分开：

1. **「`BUDGET_PAUSED` 今天没有任何写入方」不是待决，是已登记的缺陷**（0041 §7），
   本篇不重复登记。它意味着下面这一问今天是**空转**的：库里没有任何任务能在那一格。
2. **真正待决的是：`blocked` 那条边要不要免一轮钱地走。** 那一格只有一个出口，
   形态与 `EVIDENCE_SUBMITTED → IN_REVIEW` 那条 hub 自动走的边**像**，
   而有一条实质区别：自动那条**不需要任何人表态**（【规格】§7.1 从它出发只有一个出口、
   没有 action），而 `blocked` 是**一个角色说的话**。hub 替它说，
   就是 0047 §1~§3 刚消灭的那件事的另一个身份 —— **hub 替一个角色宣布了一个决定**，
   只不过这次替的不是 CEO。

两个候选与代价：

- **(A) 花钱让角色自己说 `blocked`**（**我的倾向，也是驱动器的实现取这个的理由**）：
  审计里那一行写着「某个角色说这件事必须 CEO 拍板」，**而它确实说了**；
  代价是一轮真钱（有上限：驱动器的按格尝试预算挡着，不会每轮烧）。
- **(B) hub 免钱直接走那条边**：代价是审计里多一行「某角色要求 CEO 裁决」
  而那个角色**从没被叫起来说过这句话** —— 与本篇 §5 那行 `agent/ceo`
  是同一种假记录，只是便宜一些。

驱动器按 (A) 落地，所以它**不会**在这一格免钱；也因为它有按格预算，
这一格最多试 `maxAttempts` 轮然后停下来**说话**（不静默）。
真待决的只剩「这轮钱该不该省」，而那归你，因为 (B) 的代价是往 append-only 的
审计里写一句没人说过的话。

（另一条与本篇相邻而**不是**本篇修掉的：`MEETING_REQUIRED` / `BLOCKED`
在两张边表里都没有出边，是【规格】§7.1 的死路。驱动器按「agent 出边非空」派生候选，
所以那两格**结构性地进不了候选** —— 不是被名单排除，而是它们没有可走的路。
补它们要【规格】先给出边，0046 §6 第 4 条同一条。
⚠ 这三格「今天有没有任务停着」我**逐条量过而不是推的**（第一版只量了一格就把结论
