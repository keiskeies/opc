## 0. 复算：一份配了一半的岗位书会发生什么

探针（离线，`node --experimental-transform-types`，全文在 `/tmp/probe-pair.ts`，
按下面这三行就能复算）：一份 YAML 写了

```yaml
acceptance_criteria:
  - condition: "metric:coverage < 90"      # 只有一条 metric，没有搜索那条
    action: reject
search_policy:
  tier_1_mandatory: ["security_advisories"] # CEO 声明了一个强制领域
```

按 0033 的接线口径把两半各读一遍，实到：

```
加载:                通过（没人拦）
charterMandatoryDomains ⇒ ["security_advisories"]     ← 领域读得到
criteria 里有那条吗:  false
门控标准 "metric:coverage < 90" → {"status":"unresolved","why":"证据包没有声明指标 [coverage]…"}
```

**最后一行是本篇的全部**：按 `criteriaFromCharter` 的口径展开出的门控标准**只有一条 metric**，
而 `makeSearchCriteriaEvaluator` 是**精确匹配** condition 才判（那是 0033 §6 我自己写的口径），
其余原样交回 fallback ⇒ **那条搜索判据一次也没被叫到**。
所以这份「看起来配好了第 1 层」的岗位书的真实行为是：**一个领域都不判，而且全绿**
（那条 metric 判不判得出来与搜索无关，它甚至自己会 escalate，把注意力带走）。

缺口为什么在本篇之前不存在：**判定侧是 0033 才有的**。
在那之前 `tier_1_mandatory` 连读的人都没有，「配了一半」这个说法不成立；
本篇把判定侧接上之后，这句话第一次有意义，而它同时第一次**可以是假的**。
⇒ **接上一半会把「另一半没接」从一种缺失变成一种伪装**：
之前没人会以为它生效了，现在有人以为。这一格是本仓「N 条用例、零生产调用方」那一族的
**新形状**（那族说的是「有人写没人调」，这里是「有人调、但没人让它被调到」）。

**0033 §7 那句「落错会响」按口径留在原文里，就地加了一条更正括号**，没删。

## 1. 为什么这条判据落在 schema，而不是落在门控

三个可选位置，其中两个我第一反应想过，都不该选：

| 位置 | 判什么 | 为什么不选 |
| --- | --- | --- |
| **加载期（选了）** | 同一份 YAML 的两格成对 | 两半天然**同一主体**，判据不需要回答「这是谁的」 |
| 门控（`verifyFix`） | `verifierCharter` 的领域 vs `criteria` | ⚠ **这就是 0033 §3 那一发的同形复发** |
| 装配期（`serve/assemble.ts`） | 加载完逐份核 | 今天没有生产装配读岗位书（`loadPresetRoles` 只有 `cli.ts` 一个 src 调用点），写了就是**有码而无返回点** |

中间那一格值得写细一点，因为它**看起来最合理**：门控同时拿到 `verifierCharter` 和 `criteria`，
在那儿判「有领域而没那条标准」似乎成本最低。而它错在**那两样东西不是同一份文档的两半** ——
`criteria` 是调用方传的（生产口径*应该*是 `criteriaFromCharter(charter)`，
但没有任何类型或判据强制它来自同一份岗位书），而 `verifierCharter` 是**审阅方**那份。
拿 A 的主体去配 B 的标准，正是 0033 §3 那条被判后删掉的核对的同一个结构；
**上一篇刚记过一次的错，这一篇换个字段就又来了** —— 我这次是在**写之前**发现的，
所以它没有变成一次红、一次回滚，只变成这一张表里的一行。
⇒ 判据要落在**两半必然同源**的地方；「哪里都能拿到这两个值」不是选位置的理由，
「哪里能保证它们是同一份」才是。

**方向是拒，不是代填。** 另一条实现路径是「发现领域非空就自动追加那条 `reject` 标准」，
它省事而**不能做**：`acceptance_criteria` 是 CEO 签的字
（本仓明文规矩：不代写验收标准、不写 `signed_by: ceo`），
自动追加会让一条他从未写过的 **reject** 出现在他的岗位书里，而 reject 是打回产出的那一档。
有一条测试钉住「没代填」（`charter.test.ts` 里那条 ⭐，断言 `acceptanceCriteria` 长度还是 2）。
报错的 `path` 指 `acceptance_criteria`（**缺东西那一侧**）而不是 `search_policy`：
指后者会让人去删那一格，那是把「配错」改成「没配」，**代价方向反的**。

**只判单向。** 反方向（有那条标准而没声明领域）**合法** —— 判定侧对它已经按 `satisfied` 处理
（0033 §4 那张四格表里的第二行）。双向判据等于用加载期去表达「这条标准这次不成立」，
而那一格的答案本来就该由判定侧给；后果是把一个合法写法变成加载失败。
配一条反向对照钉住它，否则「领域非空才判」那一支可能被写成恒判。

**顺带修的那处定义漂**：那串 `"search:mandatory_sources"` 在
`hub/src/search/policy.ts` 里是**字面量**，而本篇之前它只有一个读者（判定侧），复制不成问题；
本篇让**写入侧**（同一份 schema 的 `superRefine`）也成了读者 ⇒ 两个读者。
定义挪进 `@opc/contracts`，hub 那份改成 `export const MANDATORY_SOURCES_CONDITION =
SEARCH_MANDATORY_SOURCES_CONDITION`（**别名**，保留旧名字给既有 import 与测试）。
漂的后果不是编译不过，是「岗位书写了一条而判定方不认」——
**恰好就是那条精确匹配判据想防的东西本身**，而它不会红。
测试夹具（`charter.test.ts` / `verifier.test.ts` 那两处）也改成读常量而不手抄那串：
**夹具手抄一份常量，是本仓记过多次的「夹具与判据各读一本书」的形状。**

## 2. 判据形状上值得抄的一处

**「一条判据要落在哪一层」和「一条判据该多严」是两个问题，而第二个总是更容易想到。**
本篇那条判据的严宽怎么调（单向 / 双向、空数组算不算、trim 不 trim）都不改变它能防什么；
它落在 schema 还是门控，才决定它是**能成立**还是**会拒掉正确答案**。
0033 §3 是同一课的「写完之后被测试之外的事实推翻」，本篇是「写之前先问同一句」——
**同一条纪律，两次成本差一个数量级**，而差别只来自问的时机。

三条边界各挡一种坏法，各配一发测试：
空数组不触发（声明过而零领域 ⇒ 本来没东西要判）；
`trim()` 后精确匹配（判定侧也是 trim 后精确匹配 ⇒ 两侧同一口径，否则一个带空格的写法会「加载期说配上、判定期不认」）；
不代填（上面写了）。

## 3. 别当成做到了

- ⚠ **成对判据保证的是「岗位书内部自洽」，不是「门控真的判了」**。
  它管不到调用方**不用** `criteriaFromCharter` 的那一支：装配代码完全可以传一份
  与岗位书无关的 `criteria`（`VerifyInput.criteria` 是必填、由调用方给），
  那时领域声明了、标准也写了、门控里却没有那一条。
  堵它需要把 `criteria` 改成从岗位书派生（删掉那个入参），而那是**另一篇的接口变更**，
  且会牵动 `phase3.test.ts` 那组「改验收标准 ⇒ 门控结果变化」的用例形状。
- ⚠ **本篇没有让第 1 层在生产里跑起来**（0033 §7 那两条「仍零生产调用方」一字未变）：
  `verifyFix` 与 `searchPolicy` 仍零生产调用方 ⇒ 这条成对判据今天防的是
  **人写 YAML 的那一刻**（加载期与 `saveCharterVersion` 那条写侧都过 `charterSchema`），
  不是运行期。这一点比 0033 更窄，说清楚：**本篇唯一真正生效的面是加载期。**
- **七份模板仍一字未改**，所以这条新判据对现有角色零影响（全量终跑红名单与基线逐行相同，
  见 §4），而它也意味着**没有任何一份真实岗位书今天会被它拒** ——
  它防的是「下一个写 YAML 的人」。
- **判据只查那条 condition 在不在，不查它的 `action`**。
  写成 `escalate` 也过（`escalate` 在第 1 层里语义是「这条要人看」，与【规格】
  §13.3 那句「直接打回」差一档，但那是**取值**问题不是**配对**问题，
  报错也不该由 schema 代答「你想 reject」）。这一格是**留着的**，不是漏的。
- `pnpm verify` 仍跑不起来（`vitest` 解析不到）、`@biomejs/biome` 仍装不上
  ⇒ 下面那些绿是 **node:test + 自制 harness** 给的，**不是门禁过了**；排版是手工对齐的。
