# 0068　一把从没夹住过东西的卡尺 —— 以及它被修好之前先骗我的那台变异机

## 1. 一句话

0067 §9 用一句 `grep` 支撑了「配置页那一格不是我漏的」，而那句 `grep` **两处各自独立
都量不到它声称的东西**：扫描面里没有渲染侧代码，查询串在渲染侧根本不可能出现。
本篇不重述那件产品事实（结论没变：确实零调用方），本篇只记一件事——
**一条读数恒为 0 的判据，和被验对象之间可以没有任何因果关系**；
以及我为了把它变成会红的东西，先用一台【自己没跑起来】的变异机骗了自己一次。

## 2. 它是怎么被撞见的：不是去找缺口，是修 0067 §9 时顺手复算

写完 0067 后我按「后端已返回、前端没渲染」这一族找还能做的格（这一族在本仓反复推翻过
「实现层无可推进」的结论，round325/327/340 三次都是它）。要判断分发规则配置页是不是
这种格，第一件事是数界面调了哪几条端点 —— 于是我去复算了 0067 §9 自己登记的那条命令，
并在同一次复算里读到了渲染侧的传输层。命令当场变成废话，理由有两条，互相独立。

## 3. 两个洞：扫错面 + 查错串

| 洞 | 实测 | 为什么它让「0」失去意义 |
| --- | --- | --- |
| **① 扫错面** | `grep -rn "api/v1/dispatch" packages/web/src packages/desktop/src` ⇒ 0。但 `packages/web/src` 只有五份 `.ts`（`dev-server` / `dev-sign` / `hub/projection` / `humanizer` / `index`），`grep -rn fetch packages/web/src --include='*.ts'` 里能发的请求一行都没有；真控制室与七页管理视图全在 `packages/web/public/*.js`（`app.js` 189 KB、`group.js` 295 KB） | 那份目录里**任何**端点都是零命中。「0」量的是「这个抽屉里没有」，而东西在另一个抽屉。同一族的六轮先例写在主张登记表 r15：round295 那次失效原因是「扫描根只列 `web/src` 与 `desktop/src`、扩展名只筛 `.ts/.tsx`，真控制室不在它的视野里」 |
| **② 查错串** | `app.js` 的 `api()` 发的是 `fetch("/api" + path)`，调用点写 `api("POST", "/org")`；`group.js` 把前缀提成 `const API = "/api/v1"`，调用点写 `request("/groups/…")`。⇒ 拿整条 `/api/v1/…` 去扫渲染侧，实测 `packages/web/public/*.js` **0 命中**，而它**确实**在调 `/api/v1/org`（`app.js` 里那一处组织写路径的统一提交口，`api("POST", "/org")` —— 拖拽 reparent / 表单 reparent / add_node / add_edge 四条路都汇到它） | 前缀是**运行时**才拼上的，字面量里能看见的只有尾串。⇒ 这条查询对**任何**端点恒 0，**配置页明天上线它照样 0**。这是比①更阴的一半：修好目录仍然量不到 |

两个洞的形状相同：**读数恒为 0**。恒为 0 的判据不会红，也就不会随事实变化 ——
这正是本仓对「一条不可能红的判据 = 一条假绿」的定义（0007 §4.1）。
0067 那句结论**没有说错**，错的是它下面那条「证据」。

## 4. 为什么守卫不判「有没有人调」，而判「探针能不能响」

最省事的修法是把那句 grep 改对再钉进测试：`扫描面 = packages/web/public` +
`尾串 = dispatch/rules` ⇒ 期望 0。**这一版是错的**，两处：

- 它把**产品排期**钉成了一条会红的判据。配置页该不该做、放 web 还是 desktop，
  是 0067 §9 明确交给 CEO 的那一格；哪天前端排期落下来，这条判据会红着要求
  我把它删掉 —— 那种「改动是对的但守卫红了」的判据，最后的下场通常是被整个关掉。
- 它只覆盖了**今天这两个洞**。第三个洞（比如将来有人把端点挪成 `/api/v2`、
  或渲染侧换一套传输层）不会让「期望 0」变红，只会让它继续 0。

所以 `test/arch/ui-caller-probe.ts` 判的是**尺子**而不是**工件**：
同一套扫描面 + 同一个查询形状，对一条**已知有调用方**的端点（`/api/v1/org`，
组织页那条统一提交口）**必须非零命中**；控制组不过就响亮报错并附扫描面读数。
「零命中」从此只有在控制组通过的前提下才允许被引用。
外加一条把恒真探针本身抓出来的判据：查询串是空串或**纯前缀**（`/api`、`/api/v1`）时，
**即使有命中也报警** —— 那种串任何文件都命中，恒真，不能替「零命中」作证。

## 5. ⭐ 机器先骗了我一次：预检那一发抓到的「没跑起来 = 红了」

第一版变异机是 python，照 0067 §6 的教训用了 `shell=True`，跑出来：

```
[BAD] M0 控制组：加一行无关注释  :: 该绿 -> 红
[OK ] M1 … M7 七发         :: 该红 -> 红     ← 七发「被杀」
[BAD] M8 摘掉 vendor 排除      :: 该绿 -> 红
```

七发「被杀」看着像丰收。但**两发控制组同时红**这件事本身就是答案：控制组的定义是
「改了不该被任何断言吃到的东西」。手工在终端跑同一发变异 ⇒ **绿**。
往下查，`subprocess` 拿到的退出码是 1，而输出只有一行
`The system cannot find the path specified.` —— **vitest 根本没启动**。
本机 python 的 `shell=True` 走 `cmd.exe`，那条 PATH 里找不到 `npx`（连
`where npx` 都是空输出），于是**「没跑测试」被读成「测试红了」**，
每一发变异都「被杀」。改成 `node node_modules/vitest/vitest.mjs run …` 仍然一样坏，
最后用 node 自己的 `execFileSync(process.execPath, [...])` 才真跑起来。

修法两步，都不在「换个命令」这一层：

1. **预检**：未变异必须先绿，且必须读得出 vitest 的摘要（`Test Files` / `Tests`）。
   读不到摘要 ⇒ 当场以另一码中止，不进入变异循环。**这一发单独就把这台坏机器抓住了**，
   代价是零 —— 它只是把「干净树应当是绿的」这条本来就在的前提，交给机器自己确认。
2. **不认「非 0 即红」**：判绿/判红之前先断言「这份输出确实来自被测对象」。

登记：这与 0067 §10 那条（管线末尾站着一个恒成功的命令 ⇒ 上游退出码走不到我手里）
是**同一族的两个方向**——那次的错误信号被吞掉，这一次的错误信号被**凭空造出来**。
共同的那条是：**引用一个退出码之前，先证明它是被测命令产生的。**
「七发全被杀」这种漂亮的读数，恰恰是最该怀疑的读数。

## 6. 终版 9 发的落点（真抹字节 → 跑那一支 → `finally` 逐字节还原核对 sha256）

判据本体 7 发（各对应一处把尺子磨钝的改法）：摘掉空串/纯前缀那一格 ·
判据短路成永远可信（零命中也报可信）· 顺序挪动成「先看命中再看查询串」（有命中就早退，
恒真串那一格被短路）· 前缀不剥（退回本篇 §3② 那个假探针）· 扫描根退回
`packages/web/src`（§3① 那次扫错面）· 名单里摘掉 `/api` 一枚 · 报警里不再带扫描面读数。
测试侧 2 发**控制组**：加一行的无关注释、摘掉 `vendor` 排除 —— 两发都**该绿**。
最终一遍：**符合预期 9/9，所有文件逐字节还原。**

⚠ 两发控制组不是凑数：它们红的瞬间就暴露了那台坏机器（§5）。而且 M8 的「该绿」是
**实测出来的范围声明**，不是牙齿 —— 我先数过 `packages/web/public/vendor` 里
`/org` 的命中数：**0**（10 份文件，quill 与 xspreadsheet），所以摘掉 `vendor`
排除不会改变任何读数。这一格现在登记的是「`vendor` 在名单里是为了【别将来撞名】」，
它不承担「摘掉会红」；将来 vendor 里真出现 `/org`，M8 会翻红，那时它才升成牙齿。

## 7. 一处守卫被新文件打到，照名单登记

`production-deps.test.ts` 红在「新出现的 `readdirSync` 使用者」。这一条是**设计好的**：
它不许任何一份文件悄悄拿到目录遍历而不说明自己会不会 walk 进 `packages/hub/src`。
登记进 `OUT_OF_SCOPE` 并写明成立条件：两处遍历的根分别是
`packages/web/public`（主扫描）与 `packages/web/src`（反向对照那一发），都在
`packages/hub/src` 之外；⚠ **哪天把扫描根扩到仓库根，这一格作废，得搬去 `NEEDS`。**

## 8. 别当成做到了

- **本守卫不判「配置页该不该做」。** 那仍是 CEO 排期那一格，0067 §9 已写明
  依据缺口（web 还是 desktop、列表与表单的信息密度）。本篇只让「零调用方」这句话
  从「我 grep 了一下」变成「一把量得出东西的尺子读出来的」。
- **扫描面只有 `packages/web/public`。** desktop 侧仍然**只判了 `src`**：它是 IPC 契约层、
  非可运行 App（优化设计 §O13 那一格 + `test/arch/desktop-honest-label.ts` 判着），
  今天没有渲染层可扫。
  哪天它变成真 App，扫描面与 `production-deps` 那一格都要跟着改 —— 这条写在判据文件头，
  不写在断言里（断言管不了「将来有一份新目录」）。
- **「可达 ≠ 有人调」仍然成立，而且本篇没变这一点。** 三条端点在 IPC 白名单里可达，
  可达性由 r27 判；本篇判的是探针。两件事各自有自己的分母，别把本篇读成「接线又前进了一格」——
  **本篇零生产代码改动**。
- **给 r15 与优化设计 §7 第 15 格的那句过期证据，我没有改文。** 那两处
  round295 已在同一份文档里撤回过（「扫描根只列 web/src 与 desktop/src」那段），
  按「源头修正不逐处追改」的既有口径放行。本篇的新证据只登记在 0067 §9 与这里。
- **变异机不入库**（`.workbuddy/scratch/` 那批历来不入库）。于是 9 发的原文/替换对
  只活在那份不持久的文件与 §6 摘要里 —— 与 0066/0067 记过的是同一个已知代价。
- **`vendor` 那一格今天没有牙齿**（§6 末），这条不要读成「扫描面对第三方库做了承重排除」。
