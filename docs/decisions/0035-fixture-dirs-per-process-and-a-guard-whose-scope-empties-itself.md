## 0. 复算：这不是一个猜想，是三次红

0025 §7 第 7 条记过这件事并给了修法，本篇先把它**重新跑出来**（脚本 `/tmp/probe-concurrent.mjs`，
四个 db 测试文件，同一份 glob）：

```
顺序跑      89 / 87 / 2
两条并发 A  89 / 84 / 5      ← database disk image is malformed
两条并发 B  89 / 82 / 7      ← table tasks already exists / UNIQUE constraint failed: tasks.id
```

三条读数里最值得读的是**两串红互不相同**，而且**没有一条指向被改过的代码**：
报错全是「我手上的库被人换掉了 / 已经存在了」的形状。
成因（0025 记的、本篇复算的）：**33 个测试文件**各自
`const TMP = join(HUB, ".tmp", "<固定名字>")`，`beforeAll` 里再一条
`rmSync(TMP, {recursive: true, force: true})` —— 目录名**按测试文件分，不按进程分**，
于是同一个文件的两份运行互相删对方正在用的库。

**阳性对照（本篇自己的，0032 §0 那条教训的适用）**：把 `integrity.test.ts`
一处改回固定名（**语义型**：只换名字那一处，不动别的），并发立刻回来：

```
顺序      89 / 87 / 2
并发 B    89 / 85 / 4
并发 A    89 / 84 / 5
```

⇒ 消掉它的就是那个 pid 后缀，不是别的任何东西。
⚠ 这一发的**第一次跑法是废的**：我当时往那个文件里加了一行 `const HUB = ...`，
而那个文件的 `HUB` 还没被删（它另有引用者），于是得到
`Identifier 'HUB' has already been declared` —— 三个进程报**同一个语法错**、
红数**完全相同**。那一版什么都证明不了（0030 §9 那条「炸掉的变异同样什么都证明不了」的第三次适用），
而我差点就这么记下来了：**三条读数一样时，先怀疑它们来自同一个崩，而不是来自同一个结论。**

## 1. 修法为什么是「目录带 pid」，而不是 0025 写的那条

0025 §7 第 7 条原文给的修法是「得连『删整个目录』换成『只删自己那些前缀』才闭合」。
**那条不成立**，而否证它的证据就在同一句里：
`integrity.test.ts` 的**库文件名**早就带了 pid（`ig-<pid>-<序号>.db`），而它照样红 ——
因为**目录名没带**，删的还是同一个目录。
所以「光是加 pid 不够」的确切成因是「**加错了地方**」：加在文件名上，删的是目录。

| 候选修法 | 闭合吗 | 代价 |
| --- | --- | --- |
| 库文件名带 pid（已有） | **不闭合** | 删的还是同一个目录 |
| `rmSync` 改成「只删自己那些前缀」 | 闭合 | 33 个文件各写一遍「只删自己的」，**漏一处红一次，而漏的那处在单跑下永远绿** |
| **目录名带 pid（选了）** | 闭合 | 「整目录 rmSync」重新变成安全动作（删的必然是自己那份），一条 rmSync 都不用改 |

第三条的真正好处不是少写代码，是**它把安全性放在路径里而不是放在 33 处逻辑里**：
路径由一个函数产生，改一处就全覆盖；前缀删除的正确性要靠 33 个作者各写对。

## 2. helper 刻意【不注册】清理钩子，而理由是被量出来的

让 `fixtureTmp()` 顺手 `afterAll(rmSync)` 看着更省心。两处实测代价让它不成立：

1. **钩子顺序**。`node:test` 的 `after` 是**先进先出**（实测：注册两个 after，
   打出 `ORDER=first-registered,second-registered`）。helper 的注册点在文件头
   `const TMP = …` 那一行，**早于**每个文件自己那个 afterAll ⇒
   清理会跑在「afterAll 里关句柄 / 断言跑了几发」**之前**。
   ⚠ 我顺手量了这个乱序对 SQLite 是否致命：**不致命**（macOS 上先 `rm -rf` 目录、
   之后再写一行、再 close，三个动作都不抛 —— `/tmp/probe-close-after-rm.ts`、`/tmp/probe2.ts`）。
   而**「实测不致命」不构成它能用**：那是 posix 的 unlink 语义在兜着（打开的文件删名字不销毁 inode），
   一条没被声明的性质。
2. 那会让 `afterAll` 从测试框架取钩子，而本仓的离线夹具把 vitest 门面放在**仓库外**
   （`/tmp/opc-harness`，理由在那里写着：往 node_modules 放一个假 vitest
   等于把一次临时验证伪装成真门禁）。**生产夹具模块依赖测试框架的名字解析**，
   等于把「夹具能不能跑」系在夹具上。

所以清理**照旧留在各文件的 afterAll 里**（现存 33 处一条不缺、本篇一条未动），
而「有没有漏写清理」改由那条源码普查守（§3 的第二支）。
判据落在守卫里，不落在「请记得写 afterAll」这句注释里 ——
`test/arch/run-fixtures.ts` 文件头那句「注释不是机制」在这里同样成立。

**换 pid 目录会带进来一个原本不存在的新洞**，所以顺手补上：
固定名时代「上次崩留下的目录」会被下一次运行顺手删掉（**那正是竞态的来源**），
换成 pid 之后没人顺手删 ⇒ 每崩一次留一摞 SQLite 库。
`fixtureTmp()` 在建自己那份之前先删**同名字而 pid 已死**的兄弟目录。
它安全的前提只有一条：**目录名里的 pid 就是它的属主**，而活着的进程之间 pid 唯一
⇒「pid 不在」等价于「属主已经没了」。
反过来两种判据都是错的：按「目录多久没动」判（慢用例正在写的库也可能很久没动），
按「别人来清我的目录」判（**那是本篇刚消掉的动作本身**，只是换了个更弱的信号）。
实测（`/tmp/probe-prune.ts`）：两个死属主的同名目录被清掉，而
`pruneprobe-sub-999996`（**名字前缀重合**）、无后缀的 `pruneprobe`、`bench`（另一支脚本的产物）三个都活着。

**pid 必须取末尾那一组数字**：`schema-0001-4242` 的属主是 4242 而不是 0001。
从前往后数的话，一份泄漏的 `schema-0001` 会被认成 pid 1（macOS 上 launchd 恒在 ⇒ 永不清理），
更坏的是别的名字可能被认成一个**恰好活着**的无关 pid ⇒ 清理会去删别人的活目录。

## 3. ⭐ 判据的射程，在它防的东西消失之后自己变成空集

普查有两条子判据：`fixed-name`（建了固定名的 `.tmp` 目录而没走 helper）、
`no-cleanup`（走了 helper 而文件里没有 afterAll 清理）。
**第一条在转换做完后不再命中任何东西 —— 那是它该有的样子。第二条才是本篇真正留下的东西**，
而它差一点是恒不执行的。

症状不在判据上，在**它自己的射程计算**上：
转换之前，一个文件在射程内的条件是「源码里有 `".tmp"` 字面量」——
转换之后，33 个文件里**一个都不剩**（helper 把路径拼法吸收了）。
如果射程照旧按 `".tmp"` 算，`no-cleanup` 那一支就变成**一条永远走不到的判据**。

而它**不会以红的方式说话**，因为它自己的测试是绿的 ——
那条测试喂的是我手写的字符串常量，不是真仓库的文件。
所以我加了一条**射程自己的断言**（`fixture-dir.test.ts` ③ 那一组）：

```
expect(CONVERTED.includes('".tmp"')).toBe(false);   // 转换后的源码里没那个字面量
expect(createsTmpDir(CONVERTED)).toBe(false);        // 旧射程判它在射程外
expect(inScopeForFixtureGuard(CONVERTED)).toBe(true);// 新射程判它在射程内
```

**「一条守卫的射程」是它最容易被忽略的一维，因为它不出现在判据里。**
判据写得对而射程是空集，读数同样是「零问题」——
这与 0033 §6 那条「今天恒绿的守卫要自己声明自己恒绿」是同一族，
只是这次的空集**不是设计时就有的，是这次改动造出来的**：
我把问题消干净的同时，把「看得见问题的那只眼睛」也一起消掉了。

顺带三条判据形状（各配一发测试与一种坏法）：

- **`.tmp` 出现在「跳过名单」里不算建目录**。全仓 4 处把 `.tmp` 列进扫描跳过名单
  （`e.name === ".tmp"`）。一条只看 `.tmp` 字符串的普查会要求那四处也「按进程分开」——
  而**跳过名单里带 pid 是荒谬的**（磁盘上那个目录名恒为 `.tmp`，
  名单里写成 `.tmp-4242` 才是真错）。**这又是「一条更严的判据拒掉正确写法」的形状**
  （0033 §3 那一族的第三次），区别是这次在写下之前挡掉了。
- **判据不要求名字以 `-${process.pid}` 结尾**。第一版那么写，于是它把
  **唯一那 4 处已经正确的写法**（`"tokens-" + process.pid` 那种拼接）判成违规。
- **报错文案不能写成完整调用形状**。`explainFixtureDirHit` 我第一版写成
  「把 `join(HUB, ".tmp", "x")` 换成 `fixtureTmp("x", import.meta.url)`」，
  而**那段文案也在普查扫的树里** ⇒ 判据自己命中自己的判据。
  靠「helper 自己零命中」那发抓到的（那条断言本来只是收收形式，这次它接住了真东西）。

**一处我判错了的断言**：`每一条 fixtureTmp 的入参都是字面量` 那条第一版红在 helper 自己身上 ——
因为 `export function fixtureTmp(` 同样匹配「一次调用」的形状。
那是**断言写错**（它没套用判据自己那份排除表）而**不是代码写错**，
修法是把排除表抽成导出的 `GUARD_SELF_PATHS` 让两边共用，而不是把断言放宽。

## 4. 一条正则的漏口，是变异逼出来的而不是看出来的

`fixedTmpDirNames` 我第一版写成 `join\(\s*[^,()]+,\s*"\.tmp"\s*,\s*"…"`。
第一段那个 `[^,()]+` 把**任何带括号的参数**排除在匹配之外 ——
于是变异 O-B（把 `migrate.test.ts` 改回 `join(process.cwd(), ".tmp", "migrate")`）
**普查零命中**。

而 `join(process.cwd(), ".tmp", "x")` 恰恰是「新建一个夹具」最省事的写法。
`join(HUB, ".tmp", "x")` 那种纯标识符能匹配，**掩盖了「只要参数是个调用就漏」**——
我测过的那几种写法全都能匹配，于是我以为判据是好的。
现在允许一层嵌套括号；**两层以上仍会漏**（`join(a(b(c())), ".tmp", "x")`），
那是**已知漏口**（§7），并专门配一发测试钉住「漏口存在」这件事本身。

**⇒ 「我试了几个例子都被抓住」不是「判据有判别力」的证据**，
它只是「我试的那几个例子长得像」的证据。O-B 是我在写完 26 发测试之后跑的，
而那 26 发全绿。

## 5. 一次纯机械改动为什么会红掉别人的引用

本篇没改任何生产代码，却红了 **5 条【决策文档】里的 `文件:行号` 引用**
（`doc-refs` 那条守卫的快照）。成因：每个文件净减一行（删掉 `const HUB` 那一行），
而那 5 处引用指向的行**都在删除点下面**，于是整体下移一行。

按 `doc-refs.test.ts` 文件头写着的常规处置：
**先在目标文件里 `sed -n '<n>p'` 读原文**，确认「引用的还是同一行、内容一字未变」之后才改坐标，
**不按 diff 行数推算**。本篇五处的新行号是从内容匹配反查的（不是从「净减 1 行」推的），
而逐条读了 `sed -n` 确认内容一致（0007 那段常规记的是它**第五次**抓同一件事，这是第六次）。

⚠ **同一条守卫又拦了我一次，而这次坏的不是坐标是快照的抄法**：给本篇那条新引用登记快照时，
我把目标行**照屏幕原样**抄了进去（含 JSDoc 那个前导空格），于是红在
「快照 [ ` * ── 为什么需要…` ] 现在是 [ `* ── 为什么需要…` ]」——
差一个缩进空格，而**它读起来像「目标行被人改了」**。
真相是 `verify` 比的是 `(src[ln-1] ?? "").trim()`，口径一直如此（表里 0030 那条
`* 端点 → …` 同样是 trim 过的），错的是**我抄之前没读比对口径**。
处置值得留一句：我第一反应是「这条引用不成立，删掉快照」，
而那条引用**是**成立的 —— 它指的就是「那一行承载 `0025 §7 第 7 条` 这个出处」，
正是快照该钉的东西（有人把那一行改成「这里已按 pid 分目录」，快照必须红）。
⇒ **一条守卫红了，先分清坏的是「主张」还是「主张的写法」；两者都改掉的东西不一样，
而删掉主张是最省事的那一种，也因此是最容易选错的那一种。**
（这是 §5.1 那条「『照判据数过』要先读判据」在同一篇里的第二次，隔了两节，同一个我。）

另外 4 条红是 `comment-citations`，成因不同也更简单：**我先写了引 0035 的代码注释，
再写文档** —— 同一个中间态第 5 次出现（0031 / 0032 / 0033 / 0034 各一次），
而我这次是在写代码**之前**读了 0034 那条「先写文档再写注释」的常规，**还是先写了代码**。
⇒ 「读过的常规不等于会执行的常规」这句话本身也已经是抄第四遍了，
它抄多少遍都不生效；生效的唯一方式是**落盘之前去执行那一步**。

### 5.1 而 `0025 §7 第 7 条` 这条引用被报「不存在」——**那句不存在是假的**

上面那两条红里混着第三条性质完全不同的：`comment-citations` 报
「`fixture-dir.ts:4` → `0025 §7 第 7 条` 在目标篇里不存在（那一节【那一条】已被改名或删掉）」，
而 0025 第 290 行明明写着 `7. ⭐ **全量测试同时跑两路会自己造出红条**` ——
**本篇整篇就是在闭合那一条**。

根因在识别条目的那条正则（`test/arch/doc-coords.ts` 的 `itemNumbers`）：
它数的是 `## 7.` 之内形如 **`N. **粗体**`** 的行，而那一条编号后面跟的是 **⭐** 而不是粗体。
⇒ 守卫输出的那句「已被改名或删掉」**不是保守的不知道，是一句肯定的假话**，
而它的形态与一条确凿的核对结论一模一样（同 0033 §0 那一族）。

**修法有两种，我选了改守卫而不是改引用**：
把引用改成 `0025 §7` 那一节的不带条号写法，今天就能绿，
而那样做等于**为了让一句假话消失而不再说那句真话** ——
那一条恰恰是全仓**唯一**被本篇闭合的条目引用，抹掉条号会丢掉「闭合了哪一条」这个信息。
所以放宽识别口径：`## 7.` 之内**顶格**的 `N.` 清单行都算条目。

放宽前后各数了一遍全仓（口径完全照 `itemNumbers` 的实现，含它不跳代码块这一点）：

```
旧口径认 99 条   →   新口径认 101 条
多的两条：0025 §7 第 7 条（`7. ⭐ **…**`）· 0014 §7 第 3 条（`3. 顺带一条…`，没有粗体）
```

**两条都是真条目** ⇒ 多出来的是「原来漏了」，不是「现在多了」。
真正承重的是**行首无缩进**那一条（嵌套子清单在本仓一律缩进），
它挡掉了「`第 2 条` 被一个嵌套列表项洗白成存在」这种假绿，
配一发反向对照钉住「缩进子项 / `0.5 秒` / 无序列表 / 过了节界的 `9.`」四种都不算条目。

⚠ **我在这一段里先写错了一句，改在这里而不是删掉**：第一版写的是
「另一条更宽的候选（`^([0-9]+)\.` 不要求 `N.` 后面有空白）会多收 0026 §7 那两条」，
实测两个口径**都是 101 条，一条不差** —— 那两条 0026 的行本来就被现口径收着，
「不要求空白」在本仓语料上**多收 0 条**。
所以 `N.` 后必须空白那一条约束今天**没有读数支撑**，它防的是将来出现的 `0.5 秒` 那一形。
⇒ 与 0034 §读数 同一条毛病：**我按「更宽的口径当然多收几条」推断，而两条命令就能数而我没数**；
这次是在写「代价如实记」那一段时数的，也就是说**我打算给读者量代价，仍然先给了推断**。

代价如实记：口径变宽 ⇒ 「引一个不存在的条目号」被放过的面**变大一点**，
具体条件是「该篇 §7 里恰好有一条顶格 `N.` 而你引的正是那个 N」。
这一格与 0007 §4.1 那条「误报会让整套挂掉，代价比漏报高」是同一次取舍，
而这次站在对面的是**一句假的否定结论** —— 那比漏报坏，因为假话会被当成证据引用。

## 7. 别当成做到了

- ⚠ **判据只认字符串字面量当目录名**。`fixtureTmp(name, …)` 这种变量写法不报
  （读不出它带不带 pid）。漏的方向是**少报**；写宽会让人去把变量改成字面量 —— 那是绕开判据。
- ⚠ **第一段带两层以上括号的 `join` 仍认不出**（`join(a(b(c())), ".tmp", "x")`）。
  修它要真解析 AST，与这条守卫的分量不称。两格都在射程内、都不命中，
  并且**各有一发测试钉住「漏口存在」**（`fixture-dir.test.ts` ③ 最后两发）。
- ⚠ **`no-cleanup` 只查「文件里 afterAll 之后出现过 `rmSync(TMP`」**，不查删的就是那份目录，
  也不查它在 afterAll **里面**（写在 afterAll 之后的裸 `rmSync` 也算过）。
  写严要解析 AST，而误报的代价是「整套挂掉」（0025 §7 那条），比漏报高。
- ⚠ **本篇没有让「两条并发全量」变成一种被支持的用法**，只是让它不再互相销毁。
  两个进程仍然会**争同一份 `packages/contracts/dist`**（`globalSetup` 建它），
  那一格与本篇无关，0007 §9 记过。⇒ 别把 §6 那行读数读成「可以并发跑 CI」。
- ⚠ **崩溃留下的目录仍会留**。`pruneStaleFixtureDirs` 只在**同一个夹具名**被再次请求时清它，
  所以一个不再被跑的文件留下的目录要等到下次全量才被清，而它若**从未再被请求**就一直留着。
  `.tmp/` 已 gitignore，手工 `rm -rf packages/hub/.tmp` 即可。
  刻意**没有**做「启动时扫一遍全清」，因为那个判据必然是「pid 不在 ⇒ 删」，
  而 pid 会复用（macOS 到上限回绕）—— 误删一个正在用的目录的症状与本篇修的那个一模一样。

  ⇒ 下面那些绿是 **node:test + 自制 harness** 给的，**不是门禁过了**；排版是手工对齐的。
