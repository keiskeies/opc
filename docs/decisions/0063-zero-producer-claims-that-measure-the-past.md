# 0063　「这张表在 src 里零写入方」：一类测于过去、写成现在时的句子没有东西守着 —— 于是长出一个专门对账它们的事实核查

## 1. 一句话

本仓写着一整类现在时句子：「`harness_calls` 的 INSERT 在 src 里是【零】」「`im_bindings`
全仓没有任何一条 SQL 碰过它」。它们当年都是**当场 grep 出来的真读数**，写成现在时留在原地；
写入方是会【长出来】的 —— `engine/runtime.ts` 的会话存储、`approvals/cards.ts` 的建卡模块、
引擎路线的预算自增，全是后来接上的生产者。可没有任何测试判「这句话今天还对不对」，
于是这类句子在表已经有写入方之后**一直还是绿的**。

本篇量到 **5 件事、拆成 7 句已经假了**（判据口径见 §2 的表），据此造了一个守卫
`test/arch/zero-producer.ts`：**登记表 + 双向对账** —— 扫 src 抽出每一句这种话 ⇒ 必须登记；
登记里写着它是【零】还是【有】⇒ 与扫代码字符串得到的实际写入方对账，不一致就红。
一个一句抵十句的【万能锚】、一个"我只是引用"/"这句说的是别的东西"的【逃生口】，
各配一发反向对照钉死（见 §6）。守卫只有在它能先红的地方才算数，所以 §2 的先做的不是写守卫，
是拿【能扫出已知写入方】的探针把五处假逐句量出来。

**量法为什么可信**：用【最终守卫的同一条判据】跑 HEAD —— 只认字符串字面量里以 INSERT 开头
的 SQL（含 `INSERT OR IGNORE/REPLACE INTO` 那两种，少了它们守卫会自己放过真写入方，0063
自己就是靠这个教训把正则补上的），只认「零 INSERT / 零写入方 / 没有生产者」这类句式，
带历史标记（量的/当时/此前/写之前…）的不算。第三节的正面自检把【已知存在的写入方】
数得出来，才敢信「review_gates 找不到」是真的找不到而不是数法坏了。

同一次测量里被分行命中的 **真零写入方**（今天的确没有生产者，句子没撒谎）：
`review_gates`（三句）、`events` 里 `harness_call` 那个 action 值的【签发方】只有走 Gateway
才有而 Gateway 今天零生产调用方（这一句其实【话里有话】——它说的是 events 的 action 值，
不是 harness_calls 那张表，别混）、`app.ts` / `today.ts` 两个「没有生产者的取值形状」
（说的是类型上某个值没人构造）。这四类不该被判成撒谎，但也不许溜进「other 就是一个
垃圾桶」—— 见 §6。

## 3. 判决条例：判的是源码里有没有那条 SQL

判据的作用域是【src 这套源码里有没有那条 INSERT】，**不是**【真库里有没有这行数据】，
也**不是**【那条代码在生产里可不可达】。三件事是分开的：

- 有 SQL 而生产不可达 —— `policy/auto-approve.ts` 自己就是（`recordAutoApproval` 零生产
  调用方，0014 §3）。一条这种代码里的假注释运行期影响是 0（0049 §11 那条已经把分量写准），
  但它误导下一个读它的人。
- 生产可达而本守卫看不见运行时 —— 全部。想说「生产里没写入方」的句子必须把【生产】两个字
  写进登记（`harness/safety.ts` 那条就是这么归进非表档的），否则按【源码里有没有】判 ——
  那是个更弱的口径，配不上「生产」这个词。这一格是口径，不是漏判。

## 4. 为什么旧的守卫都放它过去

- `doc-coords` / `comment-citations` 判的是【小节号存在性】与【§ 引用存在性】，不判
  「这句话今天还对不对」。
- `doc-refs` 判的是【文件:行号】指向非空行，也不判这句子的内容真假 —— 它甚至会把
  【注释里那句假话所在的行】钉成快照，等于把假话锁得更牢。
- `doc-ids` 只审「正文提到的决策编号不许指空号」，与源码注释里的表白毫无关系。
- `integrity.test.ts` 的 `toContain("INSERT")` 只查模板有没有 INSERT 字样 —— 真句子和
  **假句子都含这个词**，所以 0062 §8 记的那种「注释里凡数出来的数目」同一族：改 Union 的人
  不会想起回来数分母，而改表的人也不会想起回来改那句话。

0049 §11 是这一族最硬的证据：那句 approvals 的假话【在 0049 里被白纸黑字点过名、
分量也写准了】，可它【没有】因为被点名而自动修复 —— 它今天还躺在 auto-approve.ts 里，
由 0063 亲手改掉。一篇决策文档说一句注释是假的，和一句话自己变红，是两件事。

## 5. 为什么只有 review_gates 还值得写「零」；以及 O4 动作 2 / 4

`review_gates` 的 INSERT 到今天仍是【零】—— 0016 §1 第 1 条、0018 §9 各复算过一遍，
0063 又复算了一遍（用同一条 INSERT-OR-aware 扫描器，HEAD 上找不到）：src 里没有任何
`INSERT INTO review_gates`，只有 `test/db/schema-0001.test.ts` 的外键夹具插过行。
这一句是【真的零】，所以守卫生效后它照常绿 —— 而正因为它是真的，它成了守卫最该守住的一格：
一旦将来有人给 review_gates 补上生产者（O4 动作 2 让 `independentReviewerPath` 的
unresolved 落库时写它，或 O4 动作 4 直接决定把它做成预留），这句话必须在当天变红，
而不是又躺一轮没人看。设计与当前 O4 状态：动作 2 / 3 / 4 一条没动，`review_gates` 仍是
规格要求的一张空表，`integrity.ts` 那条自检把它判成 not_observable（空不是通过）。

## 6. 守卫的三档免检，以及每一档的反向对照

一句被扫出来的声明必须落在登记表里，而登记不是「我读过这句子就该放行」—— 每一档都要
**【反向对照】**：拿一张合成源码走那条逃生口，必须红。没有反向对照的豁免与没有豁免不可区分
（0062 §8 / 0054 同形）。

- **`historical`（历史时态）**：句子带「量的/当时/此前/写之前/原本/当年」这类词 ⇒ 今天有写入方
  不红。引【决策编号】**不算**历史标记 —— `integrity.ts` 那句「src 里零 INSERT，0018 §9
  复算」是现在时且为假，0018 §9 是它援引的依据，不是它的时态。我第一版把编号写进标记，
  等于给本轮要修的那句发通行证，当场被反向对照抓住改掉。
- **`quoted`（引用）**：句子写在 `「…」` 里、是【在引用一句旧话】⇒ 不算主张。这是
  「最方便的逃生口」—— 任何假话都能自称引用。所以它要过一道【真判据】：锚必须与同一行的
  `「…」` 构成引用关系（§6 反向对照丙）。引用不是历史时态：`historical` 管「这句当时为真」，
  `quoted` 管「这句不是我说的」。
- **`other`（不是表）**：说的是「一个没有生产者的取值形状」/「那一列」/「某个 action 值」。
  这一档**所以最容易被滥用**：谁都能把一句假话登记成"这不是表"。它的硬判据不是约定：
  `about` 里【不许出现任何一张真实表名】（名单由测试对照 migrations 的 CREATE TABLE 数出），
  而且条数被测试里的常量钉住 —— 想加一条得改那个数，而那个数旁边写着它是什么意思。

另外两个不保证绿的原因也要写死：multi-claim 一行挂两条（integrity.ts 那条原话就是
`review_gates / harness_calls` 一起说的，0063 把它拆成两句分表陈述），所以登记表今天
最长也只能指一张表；而 `anchor` 用**内容**定位而不是行号 —— 本仓坐标一律内容定位
（0054 那条「行号会漂」的教训），改一行别的注释不该让这条登记变成幽灵。一条登记的锚
在同一文件命中多处 = 一句抵十句 = 假的全覆盖，也要报（反向对照戊）。

## 9. 留在原地没做的

1. **O4 动作 2 / 4 仍未动**：`independentReviewerPath` 那一跳的 unresolved 落库、
   `review_gates` 的 INSERT 方或「预留非缺陷」的正面决定。本篇只是让【那一天那句「零」
   变红】成为可能，没有替任何人做那一天。
2. **`createCard` 仍然零生产调用方**（0049 §11 第 2 条）：三个建卡点全绕过它直接调
   `insertCard`，这是本仓记过最多次的那一族的现役样本，不在本篇范围。
3. **守卫看不见 test/**（0007 §1.3：test/ 不在 `tsc -b` 内，只能独立跑），所以它自己是
   例外的 —— 它扫的是各包 src，不含 test 的夹具。夹具里插行（`schema-0001.test.ts` 的
   review_gates 外键用例）不构成"生产者"，这是口径不是漏判。
4. **生产者只扫字符串字面量**，拼接的 SQL 只看第一段（表名必在首段），一 String 常量
   （`events` 的 action_enum 之类）不区分大小写 —— 全仓先 grep 过没有小写 `insert into`，
   所以不区分大小写是白拿的，不是放水。
