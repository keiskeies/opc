# 0072 · 屏幕上那句「放开不了、要重启」是假的 —— 而它假了二十几轮，因为门换过一次而没人回来重量

**日期。** 2026-11-27（round386）。
**落地。** `packages/web/public/app.js`（`driverLine` 钱那一档那句 + 它上面那段理由）；
`test/web/app-pure.test.ts`（3 发跟着措辞走：2 发改判据、1 发改对照物）；
`packages/hub/test/overview/driver-status.test.ts`（+1 发，26 → 27）。
**同时作废两处旧主张**：`docs/decisions/0049-…md` §12（就地标注，正文原样留着）、
`docs/CEO-决策简报-2026-11-22.md` B8 的「现状」那段。

## 1. 一句话

看板上被钱挡住的那张卡写着：

```
不再推：花到了命令行那个单条上限（$5.00）· 屏幕上放开不了，要它继续走得带更高的 --task-limit-cents 重启 · 30 分钟前
```

**两半都是假的**（今天的代码下，逐字实测）：

1. 「花到了命令行那个单条上限」—— 分母是 `COALESCE(budgets.limit_cents, 命令行)`，
   **有预算行时那一列说话**，命令行那个数在这一支里从没参与过判据。印出来的 `$5.00`
   是响应里唯一的那个钱数（`driver.task_limit_cents`），而它恰恰是【没参与决定】的那一个。
2. 「屏幕上放开不了，要带更高的 `--task-limit-cents` 重启」—— **反了**。屏幕上就能放开
   （预算页把 `task/<id>/per_task` 那一格改大），而**重启改不动门**：那一行是记账时
   `ENSERT_BUDGET_SQL`（`ON CONFLICT DO NOTHING`）写的，行已在 ⇒ 新数字一个字进不去。

新那句（`packages/web/public/app.js:1046`）：

```
不再推：花到了这一格的单条上限 · 放开它在预算页：把 task/t1/per_task 那一行改大（还没有那一行就新增一行），不必重启 · 30 分钟前
```

**这一格没有用户症状之外的东西可修**：门本身是对的（r25 拍板的方向），错的是屏幕上
指向下一步的那句话 —— 它把一件**能做的事**说成**做不了**，又把一条**走不通的路**
说成唯一的出路。操作的人照它做会去重启进程，重启完发现还是挡着。

## 2. ⭐ 病灶不是「写错」，是「写过而对、后来门换了而没人回来重量」

那句假话不是拍脑袋写的，它配着一发探针和一个测试，而那两样**当时都是对的**：

| 时间 | 门的形状 | 那句话 | 探针 |
| --- | --- | --- | --- |
| `097b5ce`（0049 §12） | 上限那一侧只读进程里的参数 | 「分母是命令行 / 屏幕上放开不了」 | 实测「把那一列提到 5000 ⇒ 候选 0 → 0、看板照旧」 |
| `240fcec`（round360） | 改成 `COALESCE(列, 参数)`，**列赢**（CEO 拍板，登记为设计文档 §1.1 的 **r25**） | **一字未动** | **没有重跑** |
| 本篇（round386） | 同上 | 改掉 | 重量一遍，见 §3 |

⇒ **「一句为真的话变假」最常见的路径不是有人改坏了它，是它的前提被换掉了而没有人回去看它。**
而这次三道防线全都不会响，因为它们判的是别的东西：

- `test/web/app-pure.test.ts` 那一发钉的是**措辞不许指回不存在的路**（追加预算 / 提高预算 /
  提高上限 / 加预算 / 放开预算 / 点此），并把**「重启」/「命令行」/「--task-limit-cents」
  钉成【必须出现】**。round360 之后那句话仍然是【假话】，但它**完美满足**这套判据 ——
  **测试是绿的，因为测试要的就是那句假话**。这一条要单独立着：守卫的判据可以是
  「当时的正确答案」，于是它会把错误答案一直保护下来。
- `test/arch/claims-registry.ts` 的 `budgetColumnGovernsCheck`（r25 那条）**只读源码字节**，
  判 `underTaskBudgetSql` 那一段里「列在 COALESCE 第一位 / 比较尾巴在场 / 恰好 1 个 `?`」。
  它守住了【门】，压根不看【屏幕】—— 门与界面各守一半而中间那根线没人守。

## 3. 实测：同一份库，只动一侧

`.workbuddy/scratch/round386-budget-denominator.mts`（tsx，真迁移真库）。
关键设计：**改那一格走的是 `UPSERT_BUDGET_ROW_SQL` 本体**（`packages/hub/src/http/budget.ts:149`）——
与屏幕上点保存同一条语句，所以量到的就是「人点一下」的效果；而 `consumed_cents`
由另一发直接摆（那条语句把它写成字面 0）。命令行那一侧固定一个数，只换列；
再反过来固定列、只换命令行。

| # | 摆什么 | 读数 |
| --- | --- | --- |
| ① | 无预算行，命令行 500 | 驱动候选 `["t1"]` · 看板 `[]` |
| ② | 列 500、已花 900 | 挡下 `["t1"]` · 看板 `[["t1","no_budget"]]` |
| ③ | ⭐ **只把那一列存成 5000**（命令行仍 500） | **候选 `["t1"]` · 看板 `[]`** |
| ④ | 列 100、已花 200 | 挡下 · 看板 `no_budget` |
| ⑤ | ⭐ **只把命令行抬到 9999**（列仍 100） | **候选 `[]` · 看板 `[["t1","no_budget"]]`** |
| ⑥ | 删掉那一行（命令行 9999） | 候选 `["t1"]`（回落到参数） |
| ⑦ | 那一行已在（100）而记账时参数给 9999 | `limit_cents` 实到 **100** |
| ⑦b | 那一行没有时同一发记账 | 写进 **9999** |
| ⑧ | 无那一行而命令行 = **0** | 看板 `[["t1","no_budget"]]` |
| ⑨ | ⑧ 那个形状下用同一发保存新增一行 5000 | `no_budget` → **`[]`** |

③ 与 ⑤ 是决定性的一对：**列改得动门，命令行改不动**（那一行存在时）。
⑦ 把「带更高的参数重启」这条路**钉死**：`ON CONFLICT DO NOTHING` ⇒ 9999 进不去。
⑦b 说明为什么今天看起来「命令行与列是同一个数」：那一行第一次被建出来时用的是
当时的参数（`packages/hub/src/engine/runtime.ts:630`）—— **同源是一次性的，不是持续的**。

## 4. 判据怎么改：连理由一起改，而不是把措辞换掉

`test/web/app-pure.test.ts` 里那三发的 docstring **自己预言过**这一刻：
「等 0045 §7 那一格被拍下来、真有了端点，这一发会挡住顺手改回去 ——
**那时该改的是这一发本身（连同它上面这段理由），而不是悄悄把措辞换掉**」。
所以本轮动的正是那三发与它们的理由，而不新起一发把旧的留着：

- 「钱那一档说出【上限是多少钱】」→「说出【去哪一行改】」：`$5.00` 换成
  `task/t2/per_task`，并钉 `not.toContain("$")`。
  ⚠ 原来那句 `not.toContain("/")`（防「第 x/y 次」那种没发生过的计数）**必须换掉** ——
  新句子里的路径 `task/t2/per_task` 天然带斜杠。计数那一族改钉【汉字】：
  正则 `第\s*\d+\s*\/\s*\d+\s*次` 加上 `not.toContain("第 ")`。
  **这就是「判据的尺子要与被剪线有因果」的现场版**：斜杠从来不是那件事的因果，
  它只是旧措辞恰好没有斜杠。
- 「不许指回屏幕上不存在的那一步」→「不许把人支去【重启】这条今天走不通的路」：
  禁词族从「追加预算…」换成「`--task-limit-cents` / 命令行 / 带更高的 / 屏幕上放开不了」，
  必须出现的内容换成「预算页 / `task/<id>/per_task` / 改大 / 新增一行」。
  ⚠ **「重启」这一词不能整词禁**：这句本来就该说「不必重启」（不说，人还是会去重启）。
  我第一版就是整词禁，被自己的判据挡红。改成**每一次出现都必须以「不必」开头**
  （`/(.{0,2})重启/g` 逐次判前两字），并额外要求命中数 > 0（不许只字不提）。
  这样「得重启」「重启后生效」都会红，而「不必重启」过。
- 第三发的对照物 `$5.00` 同样换成路径。

新那发在**服务端**（`driver-status.test.ts` 的 C 组）：命令行 9999 而列 100 ⇒ 报 `no_budget`；
同一发用 `UPSERT_BUDGET_ROW_SQL` 把那格存成 5000 ⇒ 同一个 9999 之下门开；再存回 100 ⇒
命令行抬到 99999 也不许开。**它排掉的是「取两者较大」这种写法** —— 已有的那条 c5
只证了「参数为 null 时列赢」，`MAX(列, 参数)` 能满足 c5 却会误导屏幕上那句话。
改那一格**必须走生产语句**而不是手拼 `UPDATE`：后者将来就算被改成不写 `limit_cents`，
这一发仍会绿，而屏幕上那句话当场成假（每根线要有自己的那次动作）。

## 5. 新句子的两种形状，以及为什么写「改大（还没有那一行就新增一行）」

⑧ 那一发是写句子时才发现的：`--task-limit-cents` 的校验函数名叫 `positiveInt`，
而它只做 `/^\d+$/` + 安全整数（`packages/hub/src/serve/config.ts:175-188`）⇒ **0 过得去**。
命令行给 0 而库里没有那一行 ⇒ 门走 COALESCE 的回落支（分母 = 0）⇒ **一行也没有也会报
`no_budget`**。那种形状下「把那一行改大」是无从谈起的，而 ⑨ 量到：拿预算页那条语句
新增一行就能开门。所以句子把「改大」和「新增一行」**并列**，两种形状都指到落点。
（`positiveInt` 的名与实是否要修是另一格：0 是「一分都不许花」而不是「没填」，
语义上说得通，本篇不动它，只把界面上那句话写成两种形状都为真。）

## 7. 别当成「做到哪了」

- **门的语义不是本篇拍的**。r25（CEO 拍板「预算列 = 生效值」，round360）在先，
  本篇只是把屏幕追上门。设计文档 §1.1 那条与 `budgetColumnGovernsCheck` 一字未动。
- **新句子仍然没有金额**。响应里没有「那一格实际生效的那个数」这个字段
  （只有命令行那份回落 `driver.task_limit_cents`，它在这一支不参与判据）。
  要看真实生效值，去预算页那一行 —— 那里本来就有。**没有为这一句话新加契约字段**：
  一个字段唯一的读者是卡片上一行字，不值得改响应口径（0049 §12.3 那半件仍在原处）。
- **「追加预算」的真按钮仍没建**，那是 CEO 那一格剩下的部分（B8 已收窄成这一条）。
  今天的路径是预算页手填 `scope_type=task` / `scope_id=<id>` / `period=per_task`，
  能开门但没有引导；新句子指的是那一格，不是某个按钮。
- **`at_limit` 那一档一字未动**：`driverMaxAttempts` 仍然没有命令行入口，
  所以「屏幕上和命令行都没有能放开的地方」在那一档仍然是真的。
- **`positiveInt` 接 0** 这件事本篇没改，只在界面措辞上兼容了它。
- **⑧ 那一档只在命令行显式给 0 时出现**，本篇没判「0 该不该被接受」；
  如果将来给它加了拒绝，⑧ 与句子里「（还没有那一行就新增一行）」那一半要一起重估。
- 探针与变异机在 `.workbuddy/scratch/`，不入库（既有纪律）。
