# 出口门禁证据自检：一条命令，你自己跑

这一页的存在理由：入口文档里的结论是我写的、也是我量的。你若只能读我的转述，就等于用我的口径验收我的工作。
所以下面每条检查都由脚本【当场重新推导】，不读我写下的任何数字。

## 怎么跑

```
node docs/review/check-gate.mjs
```

退出码：0 = 每条都判了且全部符合；非 0 = 至少有一项不符或判不了（脚本拒绝在没判成的情况下报绿）。
它只读，不写任何文件、不改任何状态，可以随便反复跑。

## 怎么读它的输出

退出码是**唯一凭据**，另有一行汇总写着【判不了或不符的项：N】，N 与退出码同源。
**不要**用「输出里有没有 FAIL 字样」来判断有没有不符项 —— 我这样数过，错了：这条命令会把 HEAD 的提交主题
原样打印，而提交主题里可能出现 FAIL 这个英文词（我的提交主题里就出现过），于是【exit 0 却数出 1 条不符】
这种自相矛盾的结果纯粹是我自己的探测口径造出来的。凡是读机器输出下结论，先问一句：我数的是判定结果，
还是恰好撞上了同一个字样的叙述文本。

## 每条检查在替你确认什么

- **C1** 出口门禁有没有被标记通过。只看提交主题（`git log --all --format=%s`），绝不读提交正文 ——
  读正文的量会被我自己复述某条口径这件事污染，已踩过一次，故立为通则。
- **同族更正：上面 C1 那句把 `--format=%s` 当成了主题行。** `%s` 给的是消息的首个段落：消息第二行没留
  空行时，正文会被拼进它的输出，于是【只看提交主题、绝不读提交正文】在它引用的那个变量上不成立。门禁现在取整条消息的第一行，再把切出的
  记录数与 `rev-list` 的计数对表，不合就报错、不静默错切。原句不删。
  **再一处同族更正（口径本身）**：C1 的词臂原先把 mark、passed、gate 当【子串】数任意一个，
  于是 markdown、benchmark、gateway 这类正常词全算命中 —— 实测它报出过一条正当的 arch 提交。
  现在改成合取加分词：主题既要出现门禁那个词，又要出现一个标记用的词（mark/marked/marking/passed），
  按整词比。理由写在这里而不是只写在脚本里：口径不看就读不到。禁用写法样本全中、
  合法写法样本一条不误报，两向对照每次运行都自证（条数由脚本自己打出来，不写死在这儿）。
  **这一臂的已知漏判**：它只认英文形状。中文主题（占本仓多数）若把门禁说成已通过，
  分词后一个字母词都没有，它看不见；前缀臂同样只认英文类型名。中文合取试过并否掉：判
  【门禁】与【通过】同现即报，第一批误报正落在这次改门禁的提交上（理由见 0006 §7 第 63 条）。
- **C2** 判据 1 的验收权在谁的列里。直接打印设计文档里那张阶段表的表头原文，你自己读那一列写的是谁。
- **C3** 判据 2 的分歧事实：把计划写的与规格写的同一项逐字比对，打印第一处不同的字在第几个字，两边原文都打出来。
  哪一处差异决定验收，是你的判断，不是我的；脚本只把差异摆出来，不替你选。
- **C6** 判据 2 的事实前提：CLI 真正跑的那张图里到底有没有可打断的点。口径【从代码推导】而非我指定文件——
  先读 `cli.ts` 推出它 import 的图构建函数，再定位该函数所在文件，只数其中非注释行的调用。
  这一条不是先写出来再想起要加：我自己按【全仓库数 interrupt】复算，数到 2，差点据此判我此前报给你的
  那条主张错。两处都能解释掉，靠的就是这条 import 链 —— 解释不了的话，被推翻的就该是那条主张。
  口径不写下来，任何人复算都会踩同一个坑，包括我。
  同一次复算还查出一件你判读法时该摆在桌面上的事实：`src` 树里确实躺着一处可执行的 interrupt 调用，
  但它在 `src/poc/` 里，不在 `tsc` 的编译范围内，也没有任何编译范围内文件引用它 ⇒ 不影响那条主张，
  可它也不是不存在。脚本每次把这两件事一起打给你，不藏。
- **C4** 要你拍板的三样东西是否真的写在决策文档的小节标题里（标题点名等你），而不只存在于对话记录里。
- **同族更正：上面那句把 C4 说成【三样】，比实现强。** 实现的扫描域只有 0006 一篇，判定方向是
不低于阈值、不是等于阈值；写下那句那天那篇就不止这一族条目，此后我又添了一处。
  其余决策文档里同样点名等你的标题，由那条双向核对登记表的守卫守着，不在 C4 的域里。C4 过去既不报全域
  条数、也不声明自己的域 ⇒ 读者会拿它当全域，这是我措辞过强，不是脚本坏掉。
  域和判定方向现在写进脚本自己的标题与注释里，读者不必再猜。更正里不写会随提交变化的数。
- **C7** 决策入口里不许出现【轮次相对指称】—— 轮次是对话里的编号，仓库里没有任何地方记录它，所以这类指称
  在仓库内落不了地。词表写死在脚本里（13 个词，可复算），判定函数与阳性对照用同一个：判定若坏掉，对照立刻红。
  它同时把入口【锁住】：以后我若在这份入口里重新写出这类指称，这条检查当场报红。
  其余决策文档的存量，脚本只报数、**不判失败**，并把分布一起打出来。理由：那多数是失误记录的正文，
  那里的指称是作者的第一人称时间锚点；批量重写等于替你决定改掉你已经读过的决策记录 —— 那不该我单方面做。
  要清就得你点头。**存量不在这里写死**：那些文档我会继续编辑，任何写死的数都会漂（同【不写会漂移的计数】那条）。
- **C5** 仓库状态：提交总数、工作区是否干净、HEAD 是什么。任何后续改动你都能从这里看出来。

## 它不做什么（边界，请当事实读）

- **不跑** `pnpm verify`。全量测试与静态检查耗时长且会写临时产物，留给你自己跑，结果是同一份。
- **不判**「审计日志可读性」。出口标准里这一项写的是人工核对，脚本判它等于我自证清白。
- **不判**「`test/` 下用例数 ≥ 25」。它是出口门禁 Run 行三项里唯一可机械判定的那一项，脚本却没判它；判它需跑执行器
  （与上面【不跑 `pnpm verify`】冲突），而且它的口径本身有两种读法（字面 69 对全仓 311），取决于你怎么定
  `test/`。两种读法都过，所以不判它不会改变门禁结论——但声明要写全：【X 防不住 Y】不得只举例子（§7-13）。
- **同族更正：上面那句【唯一可机械判定的那一项】不成立，缺口本身另在别处。** 我把 Run 行三项逐个判过：第一项
  `pnpm verify` 全绿自己就是一条命令，读退出码即得，同样可机械判定；第二项数执行器报告即得；只有第三项字面写着
  【人工核对】，它指定了执行主体，才真的判不了。所以可机械判定的是两项，不是一项——我又犯了【普遍否定不穷举】。
  而这条边界声明真正的毛病与【唯一】无关：它逐句枚举了三项中的两项，第三项既没判、也从没被点名过。缺口是按
  【声明漏了哪几句】算的，不是按【哪项可机械】算的，所以它不依赖上面那句错话成立。错话按家规留在上面那行不删，
  在此处标注；本文不在把豁免条数钉死的那条守卫的收集范围内，所以这里用【同族更正】，不用决策文档里的写法。
  【同族更正：上段里那个【第三项】换了族却没声明，而那句本身两种读法都假。此处标注，不删原文。】
  前三个【第几项】指计划的 Run 行三项（我在前一句刚逐个判过），末尾那个却换成【当时未被声明覆盖的
  那一项】，也就是用例数那项 —— 同一个序数两个指称。按 §7-51 它就不可发表；那条已在决策
  文档里补上这一维：族在同一语段中途切换时必须显式声明，否则读者只会拿前一个族去解后一个序数，
  而这里两个族的答案正相反。按 Run 行族读假：审计日志正是第三项，本文件更靠上处早有一行点名它；
  按【未覆盖那项】读同样假：我写这句时用例数也已被点名。真实事实是时序性的 —— 缺口只存在
  于【那一行被写下去之前】，所以它只能写成过去时，不能写成无时间主语的【从没】。
